## 浏览器实际操作

| 流程 | 观察到的结果 |
| --- | --- |
| 搜索任务、阅读、会话 | 原先漏检的“核对本周消费账单”“一周如何留出恢复时间”“线束固定点”出现在正确类型，任务与阅读进入对应详情。 |
| 搜索返回与刷新 | 从任务详情返回后，原关键词和结果保留；刷新仍能恢复查询。 |
| 多资料范围 | 全不选后浏览器返回 / 前进保持勾选状态；选择 Telegram 与 Agents，应用后仅显示对应两组，刷新后保留。 |
| 阅读转任务 | 新建带原文关联的高优先级任务；回原文重复转任务打开同一任务 ID，不重复创建。 |
| 完成与撤销 | 完成后待办列表移除该项，并提供撤销；撤销恢复待办。 |
| 阅读独立草稿 | 先保留速记草稿，再保存阅读想法；新笔记有返回原文的入口，原速记文字仍保留。附件保留由隔离检查覆盖。 |
| 会话管理 | 重命名后标题更新；归档回到列表，当前数量减少 / 已归档数量增加；归档内容仍可读，恢复后可继续操作。 |
| 材料搜索与多选 | 选本地阅读笔记后搜索另一篇阅读，之前勾选保留；确认后只附上两份材料，未自动发送。 |
| 演示回答 | 输入后显示接收与流式演示，完成后可复制；转任务表单保留回答文本和原会话来源。 |
| 任务带入 Agents | 新建实际日期任务后，进入一个带该任务材料的对话草稿，没有自动发起请求。 |
| 连接向导 | 模拟失败时不保存 / 不显示真实连通；切换成功情景后需确认演示配对；全流程没有真实凭据输入。 |
| 连接总览 | OSS 内容同步和 VPS 会话分别显示，电脑离线仅影响内容最终写入的说明明确。 |

本轮发现并修复了归档确认的 `close()` / `go()` 历史竞态，以及归档状态变化后旧输入区未更新的问题。另修复不同类型同 ID 的来源、复制、最近浏览与收藏隔离，及来源转任务的重复标题前缀。

## 布局与边界

- 使用同源 iframe 容器检查 320、360、390、430 CSS 像素宽度；搜索列表与五项底栏未见横向溢出，`scrollWidth` 与 `clientWidth` 一致。桌面浏览器滚动条会占用部分容器宽度。
- 390×430 短容器内可填写任务标题、实际日期并提交；任务转 Agents 后，材料、草稿与发送控件可达。这里只模拟短视口，不等于真实手机键盘测试。
- 纯白与纯黑主题已目视检查，任务列表、底栏、表单和聊天输入区保持可读。暖纸主题沿用语义变量，未重复宣称本轮做过独立视觉验收。
- 未发现本站脚本运行错误；浏览器扩展产生的元数据通信日志单独排除，没有当作站点错误或隐瞒真实站点错误。
- 临时视口验收页已移除，不包含在发布产物中。历史截图仍保留其原日期，不作为本轮新页面截图。

## 后续修正：搜索入口与筛选草稿

针对“全部内容每次打开完整范围确认”的反馈：内容类型改为直接切换，完整面板只由搜索框右侧筛选进入；关键词建议分区；资料范围默认折叠，标题与应用按钮固定。

- 新增 `node checks/search-interactions-checks.cjs`，覆盖 8 组契约：唯一入口和快捷切换、资料聚合与精确类型、独立条件清除、存储失败回滚、面板草稿 / 重置 / 取消、提交应用与重试、旧来源范围等效与空范围、旧 session / 新访问恢复。既有四组检查同时通过。
- 浏览器输入“核对”，切至任务仅显示任务，再连续点击“全部”恢复跨类型结果；关键词保留，没有打开弹层。
- 修改类型、日期、Craft 分组后关闭，已应用结果不变；浏览器前进可恢复草稿及 Craft 父级部分选中状态。提交后出现范围 / 日期条件，刷新仍保留。
- 单独取消“11 月”只清除日期；点击“全部”只取消任务类型限制，保留关键词和 Craft 分组。
- 已应用日期后，在面板点击“重置”再关闭，原日期仍保留；只有“重置 → 应用筛选”才清除已应用条件。
- 320 / 360 / 390 / 430 CSS 像素 iframe 检查均没有页面横向溢出；桌面滚动条分别占用 15px。内容类型条独立横向滚动，不让页面横向滚动。
- 390×430 短视口中，展开范围并滚到最后一个资料库时，标题和应用按钮仍可见；中段发生滚动，dialog 自身没有滚动。应用按钮位于视口内（top 371px、bottom 419px），高度 48px。
- 纯白 / 纯黑筛选面板已目视检查；初始折叠态按内容收缩，展开资料范围时再增高，避免默认大块留白。
- 抽查本轮预览页最近 100 条 warning / error，未发现本站脚本错误。临时布局页不纳入发布源码。
