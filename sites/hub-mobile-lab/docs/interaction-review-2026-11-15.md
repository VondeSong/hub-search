# Hub 移动端原型交互优化方案

方案日期：2026-11-15。依据用户已确认的 24 页《Hub 移动端交互审查》PPT，整理本轮实施规格与验收目标。

**文档性质：已确认方向的实施计划。文中的目标、清单和建议不表示已经实现、发布或通过验收。** 实际修改、浏览器与自动检查见 [实施与验收记录](interaction-qa-2026-11-15.md)，发布与源码同步回执见 [Issue #55](https://github.com/VondeSong/hub-search/issues/55)。

## 1. 目标、基线与范围

本轮首先解决用户指出的首屏问题：搜索、浏览等页面连续出现品牌栏、同名大标题和用途说明，真正内容开始得过晚。改版将当前页名放入现有顶栏，统一页面层级，并按搜索状态调整信息顺序。保留搜索、浏览、Agents、任务、复习五个底部主入口。

工作对象是现有 [Hub 手机端原型](https://hub-mobile-lab-von11.song02211368537057.chatgpt.site/#search)，沿用原网址及 Site 项目身份。开始本轮时，Site 与 GitHub 镜像核对为 v11、来源提交 `412919de19ce8313df109258f2981573506f4186`。这是修改基线，不是本次交付版本。

本轮范围包括共用顶栏、搜索起始与激活状态、筛选入口、浏览目录，以及 Agents、任务、复习中与这套规则直接相关的界面调整。现有示例、本机记录、草稿、附件、查询范围、会话和复习状态均需保留。v11 已有的小组件预览及其入口继续有效。

本轮不因原型更新自动修改 `desktop/`、Android 安装包或 `services/hub-agents/`，不把网页演示写成真实 VPS、模型调用、来源同步或小米真机验证。相关业务原有进度继续按其具体 Issue 记录。

## 2. 用户已确认的四项设计选择

| 选择 | 本轮采用的规则 | 必须保留的能力 |
| --- | --- | --- |
| ① 合并重复标题 | 将截图中 ① 的“搜索／浏览”页名并入 ② 顶栏，替换反复出现的 Hub 品牌文字。 | 小型空间入口、当前页位置、必要的示例／本机状态仍可辨认。真实文档标题不因此删除。 |
| ② 搜索起始页重排 | 未激活时优先最近打开，聚焦未输入时优先近期搜索。洞察从浏览进入。 | 全局搜索仍可检索洞察等既有类型，已连接或本机资料的范围不扩大。 |
| ③ 筛选合并为一行 | 资料范围与内容类型分开点选，收起永久占位的七枚大按钮及重复说明。 | 类型选择仍能直接生效，范围面板保留草稿、取消、重置和应用。接受类型菜单通常多一次点击。 |
| ④ 主题收起，创建随页面 | 外观进入空间／设置菜单。任务页使用“新任务”，Agents 列表使用“新对话”。 | 各主页面空间菜单保留“速记”；搜索与浏览保留速记快捷入口。速记草稿与保存流程不丢失。 |

这四项是本轮明确采用的方向。是否增加高频类型快捷行、可定制目录密度等属于后续观察项，不作为本轮默认扩展。

## 3. 证据、现状与空间预算

### 3.1 上轮实测的适用范围

上轮通过线上原型操作和 DOM 测量得到以下数值：浏览器视口为 1363 × 936、DPR 为 1，页面内容容器宽 478 CSS px。它们描述该次网页状态，不能直接当作小米手机实际屏占比。

| 对象 | 上轮测量值 | 对应问题 |
| --- | --- | --- |
| 品牌顶栏 | 高 66 CSS px | 页名仍在下一层重复出现。 |
| 搜索输入框 | 顶部约 166.6 CSS px，高 54 CSS px | 输入入口出现偏晚。 |
| 搜索未输入时首条推荐内容 | 顶部约 467.2 CSS px | 标题、说明、类型、范围及推荐词连续占位。 |
| 浏览首个内容入口 | 顶部约 209.2 CSS px | 品牌、页名、说明、分组标题连续出现。 |
| Agents 首条会话 | 顶部约 501.4 CSS px | 受当时连接说明、搜索和列表分组影响，不代表所有会话状态。 |

已存在的交互包括即时检索、无结果提示、打开结果后返回保留关键词、范围草稿及应用、会话材料／成果和可折叠运行过程、专注复习隐藏底栏。本轮应复用并统一这些能力，不将它们描述为全部缺失。

### 3.2 设计目标

以 390 × 844 CSS px 视口为主要验收样本，搜索初始态第一条实际内容的顶部，距应用内容区顶部目标为 **不超过 220 CSS px**。系统状态栏、浏览器地址栏及安全区分别记录，不混入同一收益数字。

预算参考为：56 顶栏 + 8 间距 + 48 搜索框 + 8 间距 + 44 筛选行 + 20 间距 + 24 分组标题 + 8 间距，合计约 216 CSS px，留少量弹性设为 220。44 高筛选行不意味着所有点击区都必须缩到 44，Android 方向优先保证 48 的触控区域。

仅合并标题，按旧布局推算可前移约 100 CSS px；完整重排的 220 是目标，不能在实测前写成已实现的约 247 px 收益。所有前后对比必须采用同一视口、字体、数据状态和测量起点。

## 4. 根页面、详情与专注状态的标题规则

| 页面类型 | 顶栏组成 | 正文与导航规则 |
| --- | --- | --- |
| 搜索、浏览、Agents 列表、任务、复习入口 | 空间图标、当前页名、当前页面主操作 | 移除正文重复同名大标题及每次出现的用途介绍。保留五项底栏及各自上下文。 |
| 资料库、目录、标签等二级页面 | 返回、当前目录名、必要的更多操作 | 不再重复泛化的“资料库”等标题。来源名、同步或示例状态可以保留。 |
| 笔记、阅读、任务详情 | 返回、简短上下文、更多操作 | 真实内容标题仍在正文保留，可多行换行。不能因为压缩导航而截掉题目或任务名。 |
| Agents 对话 | 返回、会话标题、更多操作 | 长会话名有查看完整名称的方式。对话内容优先，模型／连接详情按需展开。 |
| 专注复习、编辑 | 退出或完成、当前进度／状态 | 隐藏无关主导航，保留退出和主动作。退出恢复来源页面与本轮状态。 |

常态顶栏高度建议为 52–56 CSS px，页名字号约 20–22 px，系统安全区另计。大字体模式可以增高，不以固定高度裁切文字。图标视觉尺寸与触控区域分开设置，小图标也需要足够大的按钮范围。

空间图标打开包含当前空间、速记、外观与设置的入口。主题按钮不再占据每个根页面顶栏，但外观切换仍可发现并可用。用户应能判断入口是空间／菜单，不能仅用没有名称和可访问标签的装饰 Logo。

## 5. 搜索状态规格

| 状态 | 页面主要内容 | 动作与状态保留 |
| --- | --- | --- |
| 未激活、没有查询词 | 紧凑顶栏、搜索框、一行范围／类型、少量最近打开 | 进入搜索 Tab 不自动弹出键盘。点击输入框才激活。 |
| 已激活、尚未输入 | 输入框、取消、近期搜索；无历史时给简短可操作提示 | 选择历史查询即填入并检索。取消退出激活态，保留原页面上下文。 |
| 正在输入 | 查询词、清空、当前范围和结果；真实异步来源接入时可有加载状态 | 收起介绍、推荐内容和洞察卡片。输入状态不自动清除范围。 |
| 有结果 | 分组或列表、标题、命中片段、内容类型、来源及真实可用时间 | 打开精确对象；返回保留词、已应用条件、原列表位置和必要的激活状态。 |
| 当前范围无结果 | 说明当前限制，提供明确的放宽方法 | 可清除某个条件、改类型或显式扩大范围，不默认清空所有条件。 |
| 零资料范围 | 明确显示未选择资料范围 | 允许打开范围面板重新选择，不默认为全部。 |
| 来源不可用或部分加载失败 | 区分未查到的来源、已有可用结果与故障原因 | 重试或查看连接；不能把未查询来源等同于“没有资料”。 |

### 5.1 清空、取消和返回分别处理

- **清空输入**只清查询词，保留内容类型、资料范围、日期和排序。
- **恢复全部类型**只解除类型限制，不修改其他条件。
- **取消搜索激活**收起输入状态并恢复进入前的上下文，不附带清空历史或资料范围。
- **清除历史**是独立的显式动作，不能与清空输入混用。
- 从结果进入详情后返回，应恢复原查询及列表位置，而非回到空白起始页。

原型已有即时本地检索时，不为展示过程凭空增加等待或虚构服务加载。真实来源不可用、分源加载等状态是后续真实接入的验收要求，网页中的状态预演须明确标为演示。

### 5.2 最近打开必须来自实际访问行为

现有原型已有 `st.history` 访问记录，初始为空，实际打开资料、本机笔记或阅读详情后记录。优先复用这份行为数据，而不是把固定推荐列表换一个“最近打开”的标题。

实施建议与目标：

1. 使用类型化身份区分资料、本机记录、阅读和其他对象，避免相同 ID 指向错误内容。当前未覆盖的对象类型不伪造访问历史。
2. 按真实最近访问排序，重复访问更新位置并去重。首屏先展示少量条目，例如前三条，其余进入“最近浏览”。
3. 原型中的示例内容只有在用户实际打开过之后才可进入最近打开，并继续显示其示例／来源身份。这是本浏览器访问历史，不是从真实客户端同步的个人历史。
4. 移除不存在、已删除或无法解析的记录；单条失效不应使整页空白。当前来源范围不允许显示的对象不能借最近列表绕开限制。
5. **没有历史时**显示“还没有最近打开的内容”等简短状态，给出浏览资料或开始搜索的入口。若保留示例词，只能标注“试试搜索”或“示例”，不能伪装成用户历史。
6. 历史写入失败时，浏览和查询本身仍能继续。需要区分当次内存状态和已持久保存状态，不显示虚假的跨刷新保存成功。

### 5.3 近期搜索的保存时机

近期搜索建议独立于访问历史保存，按明确的查询动作记录，例如提交搜索、采用历史词或从搜索结果打开对象。不要将每次输入的半个词都写入历史。

- 对词条去首尾空白、去重并限制数量，首屏只展示少量条目。
- 取消、空词、纯空格及输入法尚未提交的组合文本不形成有效历史。
- 中文短词可以是有效查询，不套用强制两个字符的限制。
- 至少提供清除近期搜索的显式入口，删除历史不删除资料。
- 无历史时优先简短提示，不用固定测试词冒充个人常用词。

## 6. 内容类型、资料范围与筛选规则

搜索框下方一行呈现两个独立可点开的入口，例如“全部资料库”和“全部类型”。非默认日期、排序等条件用简洁摘要及独立清除入口表达，避免再堆一整段范围说明。

| 维度 | 入口及提交方式 | 状态约束 |
| --- | --- | --- |
| 内容类型 | 单选菜单，选中即生效并关闭 | 保留全部、资料、任务、阅读、对话、洞察、闪卡。资料内原有精确子类型仍可识别和修改。 |
| 资料范围 | 多选范围面板，应用后生效 | 使用已有资料库、空间／分组树。关闭取消草稿，不悄悄修改已应用范围。 |
| 日期 | 筛选面板 | 保留已有各类型日期语义。无日期内容不编造时间。 |
| 排序 | 筛选面板 | 相关优先／最近优先与结果实际排序一致。 |
| 来源状态 | 范围摘要或连接页面 | 区分示例、本机、可查询、不可用。选中一个来源不等于已经同步完毕。 |

保留现有范围面板的草稿、重置、取消、应用及持久化失败回滚。重置在面板中仍是未应用草稿；应用后页面与面板必须读取同一套已生效状态。

“全部类型”和“全部资料库”不可混为一个含义。零范围必须保持零范围，切换内容类型不得悄悄扩大资料范围。旧版本来源、标签和精确类型条件需要兼容，不能因菜单改版丢失原筛选。

资料范围仅限制本机搜索，不等于授权 Agents 获取或上传整库。带资料提问继续沿用逐条明确选择、预览与确认流程。

类型菜单通常比直接点七枚按钮多一次操作，这是本次确认接受的取舍。若后续发现高频类型切换成本过高，可在结果态增加有限快捷项，不立即恢复多行常驻按钮。

## 7. 浏览页面的信息顺序

| 区域 | 内容 | 展示规则 |
| --- | --- | --- |
| 常用内容 | 日志、阅读、收藏、最近浏览、标签 | 紧凑目录行，以名称为主，右侧可以显示真实计数或近期状态。 |
| 资料来源 | Craft、Obsidian、本机记录及其他现有来源 | 先空间，再文件夹／分组。内容类型与来源分开表达。 |
| 发现与回看 | 洞察及相关回看入口 | 保留依据、示例身份与既有处理能力，不另建重复的任务平台。 |
| 管理 | 连接、同步、外观和账户 | 进入空间／设置或次级列表，不在首屏上半部永久铺满说明。 |

目录行建议约 52–60 CSS px，按实际内容增高。内容型条目有摘要时自然换行，不将所有条目强制压成同一高度。

“浏览”“你的内容”和重复用途说明不再连续占位。需要保留的状态包括来源未连接、本机内容、示例资料、下载情况等；减少介绍文案不能删除这些影响判断的信息。

任务管理仍在任务面板。资料库中的任务只承担来源浏览或跳转，不额外创造一套任务操作流程。

## 8. Agents 列表与对话

本节是对 Hub 的迁移建议，不是把 Codex 或 Claude 的能力自动认定为 Hub 已实现。

| 区域 | 本轮界面目标 | 保留规则 |
| --- | --- | --- |
| 会话列表 | 一套紧凑页名栏与“新对话”；搜索、归档范围和会话内容尽早出现 | 合并重复新建入口。活动状态、会话摘要与时间真实可解释。 |
| 连接状态 | 常态压缩为一行，点击看详情；故障时给明确处理入口 | 手机离线、服务不可达、执行端登录失效、额度不足与设备撤销不混为一个错误。 |
| 会话顶栏 | 返回、标题、更多；环境细节按需展开 | 保留重命名、归档和恢复，不删除历史消息、材料和运行记录。 |
| 输入区 | 附件、模型说明、发送／停止与输入就近呈现 | 草稿、附件预览、失败重试和原请求身份不丢失。 |
| 运行过程 | 一行阶段摘要，按需展开已知工具活动和来源 | 只呈现可核对活动，不承诺暴露模型内部思维链。完成后仍可回看。 |
| 材料与成果 | 入口随实际内容出现，避免空标签长期占据空间 | 已选材料、已保存成果及其回看入口不能因“精简”消失。必要动作仍可发现。 |

上传、发送、生成是不同阶段。真实接入时应分别表达待上传、上传中、上传失败、待发送、已接收、生成中、停止待确认和已完成。断线不代表取消，网络恢复后应查询原请求而非自动创建重复轮次。

本原型没有真实 VPS／模型通信。沿用现有本机附件和状态演示，不把图片预览写成服务器上传完成，不把固定示例回答写成真实图片识别，也不在本轮臆造视频语音或模型额度能力。

Agents 业务跟进 [#32](https://github.com/VondeSong/hub-search/issues/32)，本轮只同步其界面相关变化与原型基线，不改变整个 #32 的真实部署／设备验收结论。

## 9. 任务、速记与复习

### 9.1 任务

- 根页主要动作为“新任务”，避免顶栏无标签加号打开速记，而正文另一处又是新任务。
- 今天进度和状态筛选形成紧凑工具区，日期、来源与排序使用一致的面板。
- 任务名称是正文内容标题，在详情页保留完整可换行文字。
- 示例来源任务、本机任务、来源快照和本地提案状态继续可辨。界面紧凑不代表已回写 Craft 或滴答。
- 本轮不重定义桌面任务管理的数据规则与 AI 行动流程。

### 9.2 速记

- 各主页面的空间菜单有稳定“速记”入口，搜索和浏览保留快捷入口。
- 速记继续使用现有正文、附件、补记日期、格式、保存和失败恢复流程。
- 切换主页面或改用当前页主操作，不清除未保存速记草稿。
- 阅读／资料中的“记下想法”继续使用独立草稿和原文关联，不覆盖全局速记。

### 9.3 复习

- 今日、牌库、收件箱等现有入口保持，根页使用统一紧凑顶栏。
- “开始复习”仍是明显主操作，不为了减少按钮而隐藏到菜单深处。
- 专注复习保持少量导航，显示本轮进度、退出及评分所需信息。
- 退出回到来源卡组／页面并恢复状态，不重置复习队列，不执行额外评分。
- 真正闪卡内容、间隔与评分逻辑仍跟随 [#46](https://github.com/VondeSong/hub-search/issues/46) 及其既有业务范围。

## 10. 底栏、浮层、键盘与返回

### 10.1 底部主导航

五个主入口保持稳定，不因内容为空就隐藏某个入口。每个 Tab 保留自己的查询、筛选、滚动位置及必要草稿。列表底部留出实际导航高度与安全区，最后一项可以完整看见并点击。

普通根页面持续显示底栏。搜索激活、编辑和专注复习可以作为临时专注状态，避免键盘上方同时堆叠主底栏、编辑工具栏与输入器。结束专注后恢复原主导航，不能随滚动无提示丢失导航。

### 10.2 浮层

筛选、空间菜单、速记和更多操作复用统一生命周期：可见标题、关闭入口、可滚动内容、适当的底部主要动作。焦点进入浮层，背景不同时滚动；关闭后焦点返回触发入口。

范围层优先在同一个面板内展开树结构，避免逐层叠加多个模态窗口。短屏和键盘状态下，关闭、取消、应用／保存均需可达。

### 10.3 键盘

使用实际可视视口判断输入及操作位置，不能仅以 `100vh`、`100dvh` 或 safe-area 样式存在就宣称键盘适配完成。Android Chrome 默认视口调整行为与布局视口不同，固定元素可能被键盘遮挡，见 [B1](#b1)。

验收目标是输入框、光标、清空／取消、发送／保存全部可见且可点击。输入法组合文本在提交前不触发错误历史保存、跳转或发送。中文键盘、英文键盘和浏览器缩放需分别记录实际覆盖情况。

### 10.4 返回层级

目标顺序是先处理当前临时输入／浮层，再返回上一级页面；例如关闭键盘、关闭当前筛选层、退出搜索激活态、返回原详情来源。具体由浏览器、系统和现有 history 状态共同处理，不额外创建重复 history 项，也不连续弹出多层。

Android 系统返回、浏览器返回、页面返回按钮和 Escape 应恢复合理上下文。Web 中可验证的行为与真实 Android WebView／PWA／iOS Safari 的系统行为分别记录，不能仅靠桌面键盘事件冒充全部通过。

## 11. 色彩、排版与触控尺寸

以下色值与尺寸是 Hub 设计目标，不是竞品像素采样值，也不是把 Apple pt、Android dp 与 Web CSS px 当作同一单位。

| 项目 | 浅色建议值／规则 | 验收重点 |
| --- | --- | --- |
| 页面背景 | `#F7F8FA` | 与正文表面有轻层次，不形成连续厚重灰卡。 |
| 正文表面 | `#FFFFFF` | 正文阅读稳定，避免每条列表叠模糊。 |
| 主要文字 | `#202632` | 关键文字清晰，不靠颜色单独传递状态。 |
| 次要文字 | `#5F6876` | 仍满足对应文字对比度，避免浅灰不可读。 |
| 主要强调 | `#3269CC` | 用于选中及主要操作，不为每个模块强加高饱和底色。 |
| 字号 | 正文约 16 px，次文 13–14 px，页名 20–22 px | 支持大字体、中文换行和长标题；可读优先于固定高度。 |
| 目录行 | 约 52–60 CSS px | 点击区域足够，内容多时允许增高。 |
| 触控目标 | Web 项目目标至少 44 × 44 CSS px，Android 方向优先 48 × 48 | 视觉图标可以更小，按钮触控范围不能随之缩小。 |
| 玻璃材质 | 顶栏、底栏、临时工具层少量使用 | 保证内容对比度，不遮住第一条或最后一条内容。 |

继续覆盖纯白、纯黑、暖纸和现有强调色偏好。深色主题需使用对应语义色，不能把浅色硬编码带入所有输入框、浮层、提示和选中态。减少透明度、减少动态、无 `backdrop-filter` 的环境要有实体表面后备。

WCAG 2.2 AA 的目标尺寸最低条款是 24 × 24 CSS px 或满足相应间距等例外；44–48 是本项目更宽裕的目标。普通文字对比度目标至少 4.5:1，大文字至少 3:1。焦点最低要求与本项目“输入和主要操作完整可见”的更高目标分别记录，不能混称规范的精确要求。

## 12. 验收目标

以下均为待实际验证的目标。完成记录需要提供所用版本、视口、数据状态、操作路径和观察结果。

### 12.1 首屏与视觉

- [ ] 搜索、浏览、Agents、任务、复习根页面只出现一套页名层级。
- [ ] 390 × 844 CSS px 下，搜索初始态首条实际内容顶部满足约定预算；无历史时验证明确空态，不注入假历史凑目标。
- [ ] 同一视口记录改版前后内容起点，区分实测、推算及目标。
- [ ] 360、390、430 CSS px 常见宽度，以及 320 CSS px 重排检查无整页横向滚动；二维资料等例外单独记录。
- [ ] 长标题、中文、大字体及纯白／纯黑／暖纸主题不裁切关键文字。
- [ ] 顶栏、底栏、浮层的材质不遮挡首尾内容，减少透明度后仍可读。
- [ ] 主要按钮点击范围符合项目目标，实际对比度按最终背景检查。

### 12.2 搜索与范围

- [ ] 不自动弹出键盘，主动聚焦后有明确取消，清空仅清词。
- [ ] 最近打开来自实际行为，首次使用与失效记录有正确后备。
- [ ] 近期搜索不记录每个中间输入字符，取消不产生伪历史。
- [ ] 全部／资料／任务／阅读／对话／洞察／闪卡均能按现有数据检索并打开精确对象。
- [ ] 类型、范围、日期、排序状态一致；切类型不扩大范围，零范围仍为零。
- [ ] 筛选取消不应用草稿，重置后关闭保留原条件，应用失败可恢复。
- [ ] 无结果可以逐项放宽，来源不可用不伪装成查询无结果。
- [ ] 打开详情再返回，词、范围与滚动保留。

### 12.3 现有闭环与输入

- [ ] 五个底部入口及二级返回可用，最后一行不被导航遮挡。
- [ ] 搜索／浏览可快速速记，任务和 Agents 的主要动作分别创建正确对象。
- [ ] 关闭速记再打开仍有原草稿，原附件／日期／保存失败处理保留。
- [ ] Agents 会话、重命名／归档／恢复、材料与成果入口未因减层丢失。
- [ ] 上传／发送／生成的演示状态可分辨，失败保留草稿且不触发重复请求。
- [ ] 专注复习退出保留本轮状态，不因跨 Tab 导航遮住其他页面或执行额外评分。
- [ ] 短视口、浮层和键盘共存时，关闭、取消、应用／发送完整可达。
- [ ] 浏览器返回与浮层 history 不叠出重复层，焦点恢复正确。
- [ ] v11 小组件预览及原有速记／复习跳转仍可用。

### 12.4 开发检查与证据边界

按修改范围运行已有检查：`checks/mobile-checks.cjs`、`checks/workspace-checks.cjs`、`checks/search-interactions-checks.cjs`、`checks/agents-enhancements-checks.cjs`、`checks/task-tools-checks.cjs`、`checks/widget-checks.cjs`。对改动 JS 进行 `node --check`，并检查差异与空白错误。没有必要对纯文案重复运行无关业务测试。
