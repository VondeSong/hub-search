# 四类资料库结构交互原型

在现有 Hub 原型中新增“库结构”入口，使用虚构示例资料验证原生层级、目录列表、预览、搜索与反向定位。入口为 `?view=libraries` 或左侧“库结构”图标、全部内容导航中的“浏览资料库”。

## Direction contract

THESIS：通过原库层级找到内容，搜索命中可以回到相同位置。

OWN-WORLD：继承原工作台的系统字体、灰白层级、既有主题变量及鼠尾草强调色；沿用窄图标栏和其他模块的视觉语言。

STORY：先选库，再展开目录、阅读文档，沿子页面或双链继续。四个库分别保留浏览位置。

FIRST VIEWPORT：原图标栏右侧依次呈现结构导航、内容列表和弹性正文预览。搜索与范围置顶。手机先显示列表，选中后阅读，导航为可关闭的抽屉。

FORM：已有工作台的局部扩展，沿用本次明确讨论的方案。seed: none (unavailable)。参考库已核实 main 空间并读取案例索引，本次未采用其他整页案例。

FINISH：unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## 演示与核验范围

Craft 展示文件夹、多层子页面、合集表格/画廊与空目录；Obsidian 展示目录、文件名、同名笔记路径、双链及附件信息。搜索支持全库或当前位置及下级、无结果反馈和反向定位。每库保存选中项和展开状态，运行期间保留切库前的滚动位置。

支持 Ctrl/Cmd K 搜索、目录树方向键/Home/End、Escape 清除搜索或返回列表。实际账号接入、编辑、同步和原文件写入不属于原型。

结构检查：`node scripts/library-browser-check.mjs`。TypeScript 检查与浏览器桌面、窄窗操作另外核验。

## 滴答与飞书扩展

滴答保留文件夹、清单、自定义分组、任务与独立子任务，提供分组列表和看板。任务完成与正文检查项分别保存为浏览器示例状态；笔记不显示完成操作。优先级与日期使用固定示例值。四类来源以两行切换器并列，沿用既有视觉系统。

飞书使用可承载正文的页面节点，区分云文档、电子表格、多维表格和快捷方式。快捷方式共享目标正文，但保留自己的导航身份和路径；提供原位置定位。正文无权限的节点只显示权限说明，表格用只读示例记录展示。

复用所有库的范围搜索、反向定位、独立浏览位置与窄窗返回。新增的任务状态、检查项与老版两库浏览位置可共同恢复。尚未接入真实账号或真实权限请求。

本轮验证：11 组结构及搜索检查、TypeScript 和生产构建通过；1280×720 桌面、390×844 手机验证任务/检查项恢复、分组列表/看板、快捷方式原位置、表格与权限状态、四库切换和已有两库浏览。独立审查结论为 ship，文档与既有视觉系统一致。


## 全部库与跨库组织扩展

当前入口由四应用按钮改为全部库/具体库选择器。全部库保留四个独立根，默认收起；精简树只呈现目录、清单分组及有下级的 Craft/飞书页面。目录快速搜索包含完整路径，可直接进入。收藏与固定的“线束项目”示例支持增删引用、浏览器本地保存，支持收藏目录；不改变原资料位置。跨库列表显示来源和路径，继续复用任务与表格预览。聚合入口清空自己的预览，不清空单库阅读位置。

实际检查：类型检查、11 组原结构回归通过；桌面实际验证专题打开飞书台账/滴答任务、添加收藏、目录搜索进入 Obsidian 知识管理；390px 手机检查导航抽屉、阅读返回列表。示例数据尚未接入真实账号；尚未进行大规模目录性能验证。


## 分栏浏览对照与任务展示调研（2026-11-08）

### 本轮原型

顶部增加“目录树 / 分栏浏览”切换，共用当前库、目录和阅读对象。分栏第一列为具体资料库，后续每列对应一个真实父节点；点击目录展开下一列，点击正文对象保留预览，具有子页面的正文同时展开下级。空目录显示空状态，叶子和快捷方式不虚构下级。宽屏可收起预览扩大浏览面积；手机横向滑动浏览，正文页使用“阅读当前页”进入并返回。搜索、收藏、专题继续以列表呈现，定位后继续分栏。

范围仍为示例数据浏览；没有实施任务界面重设计、思维导图或依赖关系写回。

### 有特色的产品模式与操作

| 产品 | 原生操作与信息模型 | 对 Hub 的启发 |
| --- | --- | --- |
| Obsidian | 标签组菜单 Stack notes，将已打开笔记叠放横向阅读；关联视图可联动局部图谱、反链与大纲 | 分栏用于目录路径；叠放阅读用于引用链，两者不要混为同一种导航 |
| Heptabase | 卡片是内容实体，白板摆放卡片与连线，卡片库、白板等入口共享数据 | 专题白板可组合资料和任务引用；图上位置是用户的组织方式，不是原库路径 |
| Tana | 节点菜单 View as 切换大纲、表格、卡片等；按字段筛选分组，同一数据保留不同视图 | 视图由目标和字段决定，切换展示不复制对象；按状态分组与按父子层级分栏是两件事 |
| ClickUp | Views Bar 添加 Mind Map；Tasks 模式映射现有任务/子任务，Blank 模式先建自由节点再转任务 | 思维导图适合任务拆解，但自由想法和真实任务应有明确身份；拖动任务分支可能改归属，不能当纯布局操作 |
| Linear | 时间线呈现项目与日期，并以依赖线表达 Blocking / Blocked by；依赖也在项目属性中显示 | 流程依赖图必须有明确阻塞关系，不能从任务父子关系、排列或关键词自动推断 |
| 滴答清单 | 官方视图说明包含列表、看板、时间线；看板按分组查看，时间线可拖动任务安排日期和时长 | 适合任务界面执行和排期；清单结构仍可作为来源定位保留 |

### 推荐的 Hub 分工（设计建议，未实施）

滴答继续作为已接入的数据来源，参与跨库搜索、收藏和专题；日常管理以“任务”界面为主。两个入口应引用同一条任务身份和状态，不各自维护一份任务。任务有来源与原文入口；滴答中的笔记不是待办，不显示完成框。资料库页保留清单/分组定位，但不强迫执行任务必须经过文件夹。

任务界面建议先有列表、看板、时间线，再按明确用途增加图形视图：
- 列表：今天、即将到期、未安排等执行入口。
- 看板：按真实阶段或状态分组；“资料准备/设计核对”等自定义清单分组不自动等同于完成状态。
- 时间线：按真实开始/截止时间排期；无日期任务进入“未安排”，不编造日期。
- 思维导图：项目目标 → 任务 → 子任务，适合拆解和范围检查；正文检查项不是独立子任务。
- 依赖图：任务 A 阻塞任务 B，用有向线明确表达；新增依赖需要真实来源字段或 Hub 明确保存的关系，验证循环和写回能力。
- 关联图/专题白板：任务 ↔ 规范/笔记/会议记录，适合回答为什么做、依据是什么；“引用”“相关”“阻塞”分别标识。优先单项目或当前任务邻域，避免全库毛线团。

第一步推荐任务界面“列表 / 看板 / 时间线”，第二步验证任务拆解图与局部资料关系图。只有项目确有前后置约束才引入依赖流程图。以上是 Hub 候选方案，不把其他软件功能或本轮静态文档调研当作滴答接口支持证据。本轮未核验滴答原生思维导图或任意依赖图能力。

## 层级浏览与双页对照（2026-11-22）

参考 Hub v3 资料库页调整现有工作台的「库结构」入口。目录树纳入文档、子页面、任务与附件，用连续缩进线表示层级。树内 ↑↓、Home、End 移动焦点并更新右侧预览，←→ 展开、折叠或进入上一级/下一级。卡片模式复用目录内容，分栏模式继续沿原库路径逐级浏览。

正文顶部显示资料来源和路径。通过路径末端选择器跳转到可读的上级页面、同级资料或下级页面与附件。打开「专注阅读」或按 Ctrl/⌘ + 句点可展开阅读区，再按一次或按 Esc 可退出。

点击「并排对照」选择另一篇资料，也可按住 Ctrl/⌘ 点击其他文档直接对照。两篇资料可来自不同库，分别滚动、跳转和替换。可互换位置，退出后回到原来正在浏览的资料。宽窗横向对照，窄窗上下排列。使用站内既有示例资料，原型对应 #25 的浏览交互。
