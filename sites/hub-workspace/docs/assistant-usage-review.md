# 任务与用量：源码核对与原型整理

2026-11-08，仅更新浏览器原型。本地 Hub 源码未修改。

## 源码含义

- `desktop/src/AgentInvestigation.tsx` 的“任务核对详情”组合目标修订、任务树、工作状态及目标评估，实际上用于看目标、步骤、进展与是否完成，不是用户需要选择的模式。
- `AgentProviderBudget.tsx` 支持本对话累计 Token 上限和首次设置的单轮预留，包含输入、非缓存输入及输出。已有预算只允许提高累计上限，已用和未知预留保留；保存不启动分析。首次设置适用范围有提供方限制。它不是金额设置，也不是账单绝不超出的保证。
- 同组件显示独立执行额度，Token 追加不会提高工具、原生会话或资料限制。默认自动安排属于 #28 待开发规划。
- `AgentNativeContext.tsx` 显示提供方最近报告的窗口占用，非实时精确占用，也非整段对话累计用量。
- `AgentContextCompaction.tsx` 支持条件满足时安排下次继续前整理、取消安排及查看状态；Codex 自动压缩仍由提供方负责。

## 原型调整

“查看用量与上限”直接进入“任务与用量”面板，省去阅读布局、共享记忆等无关内容。普通对话详情仍保留这些入口。

1. 任务进展：展示尚未开始／正在进行或暂停／已生成回答等现有状态，不伪造真实任务树。
2. 执行方式：默认显示自动安排，将规则与到达上限后的处理收进说明。
3. 本对话的模型用量：无数据明确显示未知，不以消息条数或零用量冒充实际消费。
4. 设置用量上限：直接展开输入、输出字段，标明 Token 单位、用途和保存范围；保存须确认，已有演示设置只允许追加。
5. 对话太长时怎么办：解释上下文与累计用量区别、自动压缩和可用时的手动整理。原型不提供不能执行的伪操作。

## 去掉、增加与优化建议

| 类别 | 内容 |
| --- | --- |
| 去掉 | 消息条数充当用量、重复的大段政策文字、模糊的“任务核对详情”、没有数据的空统计 |
| 增加 | 真实任务接入后的已完成／剩余步骤／卡住原因；实际已用、预留、剩余；到达上限后的明确追加与继续入口 |
| 优化 | 常用设置直接可见；技术细节放高级项；执行上限与 Token 上限分开；将来源数量与单轮资料量放在材料说明中 |
| 高级项 | 本地已有非缓存输入和单轮预留，应在完整接入时保留解释和校验，不能简化成只有输入／输出就声称完整对齐 |

真实用量、资料预算、任务树、上下文状态及手动整理尚未接入原型。当前仅保存浏览器演示选择，后端策略沿 #28 保持待处理。未控制电脑或进行截图验收。
