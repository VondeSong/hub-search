# 原 Hub 工作台：任务聚合与 AI 分析整合

本轮仅更新既有 `hub-workspace-von11` 的任务模块，入口 `?view=tasks`。不新增站点、工作台、全局导航项或第二个任务面板；此前任务流程实验室保留为历史原型，本轮不修改它。没有改动正式桌面代码或真实任务数据库。

## 主线

- 原列表、看板、表格、任务拆解和资料关联仍引用同一批 19 条初始示例任务；来源、项目、状态、日期与子任务身份沿用原数据模型。
- 任务行「分析」与详情「分析并推进」直接带入该任务；项目旁图标直接带入来源与清单。项目分析同时定位左侧对应列表，避免不同来源的同名项目混在一起。
- 顶部三个入口为「安排今天、梳理项目、推进任务」；安排今天使用当前筛选范围，界面明确显示范围、数量和读取对象。筛选后不会宣称分析了全部项目。
- 分析留在任务面板右侧。确认后依次展示读取聚合记录、刷新示例来源、分析、选择采纳。清楚区分只读、旧缓存和资料不完整；每次分析绑定当时的读取情境，不因事后切换下拉框就把旧结果变成新数据。
- 建议提供原任务与资料依据。今日计划只保存原任务 ID 和当日标记，左侧即时显示，可按今日计划筛选；建议笔记附在原任务；来源修改先预览说明差异。
- 模拟修改任务说明通过既有滴答共享浏览器状态或原 HubItem 更新，不复制任务，不改清单、日期和完成状态。Obsidian 任务只提供本地建议，不模拟来源写入；它仍可加入 Hub 今日计划。
- 原任务变化后拒绝采用旧建议。失败可重新预览同一操作或取消；未知先核对，示例确认未写入后结束旧操作再重新分析。存储失败不冒充本地计划保存成功。
- 分析任务和项目间切换会取消旧异步回调；关闭返回当前列表。计划、笔记、采纳记录刷新后保留，既有任务存档兼容新增说明字段。

## 数据边界

任务读取与刷新、AI 回复、来源保存均为固定示例/本机模拟；没有连接账户、真实模型、真实同步服务或本机 SQLite。本站保持原分享范围，页面上的示例不来自用户真实资料。计划记录使用 `hub-task-analysis-v1`，任务状态继续沿用 `hub-dida-task-demo-v1`，既有数据与其他模块存档保留。
