# 桌面助手界面与交互优化验收

关联事项：[#1 桌面端 AI 助手交互逻辑和 UI 优化](https://github.com/VondeSong/hub-search/issues/1)。

本轮从 `6ec520229cfc686eddbf58be47e71e3e48e4f98d` 开始，修改正式 React 组件和历史记录查询。界面使用 Hub 现有主题变量、系统字体、轻分隔线和紧凑工具栏；沿用真实资料授权和模型配置接口。

## 已实现的交互

| 区域 | 行为 |
| --- | --- |
| 顶部 | 左侧历史和新对话，中间任务模式，右侧详情和关闭。中央区域不受两侧内容宽度影响；长标题截断并保留完整提示。 |
| 任务模式 | 保留标准 / 扩展的执行额度语义，控制工具步骤、材料量和运行时限；运行中的额度门禁继续生效。 |
| 输入框 | 资料范围、权限、模型和发送位于同一工具栏。资料与技能可从“+”进入；320px 下所选文字入口收进同一菜单。 |
| 资料范围 | 读取 `list_libraries`，提交实际库 ID；支持筛选、明确全选、清除、重试、离线缓存和失效库提示。库名称跟随注册表更新，新库不会自动加入授权。单独添加的页面与整库授权分别保留。 |
| 模型 | 按当前模型目录给出的推理档位显示控件；只有具有 Fast 能力说明的 Codex 模型显示速度设置，DeepSeek 不显示速度。切换模型时重新校验并恢复该模型偏好；保存失败不记为成功。 |
| 历史 | 已固定、今天、过去 30 天、更早分组；单行标题、右侧时间、行内更多操作。搜索在数据库中先过滤全部标题再分页，支持归档、恢复及撤销。 |
| 历史数据 | 归档独立于固定、删除和运行状态，写入已有历史偏好记录。活动任务和未核对写入仍受宿主保护；授权、执行回执及累计预算不因归档改变。 |
| 键盘与弹层 | 搜索、行菜单、专题引用、专题和父详情按层处理 Escape，恢复相应触发器焦点。顶部弹层高度跟随实际助手高度；材料菜单保留完整滚动路径。 |

## 自动检查

最终执行结果记录在关联 PR 中。可复跑命令：

```sh
cd desktop
npm ci
npm run test:ci
npm run build
```

独立历史数据库检查在仓库根目录执行：

```sh
cargo test --manifest-path desktop/qa/assistant-history-native/Cargo.toml --locked
```

该检查直接编译正式 `store/history.rs`，覆盖全历史标题搜索、分页、游标与条件绑定、旧偏好兼容、归档持久化、恢复、独立删除 / 撤销以及写入失败，共 8 项。它不替代 Tauri 宿主的完整 Rust 集成测试；完整检查应在具备桌面依赖的环境中执行 `npm run check`。

整合回归使用正式组件，只模拟原生 I/O 边界。覆盖范围包括：实际提交的库 ID 与界面选择一致、保留单篇页面、旧搜索响应不覆盖新结果、新对话不混入归档筛选、详情关闭回焦、技能发送，以及真实嵌套弹层的两级 Escape。

### 原有回归问题的处理

最初的全量检查发现 7 项失败，在上述未修改基线上逐项复现。本轮保留其业务语义并完成修复：过程折叠后仍显示截断和网页未获取提示，联网记录保留“结果数不代表已读全文数”的解释，专题引用的 Escape 先由内部处理。旧标题断言匹配当前文案；图片输入法测试明确扣除初始化空查询，阅读导航测试仅额外允许本地模型设置的 `get/status` 读取。

原测试引用了仓库中不存在的运行记录文件，现使用明确标注的合成 `AgentConversationRevision.fixture.ts`。该文件只用于回归，不作为实际模型运行证据。

## 正式组件预览

在单独开发端口启动：

```sh
cd desktop
npm run dev -- --host 127.0.0.1 --port 4174 --strictPort
```

打开 `/qa/assistant-refinement.html?width=520`；页面提供 320px / 520px、浅色 / 深色切换，详情菜单可切换浮窗与侧栏。示例页面直接挂载正式助手组件。

预览使用合成资料库、对话和模型能力，只模拟原生接口。归档状态仅保存在页面内存，不会读取个人资料或调用模型。实际库连接、模型支持范围和重启持久化应在桌面端验收。云端阶段只完成静态打包；后续 Windows 本机浏览器已检查 320px 浅色侧栏、440px 深色低高度浮窗和 520px 浅色侧栏，核对资料库选择、历史搜索/归档/恢复、DeepSeek 能力菜单、分层 Escape 和关闭详情回焦。520px 长标题居中，所测布局未见横向溢出，低高度历史列表可滚动；这些是合成数据的浏览器证据，不能代替真实 Tauri、系统缩放和模型验收。示例笔记清单模拟响应不完整，仍不能据此宣称单篇笔记选择通过。

## Windows 原生检查与修复（2026-11-07）

首轮完整 Rust 库测试执行到底：2161 项通过、14 项失败、149 项按原配置忽略。失败按根因处理：

- 45 个 Rust 文件的格式问题统一按项目 `cargo fmt` 入口整理，保留功能行为。
- 8 项附件交付、资源索引和日志修订测试暴露同一个 Windows 长路径问题：Rust 文件操作可处理的暂存路径，在直接传给 `MoveFileExW` 后提交失败。文件提交入口现在规范化父目录为 Windows 扩展路径，保留最终文件名以及原有原子替换/落盘选项；新增超过 260 字符、含 `..` 的写入、流式导入和损坏缓存修复回归。依据：[Rust canonicalize](https://doc.rust-lang.org/stable/std/fs/fn.canonicalize.html)、[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)。
- 2 项技能契约测试改用自包含的“仅参考说明不同”前置契约，不依赖未随仓库保存的旧方法样本或过期发布哈希；保留对其他工具契约变更的拒绝断言，未扩大正式兼容范围，也不把合成样本称为旧发布实测。
- 2 项专题记录数断言纳入已有的 `conversationCreated` 记录，保留精确记录数和幂等检查。
- 1 项 MCP 能力汇总断言同步现有目录的 48 项工具、35 项只读工具和 11 项其他组工具，正式目录未改变。
- 1 项历史冻结二进制校验缺少本机冻结清单；仅将本机已有的三份清单接入忽略目录，仍核对原冻结二进制的精确版本、数据库版本和 SHA-256，没有修改其安全校验或新增跳过项。

进一步完整运行得到 2174 项通过、2 项失败、149 项原配置忽略；两项失败均为本地模拟 OSS 请求连接中断，单独复跑通过。当前测试环境设置了 HTTP/HTTPS 代理且未设置 NO_PROXY；注入不可用代理可稳定复现同一失败。`with_test_endpoint` 现在为限定 `127.0.0.1` 的模拟接口建立直连客户端，保留原超时和禁止重定向策略；正式客户端配置未变。相同不可用代理条件下，恢复和阅读媒体两项原失败用例均通过，代理变量仅作用于本次被测进程。依据：[reqwest ClientBuilder::no_proxy](https://docs.rs/reqwest/latest/reqwest/struct.ClientBuilder.html#method.no_proxy)。这次失败运行保留为诊断证据，不记为通过。

最终在 Windows 执行 `npm run test:rust`：**2176 项通过、0 失败、149 项按原配置忽略，0 项过滤**，执行耗时 1748.11 秒，完整收集 2325 项。此前 14 项失败及两项代理相关不稳定用例均在最终全量运行中通过；没有新增忽略项。`npm run format:check`、独立历史入口 Rust 格式检查及差异检查均通过。已核对 50 个本轮修改的 Rust 文件与最终测试构建的冻结记录一致。

前端源码、依赖和构建配置未变化，复用同一前端版本已经通过的 259 个文件/1884 项测试（4 个文件/11 项按原配置跳过）及 TypeScript/Vite 构建结果，没有把这些结果记作本轮重新执行。

独立 worktree 的原生检查需要本机已生成的 `memory-distribution/windows-x64` 资源，以及历史冻结校验使用的三份 `candidate-freeze.json` 和它们引用的原二进制；这些资源保留在忽略目录，不提交个人运行数据、依赖或二进制。
