# 工作区交互优化 · 第二阶段

## 本轮交付

1. 紧凑模式的任务专用侧栏：保存视图、项目与清单、当前资料库范围内的数量。按来源、资料库、真实项目/文档标识分组，避免同名清单混合。滴答接口增加只读 collectionId，保留原有任务文档定位，不迁移或改写数据库。
2. 标准/专注模式用清单选择器保留同等入口；筛选无结果时可清除清单条件或查看全部资料库。
3. 内容列表按条目身份保存选中项与滚动位置，覆盖全部内容、标签、日志、收藏和历史的对应上下文。请求结果与当前条件匹配后才恢复；条目已不存在则回到首项。会话历史最多保留 100 个上下文，不保存正文到磁盘。
4. 搜索条件标签常显：文件夹、时间、字段范围、排除的内容类型，可单项清除或重置。清除搜索条件不擅自改变资料库范围。摘要仅在搜索条件实际适用的全部内容/搜索结果页面显示。
5. 1000 CSS 像素及以下使用可关闭的非模态浮动侧栏；点击页面其他区域、Tab 离开或 Esc 均可退出。Esc 将焦点还给入口，改变窗口尺寸不改写用户保存的布局模式。
6. 修复从标准模式收起后再展开会错误变成紧凑模式；保留窄窗口的任务搜索、排序、统计和更多工具。

## 验证与限制

- 相关前端测试 20 项通过，包含异步返回、条目重排/删除、滚动位置、同名跨库项目、滴答清单 ID、筛选重置、窄窗口和焦点恢复。
- 全量前端检查 304 项通过、7 项既有失败。任务后台相关回归测试 1 项通过；生产构建通过。
- 浏览器使用示例数据检查常规窗口和 760 × 760 窗口：任务清单筛选、资料库交集空状态、浮动任务/牌组侧栏、Esc 返回、搜索工具可达性，以及内容切换后的预览恢复。
- 修复视觉验证发现的牌组浮动侧栏被搜索栏遮挡问题。
- 保留用户现有 LiquidWorkspace 样式；按 apple-ui-design 与 apple-web-motion 使用原有色彩与静态/即时反馈，不引入额外动画等待。
- 没有操作真实资料库同步或修改源内容；示例数据验证不等于真实服务端端到端回归。
- 第一阶段已记录的 7 项标签测试失败仍存在，分别为模型列表模拟返回缺失和旧 UI 元素选择器；本轮未改动这些业务组件。
- 闪卡正在作答的临时进度和未提交编辑内容仍不属于本次恢复范围。搜索浮窗与移动端未做整套视觉迁移。

## 使用

退出旧 Hub 后运行 Hub_0.16.141_x64_portable_WorkspacePhase2.exe。推荐“布局 → 紧凑”。小窗口点击顶部侧栏按钮展开项目或牌组；无需重新设置布局。
