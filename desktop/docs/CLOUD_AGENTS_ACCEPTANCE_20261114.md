## 模拟器与真实 Codex 的恢复测试

设备为独立的 API 35 模拟器 `Hub_QuickCloud_20261112`，未使用实体手机。

| 场景 | 操作与结果 |
| --- | --- |
| 生成中强制退出 | 正式 HTTPS 服务已接收一条 120 行测试请求，界面显示“正在回答”后强制停止 Android 应用。重开并选择原会话后显示完整 120 行；服务端仅有同一条请求，回答 1,977 字符，没有重发生成。 |
| 未送达消息重开 | 停止隔离服务后发送，界面显示“待确认·消息已保存在此设备”。强制停止并重开应用，待确认状态仍在。恢复服务并点击“用原编号重试”，得到 `HUB32-OUTBOX-20261114`，待确认状态清除；数据库只有一轮。 |
| 服务在输出中被杀死 | 独立服务运行官方 Codex，出现部分文字后对其整个服务控制组发送 SIGKILL。重启后原轮次标记 `failed / restart`，保留已收到的 1 字符；模拟器显示“VPS 重启中断了本轮，已收到的内容仍可查看”。 |
| 排队跨服务重启 | 上述中断时，另一会话的请求已排队。服务重启后它自动完成并返回 `HUB32-QUEUE-20261114`。没有把已运行且中断的请求自动重跑。 |
| 中断后继续原线程 | 重试同一请求编号没有新增轮次；在原会话明确发起下一条追问，正确回答原测试编号 `HUB32-RESTART-20261114`。 |
| 撤销设备 | 撤销隔离测试设备后，GET 和 POST 都返回 403。模拟器显示“设备密钥无效或已被撤销”，新请求没有进入数据库；已在本机显示过的文字仍可能留在内存，这不是新的服务端读取。 |
| 重启模拟器 | 重启整个模拟器后，原有正式连接可恢复，并完成真实 HTTPS 请求；没有要求重新填写设备密钥。 |

隔离服务仅监听 VPS 回环 8788，使用独立数据库、临时设备及独立系统单元。错误测试期间通过本机 SSH 隧道和 ADB 回环转发访问；这些结果不能冒充手机直接公网连接或 Windows 真关机。正式服务的退出恢复及续证请求则直接访问原公网 HTTPS，测试结束时没有残留 ADB 转发。

## 登录和额度错误的验证边界

- **真实官方运行时未登录**：隔离服务把官方 Codex 指向空认证目录。Android 发送后，服务记录 `failed / login`，顶部显示“VPS 需要登录”，回答位置显示“请在 VPS 上用 ChatGPT 账号登录 Codex”。正式账号和凭据未被退出。
- **429 故障注入**：独立协议桩在 `turn/start` 返回额度错误，经真实 Hub Worker、HTTP、原生桥和 Android 页面后，服务记录 `failed / quota`，界面显示“Codex 额度受限”及稍后重试说明。此例不调用真实模型，不是实际订阅耗尽。
- 恢复官方运行时后，隔离服务能继续完成真实请求，状态恢复为 `gpt-6.1-sol · prolite`。未静默切换到 API Key 或其他账号。
