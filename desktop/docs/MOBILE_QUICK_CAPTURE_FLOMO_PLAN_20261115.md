## 1. 先回答：是否必须进入云同步页面才能同步

**不需要。当前已经有自动同步，保存后会排入 Android 后台任务。** 正常过程为：

手机持久保存 → 上传记录和附件到 OSS → 指定电脑 Hub 读取并追加到对应日期的 OS 日记 → 写入有效回执 → 手机取回回执并显示“已写入 OS”。

自动执行要求本设备速记同步、云同步总开关、自动同步均开启，OSS 配置可用，且系统允许联网和任务调度。电脑写入阶段还要求指定电脑在线、Hub 在运行且 OS 保存位置有效。手动同步只能加快本轮尝试，不能代替未在线的电脑写入。

当前代码核对基线为 main `13ce20adef768f3e92eb70be03edbdce90ef853a`；本轮没有修改这些业务文件：

| 位置 | 已存在的行为 | 对体验的含义 |
| --- | --- | --- |
| `desktop/src-tauri/src/quick_journal.rs`：`capture_quick_journal` | 先入持久队列，再调用 `schedule_mobile`；安排失败以 warning 返回 | 保存成功与上传成功分开，安排失败也不能让已保存的记录消失 |
| `QuickJournalWorker.kt`：`schedule` | 带联网约束的一次性任务；追加／替换唯一队列，指数退避；另有 15 分钟周期回执任务 | 保存会主动安排任务；周期时间不等于必须等 15 分钟才上传，也不是精确回执时刻 |

### 建议的同步反馈

| 实际阶段 | 卡片显示 | 页面内操作 |
| --- | --- | --- |
| 已入本机队列，尚未上传 | 已存本机 · 等待上传 | 无网时说明“联网后自动上传”；有失败才显示具体原因与重试 |
| 正在实际传输 | 正在上传 | 附件有真实进度才显示百分比；没有测量数据时只显示处理中 |
| 已上传，尚无有效 OS 回执 | 已上传 · 等待电脑写入 | 说明“电脑 Hub 在线后继续处理”，允许就地检查回执 |
| 收到匹配原记录的有效回执 | 已写入 OS | 可查看结果；不靠 Worker SUCCESS 或云端存在同名文件推断完成 |
| 开关关闭或本设备暂停 | 自动同步已暂停／尚未开启 | 就地说明是哪一项；只有改配置时进入设置 |
| 传输、附件或认证失败 | 同步未完成＋可理解的原因 | 本页重试，沿用原 ID；保留正文和原件 |

顶部摘要分别列“待上传 N”“等待电脑 M”，不再合并为模糊的“待同步”。状态区打开当前速记的轻量详情，提供“立即重试／检查回执”和“同步设置”；刷新按钮直接处理速记，不先跑闪卡／阅读。一次正常保存就开始自动尝试，无需追加任何确认。

建议增加保存后与返回前台时的快速传输／状态刷新，后台任务继续兜底。快速路径必须复用现有锁、记录身份、附件校验和 **automatic=true** 的开关检查，不能直接把绕过自动开关的手动命令包装成“自动同步”。编辑区和保存按钮不等待云端或电脑回执。Android 后台执行仍受电源、网络与调度配额约束，不能承诺固定秒数完成。[官方后台任务说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

## 3. 编辑器复刻方案

### 结构与布局

采用覆盖在当前页面上的底部输入层：背景遮罩、圆角上沿、无大标题和表单边框的正文区、紧凑工具栏、原生键盘。默认直接聚焦，不增加必填标题、库选择或云同步步骤。今天是默认日期，补记日期和文件等已有能力收进“更多”，不删除。

以下是参考截图像素的估计，**不是 CSS 定值**：F1 的编辑层约 y=574—828，键盘从约 y=829 开始；F300 顶部约 y=511，F590 顶部约 y=374，而工具栏位置基本不动。正文左右留白约 30/576 屏宽，工具栏按钮中心约 x=39、90、172、230、314，右侧动作约 x=517。按实际 CSS 视口归一对照，不能把 576 像素直接写进组件，也不能按内容增高时反复压缩字体。

主工具顺序按视频为 **标签、图片、分隔、加粗、列表、分隔、更多、右侧主要动作**。小图标保留足够触摸范围，选中态使用浅底色，右侧为短胶囊形按钮。参考中的绿色按钮／光标是对照目标；原型中要清楚呈现参考色与 Hub 现有主题的映射，不能借局部复刻改动全站主题。深色、大字号与减少动态效果沿用产品要求，分别补验。

键盘只有一个尺寸／避让责任方。复用 `MobileQuickCapture` 和 `useMobileViewport` 的入口与状态，但复核原生 `adjustResize`／insets 与 WebView 视口的组合，防止双重抬高。编辑层最大高度受可见视口和安全区限制，正文内部滚动；工具栏、发送和当前输入光标始终可见。照片选择等外部页面返回时重新取得键盘，不新建草稿。

### 正文与格式

当前 `QuickJournal.tsx` 使用 textarea，B／列表目前在“更多”里插入 Markdown，未选文本时还会插入 `**文字**`。因此这次需要有限的所见即所得编辑能力，不能只调 CSS 后声称交互已经一致。

建议第一步限定到视频实际出现的段落、加粗、无序／有序列表和图片：编辑视图提供结构化状态，持久正文继续使用与现有 Markdown／OS 区块兼容的文本，附件继续复用原列表。保存、重新打开、卡片渲染和 OS 结果之间必须可往返，不能引入一份与原正文不一致的新权威文本。现有依赖没有完整的富文本编辑器；具体技术方案需先验证中文输入、selection、撤销和格式转换，再决定是否增加依赖，本轮不凭方案替换编辑框。

| 操作 | 应有结果 |
| --- | --- |
| B，未选文字 | 切换接下来的输入格式；图标同步选中态，不插入模板文字 |
| B，已选文字 | 对原选择应用／取消加粗；不丢中文、段落或光标 |
| 列表 | 在按钮上方打开视频所示浮层；当前段落可切换无序／有序，嵌套操作按适用状态启用 |
| 列表内回车 | 继续下一项；空项回车退出列表；粘贴多段内容和撤销保持正确结构 |
| 点击工具栏 | 保存并恢复 selection，不因为按钮夺焦点导致格式作用到错误位置 |
| 标签 | 沿用现有标签规则；视频只见入口，候选面板细节在后续原型补齐，不照猜测制作假数据 |
| 更多 | 放补记日期、文件、现有其他格式等；不把已要求常用的 B／列表藏回里面 |
| 空内容右侧语音入口 | 与 #22 已确认的实时双供应商转录方案接续；没有真实录音／转写时不假装开始成功 |
| 有正文或附件 | 右侧变为保存／发送动作，本机持久成功后收起；仅有附件也可保存 |
| 正在保存／附件准备 | 防重复点击；失败保留原稿与原记录身份，显示原因，不默默清空 |

原生中文输入的组字／候选过程不能被受控渲染打断。旧 Markdown 草稿需要无损加载，保存前后保留特殊字符；粘贴 HTML 和附件名称必须清理，不执行外来 HTML。图片在视频中位于正文之后，先复刻这一布局，不以此擅自迁移全部历史记录为任意块排序。

### 图片选择与附件准备

视频内完整展示的相册选择层也纳入视觉／交互清单：顶部返回、相册名／下拉、取消；四列网格和拍摄入口；圆勾选中状态；底部预览数量与完成数量。最终回传的是当前选择，不是看到缩略图就自动保存记录。

自绘相册需要单独的原生媒体访问适配。Android 14+ 必须正确处理全部授权、部分照片授权、拒绝与重新选择；只显示用户授权的媒体。可提供系统照片选择器作为权限受限时的可用退路，但要明确那是系统界面差异，不把退路当作相册层严格复刻已经完成。[官方部分照片权限说明](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)

用户选定后将可读原件保存到应用现有受管附件目录，再更新草稿；取消、权限撤销、文件消失、空间不足和超限都应保留原正文。沿用当前每条最多9个、单个20 MB及现有文件支持，不因参考照片网格就删除 PDF／文件入口或偷偷提高限制。

参考中缩略图出现上传百分比。Hub 当前先保存本机附件、正式保存后才进 OSS 队列，因此复刻该反馈时要标明“正在处理附件”或真实上传阶段；没有真实传输进度时不能播放虚构百分比，也不为了视觉相同而在用户尚未保存时静默上传选图。准备完成后缩略图可移除，移除不删除用户原照片。

### 草稿、返回与保存

所有 App 内入口、控制中心磁贴和 #53 的“记一条”共用当前速记草稿。打开本身不生成正式记录；有草稿就继续，没有才进入空编辑器。日期、正文、格式和附件落到持久草稿，光标／滚动等视图状态可作为辅助元数据保存，不能破坏已有草稿格式。

视频没有覆盖的 Hub 返回规则建议为：系统返回先收起键盘；再次返回或显式关闭保留草稿并回到原入口；从控制中心启动则正常回到 Hub 对应页面。不把关闭当作删除或保存，不在选择照片回来时因外部失焦自动收起。真正丢弃需显式操作，持久保存失败要有可恢复提示。

点击保存后先取得本机持久回执，再清理旧草稿、收起输入层并在原卡片流展示新记录及同步状态；草稿清理失败与正式记录保存失败分别处理。保留唯一 ID 和未知结果保护，不因 UI 超时再次创建同一内容。当前列表的置顶和筛选规则保持；新记录不属于当前筛选时提供“查看刚记录的内容”，不悄悄改掉整个筛选。

## 4. 图3：控制中心「记一条」入口

图3是 Android／HyperOS 下拉控制中心，不是桌面 AppWidget，也不是手机网页浮动按钮。增加一个名称清楚、图标有辨识度的“记一条”动作磁贴：点击后收起系统面板，进入同一速记编辑器并继续原草稿。它不显示同步开关的开／关状态，不自动写入任何记录。

原生使用受 `BIND_QUICK_SETTINGS_TILE` 保护的 `TileService`，显式启动本应用记录动作；现有 Manifest 尚无该服务。Android 13+ 可请求系统确认添加，取消和已添加分别反馈；不支持自动请求的系统提供手动步骤。Android 14+ 使用 `PendingIntent` 版 `startActivityAndCollapse`，锁屏时先通过系统解锁再显示原草稿。系统决定磁贴的颜色和布局，Hub 不绘制假的控制中心。[官方磁贴指南](https://developer.android.com/develop/ui/views/quicksettings-tiles) · [TileService](https://developer.android.com/reference/android/service/quicksettings/TileService)

现有 MainActivity 为 singleTask，仍需新增并核对冷启动／新意图的动作交接；原有 OAuth 入口不能被改写成速记专用。待 WebView 和草稿恢复后只消费一次“打开速记”意图，连续点击不多开、不清空草稿、不重建复习。前台有其它未保存编辑器时保留其内容，返回后可恢复。

桌面小组件、控制中心磁贴和 App 内＋共用同一领域入口，但原生添加方式和验收分开。#53 已确认的“今日复习＋记一条”小组件范围不因此自动扩展为已开发磁贴，#54 只记录本次新入口。
