## 修复

- 折叠工作过程后仍显示联网批次失败、部分未获取及中断提示，适用于运行中和结束后的记录；详细原因仍在对应批次中查阅。
- `hub_list_note_sources` 是宿主管理、按授权范围枚举材料的只读工具。此前调用它后，原生正文回答被误要求提交业务交付证明，导致正确的回答及引用无法交付。将其纳入明确的只读工具名单，保留来源、引用、版本及授权核验；未知工具、业务操作和被拒绝的 `finish` 仍不能借原生正文绕过核验。
- 更新工作过程重构后过期的前端测试：折叠操作由真实按钮触发，检查实际部分失败提示、批次说明及展开后保留的截断提示。

## 实际验收方法与已有结果

使用新建隔离目录和虚构《港湾演示方案》，不修改用户个人资料。Codex 原生生产路径通过真实提供方调用，不用模型桩代替回答。共享记忆未参与；没有业务写入或草稿创建。

| 场景 | 已核对的结果 |
| --- | --- |
| 无本地资料 | 空授权问答正确给出 17×23＝391；本地工具调用、引用均为空。桌面另测 19×21＝399。 |
| 使用指定笔记 | 正确返回代号海蓝-731、6 人、420 元、人均 70 元及 12 支铅笔，保存了与原文一致的本地引用。 |
| 本地＋联网 | 同一答复分别说明本地事实与联网事实；实际访问、查找 RFC Editor 的 RFC 9110，保留本地引用和 `providerResult` 网页来源。 |

前端 12 文件、274 项相关测试通过，前次独立复现用例由失败变为通过。最终源码对应的原生定向检查为 64 项通过、4 项专用验收忽略：原生回答 11/1、队列 16/1、独立助手 9/2、授权能力 12/0、来源证据 16/0（通过/忽略）。未运行全仓测试。

修复后的真实模型另行调用 `hub_list_note_sources` 和 `hub_read_note`，完整回答代号、70 元/人、12 支，并通过 `nativeResponseDelivery` 保存本地引用；`businessCompletionInferred=false`。这条实际失败链已在生产原生宿主复验通过，最终包的桌面复验单独记录。

## 失败记录与处理

- 首轮自建夹具误把 Obsidian 笔记路径写成绝对路径，读取被宿主拒绝。已按正常存储规则修正为相对路径，补齐内容与索引输入；原失败记录保留，未放宽路径校验。
- 首轮原生带资料调用误用了“无来源创建＋非空授权”，被创建入口拒绝且未启动模型。改用有来源入口；桌面另行检查用户实际选择资料库的路径。
- 桌面资料库场景确实复现了“枚举材料后原生回答被拒”的产品缺陷，成为上述只读交付修复的依据。
- 最初候选构建期间发现该缺陷后停止旧构建，保留失败回执；不采用其产物。最终使用新的冻结身份，重新验证所有产品输入。
- 全仓 `cargo fmt --check` 检出既存格式差异；本次改动的 Rust 文件单独格式检查通过，不批量改写无关文件，也不宣称全仓格式检查通过。

## 能力边界

综合联网由支持原生联网的 Codex 路径验收；DeepSeek 不因此新增原生联网能力。本地检索仍以现有关键词检索、授权材料枚举及读取为基础，不宣称语义召回完整性。清空资料库范围不等于撤回单独添加的笔记或删除既有对话。全局主搜索合并笔记、阅读及闪卡属于 #4，独立于本次 Agents 场景。

本次有限样本不等于多平台、所有来源和长期成功率保证；打包验证不代表安装替换或 GitHub Release 发布。
