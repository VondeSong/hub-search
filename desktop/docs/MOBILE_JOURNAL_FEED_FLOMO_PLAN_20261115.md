## 3. 页面结构与 UI 对照

### 列表页

按参考建立手机专用日志工作区：紧凑固定顶部、可滚动记录流、必要的快捷区、底部中央固定＋。标题显示“日志／当前视图”，不复制 flomo 商标；顶部左菜单和右搜索的层级、位置与点击范围跟随参考。现有搜索与筛选能力迁入搜索／视图入口，普通浏览时不让大搜索框、介绍文字和多排按钮持续占据正文空间。

卡片使用浅底、低对比边界和足够留白。日期与置顶信息在左上，更多在右上；正文沿用原段落、加粗、列表、标签、高亮及图片等实际内容，长文折叠后提供“展开／收起”。附件／语音是卡片内内容，不在每张卡片下堆一排“保存文件”按钮；文件保存改到附件自身菜单，保持已有导出能力。

参考估测，不能直接作为 CSS 值：576像素宽画面中，卡片约 x=16—560，正文左缘约x=33；相邻卡片间距约12；顶部图标中心约x=31／545、y=100；底部＋约73×73、x=252、y=1181，约占屏宽12.7%。正文源画面字号约21—22，段落行高约38—40。菜单约x=254—551、y=94—812。真实实现须按设备CSS视口、字体缩放和安全区归一对照，不直接照抄这些像素或将卡片高度写死。

中央＋固定在安全区内，下方渐隐背景只维持可读性；列表末尾留足空间，使最后一张卡片、展开按钮和附件都能滚动到浮动控件上方。为贴近参考，日志子页内不再叠加当前五项大胶囊导航；Hub上层主导航仍保留，侧栏／系统返回能回到原入口。这是日志子工作区的呈现，不重设计搜索、Agents、任务或复习页面。

AI洞察／每日回顾在视频中只是快捷入口，不能通过复制按钮就宣称功能完成。原型需展示其位置与有效状态；实际客户端按 Hub 已有能力关联 #2／#52，未接通的部分如实列为未接通，不能自动生成内容、调用模型或借复刻启动未授权的洞察开发。

### 卡片展开、滚动和动作

- 稳定ID作为卡片身份；展开状态、已经加载的图片和菜单对象不能因15秒刷新或同步返回而重建。
- 展开原地显示，收起时保留该卡片锚点，防止长记录使视口骤跳；进入编辑／返回恢复当前筛选、滚动锚点与展开状态。
- 置顶记录先显示，普通记录保持既有按日期／创建顺序的稳定规则；编辑不默认改变记录日期或把旧记录挪到今天。
- 点击标签进行本页筛选，并保留可返回的原视图；标签区域、图片、语音控件与更多按钮不能被整张卡片的点击处理抢走。
- 阅读长文时可选择／复制文字；单击正文进入同一记录的全屏页面，阅读、光标编辑和附件操作有独立命中范围，不因滚动手势误触编辑。
- 参考有时间文字，而 Hub 已有按天记录、不要求且不展示具体时分秒的明确规则：继续保持日期位置与层级，卡片显示记录日期；不为仿照画面伪造`00:00`或强制用户填写时间。若详情后续展示真实创建／编辑时间，须先有可靠元数据，未知就明确未知。此产品差异在原型对照中单列。

### 搜索与导航：参考未展示的补全

菜单、标题下拉和搜索图标虽可见，本段没有操作其内部。方案保留 Hub 的全部／今天／日期、置顶、有附件、无标签、关键词及附件名筛选能力，集中到搜索／视图入口；不能丢掉已有过滤条件来换取相似外观。进入和退出搜索恢复原列表；筛选没有结果与实际无记录分别说明。导航切换不清空新建稿或旧记录编辑稿。

## 4. 卡片菜单：12项入口逐个对照

第一行三项图标动作，其下九项文字动作，底部三行元信息。浮层在当前记录的更多按钮附近择向展开，受可用高度限制时内部滚动；保持顶部／系统安全区可达。点击外部或返回只关闭菜单，不直接离开日志页。菜单放到正确的最上层，不复现被父窗口盖住的二级层级问题。

| 参考入口 | Hub 当前可复用／缺口 | 后续复刻必须有的结果 |
| --- | --- | --- |
| 分享 | 有附件导出，但没有已核通用手机记录分享闭环 | 调起真实系统分享，明确正文／图像／文件范围；用户取消不产生新记录 |
| 编辑 | 当前手机卡片无该入口；现采集协议不允许原ID换正文 | 进入同ID的完整编辑器，保留原版本和附件，按第5节提交变更 |
| 复制 | 桌面菜单已有复制正文，手机菜单被隐藏 | 复制当前正文，明确是否含Markdown；不能只复制折叠摘要、附件路径或显示假成功 |

| 相关笔记 | 没有已核的手机记录关系结果页 | 先接真实标签／明确引用等依据，说明关联原因和范围；AI关联需单独显式动作，不能编造匹配结果 |
| 查看详情 | 原记录ID、日期、附件与同步状态已有基础 | 打开记录详情，正文／附件、同步阶段及真实来源可核对；不把采集副本说成电脑最新原文 |
| 历史版本 | 当前不可变采集不等于可恢复的编辑版本史 | 保存修改前后真实版本；查看／比较及恢复明确目标，恢复是新操作而非抹掉历史 |
| 复制链接 | 现Android深链只核到OAuth用途，没有手机记录定位闭环 | 使用稳定记录定位；打开后校验是否可访问，缺失明确提示；不复制电脑绝对路径冒充手机可用链接 |
| 批注 | 未核到跨端的记录批注模型 | 原文与批注独立，绑定记录及版本；不偷偷改写原正文或自动跨库写入 |
| 设定日期 | 新建草稿已有日期；旧记录跨日日记移动尚无闭环 | 调整原记录归属日，保留ID；同步完成后原日与新日只保留正确的一份区块，失败不只改单个手机标签 |
| 删除（红色） | 未核到速记跨端删除／墓碑协议 | 明确删除范围、确认和恢复策略；防云端再次导入，保留外部人工编辑及未共用的原件，不只从列表临时隐藏 |

元信息是“字数统计、创建时间、最后编辑”。字数规则统一并清楚定义正文／标签是否计入；格式标记和附件路径不冒充用户文字。当前 `Record` 只有日期，没有可靠的创建／最后编辑字段，不能把数据库顺序号或日记文件修改时间当作记录创建时间。旧数据迁移允许未知，不能凭空补齐。

上表所有项目都进入完整复刻清单，但“看到入口”“Hub已有能力”“待新增能力”分别记录。后续原型可以演示完整状态并标明示意；客户端未实现的入口不得报告成功，也不能通过删掉参考中的项目来声称整页功能齐全。

## 5. 两种编辑状态必须分开

| 状态 | 新建记录：第一段视频 | 旧记录编辑：第二段视频 |
| --- | --- | --- |
| 容器 | 当前页面上方的底部面板与遮罩 | 独立全屏页面，无新建遮罩 |
| 顶部 | 无完整详情导航；维持轻量输入 | 左返回／有改动后的确认勾，右更多，正文前有原记录日期 |
| 底部 | 工具栏＋右侧主要动作 | 同一组格式工具；没有新建发送胶囊 |
| 身份 | 草稿ID；真正保存才创建正式记录 | 原记录ID不变，另外记录编辑草稿和提交操作身份 |
| 关闭／返回 | 持久保留草稿；不因为失焦或关闭就创建正式记录 | 未改动直接返回；键盘存在先收键盘；有改动时按参考执行修改提交并返回 |
| 保存反馈 | 本机保存后出现新卡片 | 原卡片进入更新／同步状态，列表位置和原日期保留 |

视频F480的系统返回反馈与F490的同步状态说明，旧编辑的返回不是新建稿“仅保留未提交草稿”的那套语义。方案采用：确认勾或键盘已收起后的系统返回，都先持久保存本次变更操作，再返回原列表并自动继续同步；持久保存失败保留编辑器和可恢复内容，不能只关闭页面。返回手势取消不提交；仅收键盘不提交；未改内容不创建版本。

参考只能证明上述UI反馈，不能证明它远端已完成，所以 Hub 仍要区分“修改已保存在手机”“修改已上传”“电脑已应用”“发生冲突”。正常变更不增加一次无意义确认弹窗；只有与外部编辑冲突、范围变化等需要用户选择的情况才提示。

### 建议的受控变更闭环（未实现）

保持原采集对象不可变，增加独立、版本化的变更操作，而不是覆盖 `journal/records/<id>.json`。操作至少绑定原记录ID、操作ID、类型、基准版本／正文摘要、修改内容和附件清单。重试使用同一操作ID；原记录ID、历史链和有效回执保持连续。

指定电脑仍是 OS 写入端：按基准核对实际原文，只修改目标记录区块，保留日记其它字节和人工内容；外部已改、区块缺失或版本不符时返回冲突，不能覆盖。电脑发布实际应用版本及回执后，手机据此更新展示的副本；旧采集回执不能冒充新编辑已应用。没有取得可靠基准时可以保存本机编辑草稿／待核对操作，明确等待电脑核对，不伪称已改OS。

改期涉及两个日期文件，删除涉及墓碑与云端重放，历史恢复涉及新版本，均必须按同一操作身份处理部分失败、回读和恢复，不能只改单个页面字段。附件继续哈希校验和引用保全；删除一条记录不等于删掉用户图库原照片或别的记录正在共用的附件。

这也是本次复刻区别于“换皮”的主要成本：现有输入／卡片可以复用，但手机已有记录的编辑、历史、删除和日期调整缺少完整受控闭环。上表是后续实现与验收条件，不是本轮已开始迁移协议、全库同步或向OS写入。
