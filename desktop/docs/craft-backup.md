# Craft 本地备份与 Obsidian 恢复

在「设置 → 资料库 → Craft → 备份与恢复」首次设置名称和间隔。保存位置由当前 Hub 数据目录自动管理；「立即备份」与自动备份共用保存的名称、位置、间隔和第二份副本设置。完成后在数据目录内产生两个独立目录：

- `名称 - 备份/`：原始对象、不可覆盖的恢复点清单和采集报告。
- `名称/`：用于日常阅读的 Obsidian Vault。

原始备份位于 Hub 数据目录内的 `external-sources`，与可重建的搜索索引分开，清理索引不会处理它。图片、视频、压缩包等原件均自动保存；文字识别单独控制。每个 Craft 空间保留自己的备份间隔。

Hub 启动时自动收拢旧版目录外的原始备份和受管附件；新备份和新增附件直接保存在当前数据目录。每个附件核验哈希、长度和原件内容后用于预览；未完成采集中的有效附件也可接入，但不会将资料库标记为完整备份。数据库保存页面、资源地址和目录内原件的对应关系。独立 Obsidian 原库不搬运，旧版外部原件保留。

资源地址刷新时，原生附件通过有效的块 UUID 关联。仅在 Markdown 正文中出现的附件分别按地址记录；当当前整篇正文与已校验备份正文完全一致、仅 Craft 资源地址不同，才建立旧地址到备份地址的对应关系。正文随后发生变化时对应关系失效，避免同名图片或旧版本内容被误用。

图片与视频优先读取可用备份原件，其次使用已有缓存；都没有时按需获取。预览与后台处理共用附件下载锁，旧版本的预览不能覆盖新附件。文件附件点击时优先打开本地工作副本，避免外部编辑器修改备份原件。PDF 可继续进入原有正文提取流程；接入文件不等于所有格式的附件正文都已建立全文索引。接入备份同时核对当前附件版本、字节数和下载状态，原文修改时间缺失也不能让旧附件版本覆盖当前版本。备份文件移动、缺失或发生变化时重新检查或回退，缓存清理只处理搜索缓存目录内的文件。

## 保存范围与完成标准

每次遍历当前连接可访问的普通文档、未分类页面、日记、模板、回收站，保存文档原始结构、Markdown 和返回的元数据，并读取集合 schema / items / views、白板 elements / assets / appState。Craft 托管的附件原件和原生 Unsplash 图片流式下载，核对元数据字节数并用 SHA-256 回读验证。单文件上限为 4 GB，超限会阻止完整性确认。

采集前后复查文档清单、修改时间和文件夹清单。任何必要请求失败、未知块资源不能确认、附件缺失、字节数或哈希不匹配，都留下 `attempts` 报告，不提交新的恢复点，不更新现有 Vault。报告保留失败对象和原因；重试时重新读取云端地址。

附件格式从已保存的原始字节识别，避免 Craft 返回通用名称或空 MIME 时将图片和视频导出为 `.bin`。现有受管理附件会修正扩展名并重建正文链接，本地修改保留。空图片、视频、Office 文档等原件、二进制附件返回 HTML，以及结构不完整的 JPEG 都不能通过完整性确认；哈希一致仅证明保存字节未变，不能证明媒体可解码。媒体格式识别也不等于所有播放器均支持其编码。

`snapshots` 只收纳完成的恢复点。历史文件不可覆盖，云端删除不删除过去的快照。重复原件按内容哈希共享磁盘空间。立即备份和自动备份仍重新读取页面结构、评论、集合与白板元数据，但附件自身版本与资源定位匹配、且本地原件哈希和长度通过核验时，会复用已有备份或搜索缓存中的原件。历史备份未登记附件版本时，先从保存的原始结构恢复版本证据；没有版本证据时，可用远端强 ETag 和长度核对，匹配则不下载文件正文。缺少可靠验证信息、附件有变化或本地原件损坏时重新下载；父文档修改时间不能单独证明附件未变。默认永久保留历史，没有自动删旧快照功能，需预留磁盘空间。

这不是 Craft 的系统级镜像：公开读取接口未提供完整历史版本和权限恢复。仅返回的评论及其它元数据被保留；不可访问数据、第三方嵌入的服务内容及全空间同时刻事务一致性不作保证。外部服务地址（例如飞书网页）记录在 `externalReferences` 和采集报告中，数量在界面单独显示，不假装已保存对应服务资料。未知块类型和无法下载的必要原件会阻止“完整”确认。

## 原始目录结构

```text
名称 - 备份/
  archive.json         # 格式版本与空间身份
  objects/             # 按内容哈希保存的正文、结构、附件、集合和白板对象
  snapshots/           # 完整恢复点清单；每份引用所需对象
  attempts/            # 进行中记录、未完成清单、采集报告
```

请复制整个原始备份目录，不能只复制 `snapshots`。原始备份目录保留云端资源地址与返回的作者等信息，按个人资料保存；不保存 Craft 连接凭据。

## 自动备份与第二份副本

可选择手动、每小时、每 6 小时或每天。后台任务与同步、手动备份共用互斥锁，不会并发采集同一个 Hub 实例；Hub 需要运行且连接可用。重启后从持久化设置继续，到期执行。失败原因显示在恢复点面板；采集间隔从最近尝试计算，失败不会每秒重试。

可选择第二份副本的父目录。副本独立保存原始对象和快照并回读校验，不依赖第一份文件。两个目录不能互相包含。不同路径不等于不同物理磁盘；建议选择移动硬盘或另一台设备的同步目录。外部同步本身是否完成需由相应工具确认。

## 更改保存位置

原始备份随整个 Hub 数据目录保存。需要更换磁盘时，使用「设置 → 数据管理 → 备份与迁移 → 更改数据位置」，整体复制并校验后切换，原目录保留。换电脑时完全退出 Hub 后直接复制整个数据目录，再在新电脑打开已有数据目录，无需单独的复制前准备。备份间隔和可选第二份副本仍可在 Craft 恢复点面板设置。

## 离线恢复

「从已有备份生成 Obsidian 库」可以选择原始备份或第二份副本，无需保留原 Craft 资料库或连接。选择恢复点，先「核验原始备份」，然后「生成 Obsidian 库（另存为）」。核验失败时停止生成。

已配置空间还可「生成 Obsidian 库（原位置）」，重新生成同一个正常阅读目录，不新增另一套原始备份。它只从该空间当前备份位置的完整恢复点读取，保留本地修改。「另存为」使用带恢复点编号的独立副本名称；两种生成操作均不更改自动备份设置，也不主动访问 Craft。原位置更新与联网「立即备份」的区别是内容来自所选本地恢复点。

恢复不访问网络，也不向 Craft 写入。正文和附件从原始备份生成，`Craft 原始资料/恢复点/` 提供原始页面结构、元数据、集合信息与白板文件。`.excalidraw` 文件可用 Excalidraw 打开，Obsidian 原生不直接编辑白板。Craft 的布局、交互式集合视图和样式不会完全等同于 Obsidian。

同一 Vault 更新时，已有本地修改保留，生成独立的「Craft 更新」文件，链接使用本次分配的实际路径。云端删除也不自动移除 Vault 中旧文件；需要精确复原某一时刻时，恢复到新目录。

段落定位编号只为实际被引用的块生成。更新时也会检查阅读库中已有的本地段落链接，保留它们需要的定位编号。Hub 阅读预览隐藏这些编号，并支持文内段落跳转；代码示例中的编号和普通正文不作清理。Obsidian 源码模式仍可能显示少量用于跳转的 `^编号`，阅读模式将其作为定位信息处理。原始备份中的块身份和结构始终保留。

首次备份必须实际完成且核验通过，才能视作已有可用副本。建议复制到另一块磁盘后再次执行离线恢复，确认页面与附件均能打开。成功快照只能代表该次捕获的数据和接口覆盖范围。

旧版本已经写入的历史清单不会改写；发现其中包含空 Office 原件时，新版会排除该点并显示原因。历史 JSON 中的旧 `complete` 值不能代替当前核验。2026-09-27 附件内容复核已撤回 Car 的完整性结论；Car 和 Main 的阅读库仍保留可用内容，具体缺项以备份目录中的 `附件内容与格式复核.md` 为准。

## 本轮验证边界

Windows 当前工作区：类型与 Rust 编译检查；针对备份及导出模块的聚焦测试；恢复界面错误展示和无连接恢复交互测试；前端生产构建及包含内嵌前端的 Windows 预览版构建。恢复测试覆盖附件损坏拦截、页面清单不一致、删除第一份后的第二份副本恢复，以及本地修改保护。

真实空间采集的结果以备份目录下的 `snapshots`、采集报告和 `本地完整性核验.json` 为准。`attempts` 中保留早期失败记录，不能当作成功恢复点。`离线恢复验收/` 用于从真实恢复点生成新的 Vault，演练不使用 Craft 连接或搜索数据库；它仍在同一磁盘，不能当作另一物理设备上的第二份备份。

首次验收过程中，如源附件不可访问，可在另一个 `未完成阅读副本/` 目录生成已保存内容的阅读库。这里的“未完成”指附件采集不完整，建议在说明中称为“Obsidian 阅读副本（附件有缺项）”，与阅读进度无关。它会带有醒目的缺项说明、原始缺项清单和导出报告，不能当作完整备份，不替代正常 Vault，不把失败采集改成成功恢复点。这是本次实际验收的辅助材料，常规界面仍只从完整恢复点生成库；本轮没有改名或移动已有阅读副本目录。

工作区根目录的 `Hub_CraftBackup_优化版.exe` 是本次界面与配置优化版。原 `Hub_CraftBackup_preview.exe` 因正在运行而保留，没有覆盖。退出旧 Hub 后打开优化版，再到设置管理备份。每日备份需运行含备份功能的版本；仅配置备份而继续运行不含此功能的旧版，不会执行定期采集。
