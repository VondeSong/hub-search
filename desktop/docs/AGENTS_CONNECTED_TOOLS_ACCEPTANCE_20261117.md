## 发现的问题与整改

1. **市场应用目录不等于可调用目录**：安装版 `app/list` / 冷启动 installed 结果可能空、延迟或超时。改为无模型侧车读取正式网关工具注册表，按 `_meta.connector_id` 分组和过滤。网关可能返回所有应用，完整目录绝不是本对话授权；调用转发当前工具自己的注册元数据。
2. **原生目录容量不同**：Apps 发现帧采用 4 MiB、90 秒 RPC 上限；主模型保持 512 KiB / 原有约束。选定工具目录和模型结果仍有容量守卫，不静默截断工具定义。长评论线程最多由宿主内部核验 3.5 MiB，无关评论不进入模型或持久工具记录。
3. **新动作误走笔记和标签检查**：无笔记 anchor 的评论草稿被旧 inspector 拒绝，已核验插件回执也曾落入补标分支。补齐 pluginWrite 的检查、inspect、事实、完成依据及回执提示；UI 的状态和忙碌文案独立标为 GitHub 评论。
4. **错误重试与过期身份**：执行中断保持 unknown，不能重发；同决定重试沿用动作。新决定只允许重新准备从未发送的旧草稿；已经发送、结果未知或已核验时保留原动作身份。撤销后隐藏不可继续执行的草稿正文与确认入口。
5. **Playwright 导航默认返回快照文件链接**：不能把文件路径交给模型或冒充内联正文。导航提示显式调用 `browser_snapshot`，仅内联快照提供元素引用。过期引用返回失败活动，允许重新快照后继续；授权和传输失败仍停止该服务。
6. **多标签来源串入**：会话中的全部 open pages 曾都可成为 snapshot 来源。现由实际 snapshot 回包的 Page URL 与真实 open pages 交叉检查，只记录当前读到的页面；其他标签只作会话元数据。
7. **实测运行所有权**：GUI 与独立测试宿主同时读取同一活跃聊天会触发进程内孤儿运行回收。完整模型验收期间不由 GUI 轮询该聊天，避免用两个运行宿主管理同一个任务；失败记录保留，最终成功运行单独取证。此实验限制不冒充支持多实例同库运行。
8. **模型设置必须完整**：首次验收仅指定高强度而未指定支持该强度的模型，提供方拒绝；改为实际支持的 gpt-6.1-sol / high 后通过。没有把提供方拒绝改写为产品成功。
