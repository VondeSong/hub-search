# Windows Hub 工程资料联合验收

2026-11-19，Windows 版 Hub 0.16.396，代码基线 74e799a。使用日常资料库和 Codex gpt-6.1-sol（中等推理），在同一对话中读取工程资料、计算、交付和重开后续读。

| 检查 | 观察结果 |
| --- | --- |
| 读笔记和图纸 | 回执显示读到「1 线束」正文第 12,000 字符。工程 PDF 第 1 页图像实际送达，回复说明了已辨认的图面信息和需要看高清原图的细节。 |
| 统计真实 T29 工作簿 | 五张表的非空行数依次为 78、9、1、91、81，公式格均为 0。独立用工作表读取器复算并逐表核对。原件可选自定义属性会使普通读取报错，本轮实际用只读 ZIP/XML 扫描完成统计，输入哈希与原件一致。 |
| 交付和导出 | 同一成果第 1 版包含 Markdown 检查单及 CSV。实窗显示两份文件和原回答。通过正式本机导出逻辑各导出两次，重复请求复用原回执，两份导出文件均经独立哈希核对。 |
| 正常退出和接着做 | 退出脚本和原进程均正常结束，新进程启动后从历史打开同一对话。实窗追问只补读一段，新增引用落在 12,000–14,000 字符，另有一条先前范围内的引用。约 37 秒交付一条答复，未新增表格分析或业务动作，导出文件哈希一致。 |
| 替换原件 | 用两份真实 T29 版本与独立 T28 分析复测，约 32 秒。换版后旧 T29 结果失效，使用新版发布同一成果第 2 版。T28 仍使用第 1 版及原有文件哈希。 |

首次联合任务约 175 秒。补测使用当前基线的 Rust 测试程序，图文权限、资料覆盖、分析及导出相关 19 项通过，6 项默认忽略。另有真实联合任务、重复导出和真实文件换版通过。Windows 界面验证复用了同一真实任务的回执。Hub 保持在本机开发模式。

## 导出后遇到连接故障和版本变化

沿用上述同一真实任务。两份成果已导出，在后台测试进程中让模型连接不可达。约 133 秒后本轮报出提供方连接错误。已有答复、计算记录、导出回执和两个文件的哈希均经回读确认。

正常退出 Hub 并启动新进程，从同一对话点「继续调查」。期间笔记版本发生变化，系统拒绝以旧版的第 14,000 字符为起点。该轮只解释原因，没有新原文。随后明确按当前版本补读，从第 0 字符读至第 2,000 字符，得到可定位的引文。覆盖记录保留两个版本各自的阅读范围。两轮恢复共新增一条失败说明和一条引用新版本的答复，分析、导出回执及业务动作均无新增。再次核对两个导出文件的哈希，均与原回执一致。

远端实时取件、真实缺公式缓存的工作簿、接近上限的容量和其余故障组合仍按 #58 跟踪。资料库界面一度显示连接未恢复，本轮使用已授权的本地资料。实窗截图留在会话，真实原件、报告、导出副本和回执留在本机忽略目录。
