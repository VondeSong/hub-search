## 明确未完成项（继续跟踪，不作为其余 UI 的阻塞）

1. **#29：完整资料策略与通用专题。** 材料优先/仅依据材料/开放研究尚未形成后端持久化协议和每个工具/记忆入口的强制边界；本轮没有仅靠提示词或联网开关宣称实现。站点的多来源专题、专题/手选双来源记录、同项去重、只在下一条临时纳入手选、专题切换/取消、失效来源复核和跨来源通用模板均待接入。现有 Obsidian 固定方法/按期工作继续有效。
2. **#30：标签任务统一会话尚缺。** 目前是在助手内复用原有真实审核组件，尚未让三项任务通过普通输入框统一提交，也未继承本对话模型/临时资料范围。普通模式多标签结构化引用、两枚明确比较对象、定义查看与切换、关联资料任一/同时搜索、标签拖拽和任务结果进入同一消息历史仍需实现。关系后台仍按当前标签相关候选范围分析，不能声称只读取资料面板中的内容。未改现有定义版本、漏标分批续查/预演及来源写回规则。
3. **#31：通用插入与创建。** 当前真实回写仅支持已授权的 Obsidian 目标与当前最新报告。原型的搜索任意页面、编辑插入正文、任意历史回答插入、新建笔记和新建行动任务尚无统一真实交付合同；不能用“归档参考笔记”冒充创建滴答行动任务。暂保留现有目标选择、草稿、预览确认和实际回执。
4. **#28：运行保护。** UI 自动发送不等于后端自动扩额度；原有单轮/累计执行限制及已经手动保存的旧 Token 预算仍然有效。自动选择执行档、触限后继续所需额度、完整生成优先等验收仍属 #28。本轮只移除对话预算表单；未清除用户旧预算，也未把上下文窗口当累计预算。
5. **Windows 实机验收。** 本轮遵循不控制电脑的既有偏好，从两个项目源码和自动化测试验证。尚未进行真实 WebView 的主题/窄窗/缩放/触屏截图比对，也未替换正在运行的桌面二进制；真实模型、MCP 账号与外部写入不因 UI 测试通过而算验收。
