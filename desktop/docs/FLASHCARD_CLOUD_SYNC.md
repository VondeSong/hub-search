# 闪卡云同步

云连接和设备开关已移至“设置 → 云同步”，闪卡云按钮打开同一入口。总开关、自动同步、模块开关与迁移规则见 [Hub 云同步](CLOUD_SYNC.md)。闪卡的本地备份与恢复仍在闪卡页面。

## 范围与数据真源

本阶段同步牌组、文件夹、卡片、复习事件、学习设置、收件箱草稿及其处理状态、质量反馈、已接受的制卡规则、规则建议和历史，以及这些记录引用的附件。Craft / Obsidian 原资料库、索引、授权与账号不在本阶段同步范围内。

设备本地数据库拥有领域状态；同步协议传递记录，禁止直接在两台设备之间同步 SQLite 文件。全部服务复用同一领域合并入口。密钥通过平台安全存储保存，不进入同步内容或报告。

## 服务

- 坚果云 / WebDAV：已退出。连接、传输、测试及互迁代码已移除；仅保留历史备份的离线快照解码。本机内容与旧云对象不删除，仅存旧云端的内容应先用旧版取回。详见 [退出记录](CLOUD_WEBDAV_RETIREMENT_2026-11-12.md)。
- 阿里云 OSS：私有 Bucket、地域、同步目录及专用 AccessKey；原生 OSS V4 签名。目录路径只允许 ASCII 字母、数字、横线、下划线和斜杠。
- AWS S3：后续接入；目前没有显示一个尚未接通的 AWS 选项。

OSS 使用不可覆盖的对象日志，不共同覆盖一份快照。普通同步只发送发生变化的完整实体记录，未采用字段或字节差分。每次变更按 `设备身份 + 正文 SHA-256` 写入新对象；首次同步、迁移，以及本机已完成上传计数到达 50 的正倍数后的下一次有变化，会产生完整检查点。无变化不因此生成新检查点。检查点与删除记录仍保留，当前版本不自动删除云端历史。

日常云同步只使用 OSS。云连接页直接配置 OSS，没有 WebDAV 选择或反向迁移。更改活动 OSS 云位置仍需暂停其它设备，并经过复制与逐项读回核验；已绑定速记时拒绝变更云位置。

自动同步在本设备保存，应用运行且网络可用时尝试同步。移动系统可能限制后台运行，不承诺关闭应用后或任何网络条件下均能在固定时限内完成。OSS 传输详情表达最近一次同步结束时的状态，不作为实时附件缓存检查。

对象布局：

```text
<prefix>/v2/changes/<device>-<sha256>.json
<prefix>/v2/media/<sha256>
<prefix>/v2/probes/<sha256>
```

变更外层格式 `hub-flashcard-changes`，当前写入版本 4，读取兼容版本 2、3、4；内部快照继续由领域序列化器拥有。ListObjectsV2 分页完整读取；失败或无效游标不能当作列表结束。内容身份不匹配时拒绝导入，不推进已应用清单。

确认上传的同一事务登记自身已应用对象，避免重新读取自己的日志。当前源码把完整分页清单、已应用记录与结构合并状态保存在 SQLite，按索引逐对象查询，不在 Rust 中一次载入全部历史键或已应用集合。领域合并后，仅将与已验证远端条目完整相同的记录纳入逐记录已知基线；网络期间的本地编辑、合并生成的冲突历史和派生状态仍待后续上传。每轮仍完整分页查询：当前哈希对象名称没有单调顺序，不能用最大键或最新检查点跳过长期离线设备补交的数据。

## 失败与恢复

上传队列在网络副作用前写入本地数据库。网络失败保留相同正文和对象身份；确认丢失时先读回对象，不能用新身份重复生成同一次上传。领域合并成功后才登记已应用对象；此间中断会幂等重放。同步仍在使用本地正常编辑入口，修改后保留待同步状态。

已完成本地队列只保留对象身份、状态与计数，清空重复的正文和完整基线载荷；正式当前基线和 pending 的重试载荷保留。这会释放可复用的 SQLite 页面，不承诺数据库文件立即缩小。云端历史清理仍需证明覆盖范围和离线恢复能力，当前不自动删除旧日志或附件。

草稿接受使用由草稿身份派生的卡片 ID；两台设备离线接受同一草稿后只产生一个卡片身份。接受、拒绝及重复状态不会由旧 pending 草稿回退。相同秒时间戳的卡片冲突使用确定性的序列化内容顺序收敛。复习事件按 ID 合并后重算计划；删除记录阻止离线复活；质量记录使用质量模块已有的版本与冲突保留机制。

## 附件

附件按 SHA-256 去重；上传后读回并校验，已有对象优先通过 HEAD 响应的摘要元数据及 `Content-Length` 头核对，不将空 HEAD 正文的大小误当附件大小。两者一致时不读取正文或重复上传；元数据缺失或不匹配时仍完整读回比较，内容不一致拒绝覆盖。支持“全部下载供离线使用”和“打开时下载”，后者在后续提交内容变更时也不会自动下载全部附件。未下载附件保持明确待下载状态，下载并校验后才成为本地附件；同时恢复文件类型索引，SVG 在校验安全内容后恢复正确的图片类型。单附件上限 250 MiB；SVG 与现有导入入口仍按自身 64 MiB 合同校验。普通同步不会伪造缺失附件已就绪。

本机已校验的不可变附件按路径、大小和精确文件时间记录校验结果；普通重试在这些信息不变时复用 SHA 与类型校验，每次仍重新检查当前云对象。新文件、时间或路径变化、切换文件根与明确强制核验都会重新读取本机字节；强制核验还独立读回全部当前引用的云附件。本机信息缓存依赖内容寻址文件不被外部原地篡改的约定，保留全部文件信息的恶意改写需强制核验才能检测。单项打开附件复用同一个类型索引与校验入口。

附件上传和下载按 64 KiB 块处理，下载先保存在本机暂存文件，验证摘要、大小并完成写盘后才成为正式附件。失败不确认媒体队列；上传响应丢失时按实际远端字节确认，不产生覆盖写入。统计记录实际读取或发送的正文块（包含读回与列表正文），不包含 TLS / HTTP 协议开销，不作为运营商计费账单。

单个变更对象继续受 32 MiB 传输上限约束，超限明确失败并保留本地记录。普通 OSS 恢复使用最多 128 MiB 的本机正文暂存窗口：逐对象验证与事务应用后释放窗口，历史总量超过该窗口时继续处理，而不是只恢复前 128 MiB。每页列表及单对象有界，完整历史的清单和收据由 SQLite 拥有。正式历史清单、维护预览与迁移没有 200,000 项总条数截断；200,000 项仅是单个 Proof 替代对象的既有协议条数上限，以及旧测试聚合参考入口的限额。显式维护继续使用自己的 2 GiB 暂存及分批核验合同。

## 本机资源与旧版本兼容

`flashcard_snapshot` 拥有全部领域记录映射和合并；普通变更按逐记录修订读取，首次同步、每 50 次有变化的检查点与强制核验仍需要扫描完整当前内容。结构冲突、墓碑、复习顺序及草稿身份使用相同领域规则；整库快照保留给正式导出与历史备份的离线读取。

旧完整基线和 pending 的 `baseline` 字段继续是旧版本可读取的有效完整 JSON，不写入占位标记。旧合法本机基线即使超过 32 MiB 也通过只读 BLOB 单遍读取，逐记录确认由独立表保存；尾部损坏或事务失败回退整个导入。新 pending 在 SQLite 内复制既有有效基线，避免在 Rust 中构造整库 String/Value；为保留旧读者兼容，这个字段仍有与完整基线大小成正比的磁盘复制成本，SQLite 处理复制或类型转换时也可能暂存完整单元格，不能把 Rust 层的有界分配视为整个进程的恒定内存上限。旧客户端可能基于陈旧但有效的基线多做幂等重传；新客户端根据已应用收据与冻结值恢复准确确认，保留期间发生的新编辑。

资源有界不表示恒定总工作量。每轮仍检查完整云清单、当前附件文件信息与远端 HEAD；缺少可信摘要元数据的旧附件仍需读回正文。检查点、首次旧基线导入和兼容 JSON 发布需要完整扫描或磁盘写入，强制核验需要全部附件字节。单条记录可包含较大合法正文，SQLite 单元格上限及既有传输和 SVG 上限保持生效。本节描述当前源码的生产链；本轮统一编译、回归与独立运行结果以最终验证收据为准，不据此宣称真实 OSS 或安装版本已验证。

## OSS 云位置迁移

1. 所有设备先升级到支持收件箱同步的版本，并完成当前服务同步。
2. 暂停其它设备编辑及自动同步。
3. 保存目标配置并测试列表、上传、下载及读回校验。
4. 本设备合并原云端与本机数据，再合并目标端内容，迁移闪卡、阅读、原附件、来源凭证、资料库副本、设备日志与检查点；模块开关不排除历史数据。
5. 逐项读回内容及附件、校验成功后才提交活动服务；失败保留原服务和原配置。迁移期间检测到本机编辑时也不切换，待停止编辑后重试。
6. 其它设备配置相同的目标位置（OSS 的 Bucket / 地域 / 目录），完成切换后再恢复自动同步。

首次从旧 WebDAV 升级时不再读取旧服务，只合并本机已有内容和目标 OSS。旧配置与旧云对象保留，不自动清理。

创建云端账户、购买服务、设置 Bucket 及授权由用户完成。建议私有读写、专用目录权限、启用云端版本保护。日常同步、迁移与连接探针只需要列表、读取和写入本目录，不要求删除权限；明确使用历史清理时另需本目录的精确删除权限。每次测试连接会保留一个带随机标识的小探针对象，以重新验证当前上传和读回权限。

## 验收边界

本地隔离数据库与 HTTP 对象服务用于验证协议、分页、并发、断线、重启及损坏内容。它们不能证明真实 OSS 的地域、权限、签名或双端运行已经通过。真实云验收与模拟器结果见 [当前云同步合同](CLOUD_SYNC.md)，实体手机仍单独待验证。

云端设备、可验证检查点、显式历史清理和长期离线恢复的当前合同见 [Hub 云同步](CLOUD_SYNC.md)。OSS 承载共享阅读与闪卡同步。维护采用有界持久批次，保留逻辑删除和全部复习事实；恢复经正式合并与逐记录已知基线入口。历史和附件不自动清理，显式清理仅删除已被核验检查点确切覆盖的不可变记录；旧服务内容不由新版访问或删除。手机可查看和恢复记录，设备退休、云检查点发布与历史删除由桌面端管理。

后续扩展：AWS S3、大附件分块续传、来源 PDF 的显式归档，以及其它 Hub 数据。不能把这些后续能力显示为当前已经可用的设置。
