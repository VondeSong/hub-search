# 洞察 P0：真实资料与助手＋Skill 对照

对应 [#52](https://github.com/VondeSong/hub-search/issues/52)。这是一次有明确边界的产品检验，不把完成实现清单当作独立产品价值成立。

## 事先固定的合同

2026-11-15 在第一次模型运行前固定三组正常 Hub 资料：工程文件与笔记组织建议；增加页面结构资料后对原判断的补充；两份真实阅读摘录的回看。第二组使用已保存的原判断文字，不把新加入分析的旧笔记称作今天发生的新事件。阅读组区分作者观点、划线、本人评论、元数据与实际完成，不推断用户已读完或采用某种方法。

每组对照“洞察直接入口”与“统一助手＋相同分析方法”。两者使用同一原文、明确选择的资料、模型 `gpt-6.1-sol`、`quick` 预算、外部 MCP 关闭及相同的正式分析指令，交错执行先后次序。Skill 基线也可以读取全部所选正文、生成结构化结果及使用既有保存能力；没有故意给它残缺资料。两条路径均复用统一助手，预期差异首先在资料组织、结果搬运与接续，不预设模型答案一定更好。

完整首次输出、错误、原文、版本及实际计量保留在本机忽略目录。每组每条路径各运行一次；明确技术故障的修复复验要另记尝试，不能覆盖失败或为挑更好语义回答重复抽样。没有测量到的字段保持未知。程序路径计时不冒充用户操作计时，不能用自动化耗时推导真人节省几分钟。

历史检索另行检验：一份当前记录，明确允许本次查找的历史库，展示未手选候选和命中文字；候选经原文核对后才加入分析。当前为本机文字检索，没有向量或语义召回保证。零候选、同词但不适用、来源不可用均保留；不宣称找全历史。

## 评价与决策

分别判断四件事：答案是否准确而有帮助；是否找回未手选资料；是否减少界面搬运；后续记录是否保留同一发现与版本。引用匹配是正确性底线，不能单独当作有用性分数。未参与结果生成的评审要核对原文支持关系，至少评价10条真实候选；不足时如实记录，不固定每轮条数或制造资料凑数。模型独立评审和用户主观评价分别标注。

6／10 是小样本试点目标，不是成功率保证。没有达到目标，或对照只证明少搬运，就缩小当前价值主张为“明确范围中的便捷分析与可追溯收藏／接续”，不借增加视角、菜单和定时器宣称已经形成独特分析能力。

## 本轮交付范围

先完成当前原型与桌面可靠性、单次历史候选检索和上述真实对照。P1的增量收集、跨事项推荐抑制及更长期运行，P2的周期回顾，以及跨 Work 自动合并继续保留为后续候选。它们需要单独定义授权范围、期限、预算、退出行为、重复和纠正效果；本轮不开启后台扫描或通知，也不为关闭本期而标成已实现。

原始资料、账户信息、完整运行轨迹和日常库截图只保留本机；GitHub 仅存去除私人内容的方案、汇总与验证结论。

评审由未参与八份结果生成的另一对话独立进行，逐条读取完整原文与第一次输出，并独立重数。它知道路径标签，使用同一家族模型，属于**非盲模型独立评价，非真人采用率**。两路径各有4条主要是有支持的共同原则或提醒重述，没有计为明确帮助；未把候选数量、引用匹配或自动保存当作有用性。

“有帮助”采用保守口径：能识别具体任务联系、会改变取舍的条件、有用的证据区别，或针对性核对旧判断，才计入；一般共同原则、纯清单重述保守不计，但不因此判为错误。具体场景和限制能够帮助所问的后续回顾时，带明确归属的提醒也可有用；不要求观点新颖，不把未知的真实采用记为成功或失败。比较完整回答，不拆分复合候选凑数；同轮按核心判断及决定背景识别重复，共用来源或限制重叠本身不算重复，跨情景重现和两路径拆合也不计作新增独立成功。

八轮均完成，直接16条与Skill17条分别有88与111处结构化引文，199处均逐字匹配冻结原文，所选正文读取并集完整。两路径均实际加载同版 `hub-research`，共同分析指令、模型、资料范围和材料上限一致；创建事项的 `successCriteria` 措辞不同，共同质量要求相同，未逐字证明所有适配器系统载荷相同。

所有调用的 `usageComplete` 都为 false，缓存／未缓存分项未知。已报告的输入、输出和总token仅作为不完整运行回执保留，不能据此计算费用或宣称成本优势。上表从开始运行到正式返回的秒数不含真人找材料和组织上下文时间。

独立评审认为两条完整答复总体相当：观点的拆分和合并造成卡片数不同，主要内容高度重合。这八轮只支持有依据的分析和两路径回答总体相当；均未进行保存与持久接续，不能据此证明收藏、接续或操作收益。**便捷分析、结果收藏与判断接续**是当前产品定位。八轮之外的日常窗口流程验收见下节，其保存或接续结果不归入这八轮质量评分。没有证据证明模型比合适的Skill更聪明；用户主观满意、真实采用和长期价值仍未知。

### 评价指出的呈现与使用边界

- D两路径都对一处病句的几何含义作了偏确定的整理；保留原句歧义，不能拿本次分析作为通用工程标准或设计放行依据。用户保留前仍须核对直接依据、条件和分析方法；全部候选都要求明确确认。
- D直接答复有重复的显示引用编号，结构化引文未错配。不修改原始回答或把显示瑕疵藏起来；是否统一引用呈现应沿共享助手引用入口处理，不能为消除编号重复而删掉代码或真实引用。
- 冻结B只检验把已保存判断文字带入新问题后的回答，不能把它当作同一已保存发现的持久接续证明。该证明需使用发现身份、原事项和版本历史的真实流程。
- 查找快照证明允许范围中的本地文字检索可找回未手选候选；其单独返回并不证明候选已加入实际分析，也不证明找到的材料有用。实际界面流程必须另行核验。
- 八次模型答复均非空；无答案、取消恢复、访问失效与长期重复控制不能从这八次输出外推。既有有效回归证据可以复用，新入口受影响的分支需定向核验。


## 日常窗口的流程与操作复核（2026-11-15）

这一节另行检验产品流程，没有重跑或改评前述八轮。使用正常日常资料库、原模型与真实笔记；没有建立隔离资料库、注入模拟记录或修改源笔记。

### 两个实际情景

- **A，当前工作找旧资料**：选择一份工程整理记录，明确允许本次查找的历史库。默认自动线索过宽，保留失败观察；手动收窄为 PARA 后，候选仍含英文代码的同词误报。实际读完一份未手选的旧组织提示词，返回保留候选，明确加入，再用两份真实正文分析。自然产生3条候选，核对后原地保留1条具体的工作区目录建议。没有把提示词当作已经执行的结果。此次先停止再恢复同一事项，最终正常交付；停止尝试和恢复后的完成分别保留。
- **B，原判断的持久接续**：回到11月14日已保存的原发现和原事项，沿用三份真实材料，明确重新核对。实际模型说明三类组织规则仍各有原文支持，组合仍是推导、实际采用及效果未知。原“维持”提交因旧依赖版本已变化而被拒绝；正常核对确认未提交，再结束该未提交请求，明确采用本轮带当前依据的修订。原发现身份与原事项不变，版本2升至3，前两版保留。已在最终代码的日常窗口逐一读取版本1、2和3，旧版本不会在切回窗口时跳回最新版。不能把本轮写成“维持成功”。

### 操作对照的实际终点

| 情景／终点 | 洞察直接路径 | 助手＋Skill常规路径 | 能说明什么 |
| --- | --- | --- | --- |
| A：同一问题、两份真实资料与相同方法准备齐 | 在发现流程选择当前记录、查历史候选、读原文并加入；方法自动采用 | 实际新建未发送草稿，输入同问题，核心材料中逐一查找并勾选两份笔记，完成材料和范围选择，再查看并加入同版资料核对Skill | 直接入口少了资料范围与Skill的菜单准备；历史检索仍有筛选负担，不能宣称找得更全。基线直接使用已知完整标题，未故意削弱它 |
| B：同一已生成成果准备好保存到同一发现 | 从结果与新旧对照已展开开始，1次勾选即可启用明确的维持／修订动作 | 实际打开旧发现的成果更新入口；原事项与最新成果自动选中，打开入口1＋选候选1＋勾共同背景3＋确认方法1＝6次界面操作后保存按钮启用 | 直接路径减少成果搬运与重复选择。基线也保留原事项、材料、结构化成果和保存能力，不需要重抄旧判断 |

A的基线止于**准备发送**，B止于**准备保存**，没有为凑对照再发一次模型请求或重复写入同一修订；直接路径的真实分析与保存另有完成回执。这里只比较已实际操作的准备和结果处理，不声称两条完整运行的真人用时差。B两条路径的起点不同：直接路径从结果已展开开始，常规路径包含打开更新入口；只将它作为结果处理负担的分项记录，不称为完整配对效率分数。表中次数不含滚动、原文阅读、自动化定位重试或首次认识界面的成本；不将工具按键、程序等待秒数换算成人的效率。基线准备草稿已清理，未改变原文或用户其他草稿。

### 验收结论及没有达到的强目标

有帮助的小样本目标由前述非盲独立模型评价达到，回答质量总体相当；实际找回并加入未手选资料、保存与同一发现接续均有独立于八轮评分的实窗证明。没有证据证明语义召回、找全历史、真人采用率、费用优势或长期主动价值。

“首次配置后两次操作内开始”和“两个真实情景均减少找资料／组织上下文”这两个更强门槛没有获得完整证明：本轮明确测到的是A的准备路径和B的结果处理，后者不能冒充找资料收益。因此执行开发前已有的收缩规则：**交付明确范围中的便捷分析、结果收藏和可追溯接续；不据此扩建独立分析面板或启动P1／P2自动化。** 这是P0试点得出的受限产品决定，不把原始高目标改写成已达到。

长期增量、跨事项纠正与重复控制、周期回顾及更长期运行继续作为候选，需有具体场景、范围／期限／预算、退出行为和连续使用评价后另行开工。当前发现页面不会自动扫描整库，公开案例也不填充个人发现。
