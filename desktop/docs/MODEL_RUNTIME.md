# Hub 模型运行层

Hub 统一管理模型请求。设置中的“模型与运行”可选择 DeepSeek 直接 API，或本机已有的 Codex CLI。Codex 的登录、账号和安装仍由外部 Codex 管理。

## 运行与设置

- `src-tauri/src/model_runtime.rs` 是唯一的设置、FIFO 排队、并发、预算控制、取消和安全回执所有者。调查、标签定义、补标发现、逐篇检查、标签关系、归档、闪卡与任务转换都使用同一个 Operation。
- 每次提交固定提供方、模型、推理与速度；之后修改设置不会改写已排队的请求。当前活动数据根共用 1–4 个并发名额，后台复查继续让位于手工操作。
- 一项操作内的模型调用串行进行，不能绕过全局并发上限；结束后的操作不能继续发起调用。领域预算在同一 Control 中覆盖准入、模型发现、生成及来源核对。共享输出门检查 JSON 类型和 schema，领域所有者继续核验引用及业务规则。
- 新设置保存在 `model-runtime-v1.json`（schemaVersion 2）。首次兼容读取旧 `codex-suite-v1.json`，保存后使用新文件；旧调查和回执保留。整库备份包含模型设置，不包含系统凭据。

## DeepSeek

密钥可输入或从 UTF-8 文本文件导入，只保存在系统凭据库。前端仅在输入期间持有密码字段，不回读密钥；日志、模型回执和备份不包含密钥。密钥文件仍由用户自己保管。

适配器直接调用官方 `https://api.deepseek.com/models` 和 `/chat/completions`，不经过 Codex。模型目录决定模型、推理档位和图像能力。当前默认选项为 `deepseek-flash`；目录由 API 实际发现，不将 Codex Fast 参数发给 DeepSeek。

对话生成使用 SSE 流式请求。收到推理阶段信号时显示等待公开摘要；只将公开的 `rationale` 和 `report.markdown` / `report.summary` 增量显示，不持久化内部推理原文。预览是未核验候选，不能据此派发工具或宣布交付；回答预览达到 6000 字符显示上限时明确提示仍在接收，最终结果继续按完整 JSON 校验。收到 `data: [DONE]` 后即结束流读取，不等待连接关闭；缺失结束原因、非 stop 结束、断流和 Schema 不合格仍拒绝交付。

使用 JSON Output，Hub 验证结构及业务事实。模型只能提出结构化工具请求或候选结果，来源读取、权限检查和写入由 Hub 执行。传输不自动切换端点、提供方或重复调用。调查对明确的单次生成超时最多恢复一次，计入普通调用预算；JSON/结构或交付候选被拒后，另有最多一次结果纠错，继续使用同一授权、来源、记忆版本、总时限、请求字节和工具预算。只有正式交付通过并发布，运行层才确认这类恢复。主动取消、鉴权、余额、限流、截断、能力不支持、服务失败和连接中断分别反馈；这些错误不因此获得隐式重试资格，连接中断不能当作成功。

调查的默认快速档为 2 分钟、3 次普通调用和最多 1 次结果纠错；深入档为 4 分钟、6 次普通调用和最多 1 次结果纠错。实际调用次数包含纠错，`outputRepairs` 单独记录。最后一次交付失败同样保留拒绝记录；非法候选不派发工具或发布结果。

用户用《…》点名资料时，Hub 在当前授权内做最多 4 个标题的定位：在本轮检索候选中仅一个准确同名时预读，有已知重名时保留候选。未命中不当作不存在的证明。普通搜索每批最多实际读取一个首位未读候选，继续核对版本、权限和读取预算；摘要仍没有引文资格。初始页面和受控读取均最多 6000 字符，并受 15000 字符的本轮正文预算约束。

每轮实际读段生成 `quoteCatalog`。模型的引用只选择 `quoteId`，由 Hub 从当前读段填回原句；持久报告和界面继续使用 `evidenceId + quote`。未知/未读编号及模型自带的引文字词拒绝；实际原文、来源版本和发布资格仍再次核验。引用展开后的完整结果同样受共用的 40000 字节限制。

模型输入有 512 KiB 共用上限，业务功能可以采用更小预算。DeepSeek 单次输出上限 8192 tokens，完整 JSON 结果最多 40000 字节，非流式目录响应最多 2 MiB；SSE 传输最多 16 MiB，解码后的正文与推理增量合计最多 2 MiB（不保留推理原文），避免重复分片元数据提前耗尽正文额度；只接收完整结束的回答。图像仅在模型目录声明支持时传递，最多 4 张、单张 5 MiB、合计 10 MiB。

## 记忆与正式消费者

Basic Memory 继续负责本地 Markdown 正文、索引和相关候选；Hub 数据库负责确认、项目、当前版本、替代、停用、遗忘和重复请求。模型适配器不拥有第二份记忆，也不能扩大来源授权。

调查先按已选项目和权限组装同一份有界记忆上下文，再交给当前适配器。提供方切换不改变记忆 ID 或版本；生成及发布前继续复核记忆、来源和授权。检索候选仍需模型判断相关性，不能因为被召回就算作适用依据。

标签建议保留兼容的 `agent=codex` 外部来源；Hub 自己生成的记录使用 `agent=hub` 和实际 `provider`。来源核验、定义版本、人工审核及幂等提交要求保持。闪卡仍先准备草稿，引用必须逐字存在于实际材料中，接受后才能进入后续流程。

归档与任务转换使用 Hub 内置、版本化的技能文件 `assets/model-skills/v1`，在编译时包含必要正文与引用闭包，不读取运行机器的 Codex 技能目录。归档定位、实际锚点、附件与写后核验继续由原业务所有者负责。
