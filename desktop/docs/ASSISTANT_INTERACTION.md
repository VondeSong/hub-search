## 第一批行为

- 搜索预览中的助手作为正文旁的独立区域，宽度可在回答选项中调整。预览可用宽度小于 640px 时，提供正文／对话切换，保留原正文节点与滚动位置。
- 首次提问与后续追问共用输入框；发送追问后直接开始下一轮。运行期间可以输入下一条草稿，并停止本轮后发送。
- 打开对话后固定当前笔记、任务、附件片段或阅读条目。浏览另一个对象不会重建对话；明确点击“用当前材料新建对话”才切换锚点。
- 历史记录按用户消息与助手回答顺序显示；重开只读取记录，不自动调用模型。来源变化后，隐藏无法重新核验的历史回答正文。
- 普通追问保存为 `userMessage`，不自动成为确认事实或长期记忆。回答选项中明确勾选的决定继续走原 `userDecision` 入口。
- “查看引用原文”根据工作、运行及来源编号重新读取对应来源，并高亮引文。原文窗口最多展示 6000 个 Unicode 字符，清楚标识范围与节选；这不是跨库全文浏览器。
- 业务动作、共享记忆、条件复查保留原有所有者、审核、权限和回执。第一批不把自然语言请求直接路由成业务写入。

## 持久记录和模型上下文

沿用正式 SQLite 的 `agent_works`、`agent_runs`、`agent_records`，没有平行聊天数据库或浏览器存储作为生产记录。旧事项无需批量迁移，初始问题由原目标恢复。

- `message` 使用客户端消息身份处理重复提交，并检查可选的事项版本；运行中拒绝追加。新要求增加事项版本，清空当前结论并暂停自动复查，历史交付仍保留。
- 每个对话最多追加 32 条普通追问；超过时要求新建对话。界面读取最近 64 条消息／交付记录及初始问题，提示是否有更早记录。
- 模型取最近最多 16000 字节的对话上下文，并单独给出本轮要求。历史回答的引用身份不会混入本轮 `quoteCatalog`；每次请求前重新检查历史回复的来源依赖。原始资料和本轮证据仍受既有预算与版本核验约束。
- `source` 只接受本事项正式交付中已保存的来源；检查运行归属、授权版本、真实引文和来源版本，不接受前端提供的任意资料定位器。

## 新规划第一阶段：同轮 Agent 工作闭环（0.16.302）

此前的问题来自执行结构：模型只做搜索与读取，在最终回答里提出一个业务请求，再由另一段流程生成草稿。它无法在同一轮观察草稿结果、纠正制作错误或完成多种依赖动作。固定报告栏目、答复后隐藏进展和输入区过多说明进一步强化了表单感。本阶段直接替换这条生产执行链，旧待领取草稿仅保留兼容读取与手动领取。

- `respond` 从一次模型准入开始，在同一运行身份、授权版本和总时限内反复执行“选择下一步 → 调用工具 → 观察实际结果 → 继续或交付”。工具包括原有搜索/读取、取得制作上下文、提交完整候选、重新检查真实草稿和调用原归档方案服务。简单问题可直接交付；不强制生成计划。
- 一轮可准备笔记修改与闪卡等不同成果。制作候选直接通过原领域校验器，成功后返回实际草稿；失败作为观察返回给模型。模型可以纠正后再提交，也可在同一轮基于旧稿继续调整。旧版本标记为已有更新草稿，旧确认不能提交新版本。
- 草稿入库、来源重新核验、上下文身份与前驱替换在正式事务中完成。运行中允许显示实际预览，但确认凭证只在该轮结束后提供。人工确认、原文件版本/备份/回读、归档结果未知时保留身份等原业务规则继续生效。
- 对话的收件箱导入授权只表示允许操作，不代替当前用户意图。0.16.304 起，助手需明确调用 `importFlashcards(actionId)` 选择具体的本轮闪卡草稿；仅预览或不要导入时保留草稿，交付正文不会触发导入。宿主核对当前授权快照、来源、版本与实际回执；重复请求返回原回执，未进入正式复习。独立的显式生成草稿旧入口仍按它自己的确认合同处理。
- 工作过程由正式 SQLite 中的公开进展说明、实际工具调用、结果和业务回执按顺序投影。每一步显示具体成果或失败，时钟来自实际开始/完成时间；提交记录后通过桌面事件通知刷新，轮询仅作后备。完成后可展开历史过程；撤权或原文失效会隐藏相关过程正文。
- 最终答复支持自然段、列表和表格，不再强制“查明的情况”等栏目。资料事实通过当前证据编号核验后成为行内引用，点击仍从准确运行重新读取原文。公开进展说明用于解释计划、发现与方法调整，不展示提供方私密推理，也不伪造终端或进度。
- 输入区保留材料、统一输入、模型/确认方式、回答选项及发送/停止。范围、用量、来源核对、业务备用表单和共享记忆收进“对话详情”。320px 区域可完整查看模型菜单，Esc 先收起菜单，再关闭助手。

标准模式最多 8 次分析调用、24 次工具步骤、8 分钟；深入核对最多 16 次、48 步、15 分钟。纠错仍受同一总时限约束。归档继续使用原服务的两次调用/128 KiB 上限，进入前预留预算和交付余量；预留上限与实际用量分开记录。所有调用使用同一模型选择与取消控制，不因内部动作另开一份无限预算。

本阶段保留当前单一锚点及领域边界：当前页面最多 12000 字符、每份 1–5 张问答卡；Windows 单篇 UTF-8 Obsidian 修改；实际连接目标上的阅读归档方案。已有授权范围内仍能搜索其他资料，但没有多选材料入口、完整库统计承诺、Python 计算环境或运行中插入新要求。提供方回复仍以完整结构化结果进入工具循环，过程展示不等于逐字流式输出。

验收证据归 `artifacts/agent-workbench-20261021/`；生产链、真实模型、桌面接口、组件回放与完整包分别记录，不互相替代。最终范围与结果以同目录 `verification.json`、`report.md` 为准。

## 原生 Agent 会话（0.16.303 已交付）

最新复查：0.16.304 已修正三处边界——导入改成模型显式选择的独立工具；完成事件的公开思考摘要按正式 `summary` 字段读取；宿主自动载入材料单独标明，不计入模型工具步骤。真实 Codex 对简单答复、文末补读、只预览、明确导入分别选择 0、1、4、5 个工具步骤，同一导入权限下只有明确导入场景写入一份隔离收件箱草稿。219 项相关普通回归与 2 项真实提供方测试通过，后者还覆盖连续线程、中途追加、取消和恢复。当前交付包与最终验收以 `artifacts/agent-autonomy-audit-20261022/verification.json` 和 `report.md` 为准；下文 0.16.303 数字保留其历史适用范围。

用户要求模型承担理解、推理和自主决策，Hub 提供工作环境并实时呈现执行过程。0.16.303 已将 Codex 交互从临时 `exec` 完整 JSON 调用迁移到 App Server 的持续 thread/turn。由一个原生运行层主导模型与工具往返，Hub 不再外套同任务的结构化决策循环。其它 provider 的现有路径继续按其实际能力声明，不能因为界面相同就宣称具有原生流式摘要和运行中追加能力。

责任边界：模型解释目标、选择下一步、处理工具反馈并生成正文；Codex 运行层维护会话与原生事件；Hub 独立执行授权范围、版本校验、工具预算、领域草稿、提交回执与最终发布。工具参数和交付引用保留结构化校验，公开过程消息不参与授权或推进业务状态。

Hub 工具采用本机生成协议验证的动态工具接口。该接口仍属实验能力，当前本机协议来自 Codex CLI 0.163.0-alpha.11；不支持的版本应明确失败，不能静默切回旧流水线并声称已获得相同能力。过程只接收正式 agentMessage 与 reasoning summary 通道，不读取 raw reasoning、stderr 或认证事件作为用户正文。

运行中追加保留真实用户身份、clientMessageId 和准确 run/turn 绑定；运行层正式确认后才标记接收。未接收追加要求、停止、撤权或来源变化时，旧结果不能发布。流式项目按稳定身份更新 SQLite，桌面通知触发回读，关闭或重开界面不新启动模型。会话复用必须再次验证此前实际发送的来源版本、授权、模型选择、工具合同和共享记忆；变化后由当前真实上下文建立新会话。

交付范围：持续模型会话、实时公开进度、支持时的思考摘要、Hub 工具闭环、同轮复合草稿与修正、连续追问、运行中追加、停止与恢复，以及完整免安装包。53 项前端、114 项 Agent 原生和 47 项模型运行层回归通过；真实 Codex 单独完成复合草稿、同线程追问、追加、取消与恢复四阶段验证，遇到实际工具错误后调整方法。完整 ZIP 的 4 项内容与哈希核验、解压后程序隔离冷启动通过。正常与 320 像素侧栏使用正式组件回放真实记录做视觉检查，未将其当作完整原生桌面鼠标端到端测试。真实提供方本轮没有返回独立思考摘要，摘要通道由组件测试验证。证据见 `artifacts/agent-native-20261022/verification.json` 和 `report.md`，完整包见 `artifacts/releases/0.16.303-native-agent-delivery-20261022/`。

资料统计和计算环境仍需独立执行能力，不能由新增过程面板自动取得；当前不开放任意 Shell 或 Python，不宣称已具备 Notion 的所有场景能力。所有验证只在隔离资料中进行，个人来源与远端对象不参与验收写入。11 项 Agent 与 3 项模型运行层的单独启用测试未在普通回归组运行；真实模型集成测试另行启用并通过，不将本轮结果扩展为整个仓库测试通过。

原生会话的强制边界是标准/深入模式下 24/48 次 Hub 工具步骤、36k/60k 来源字符、1/3 MiB 新增宿主上下文和 8/15 分钟总时限；工具模式、原文与草稿仍沿用领域约束。原生模型内部请求由 Codex 驱动，不把旧循环的 8/16 次调用数冒充原生调用次数。用量分别记录 Agent 会话、已知嵌套调用及提供方实际 token 统计；恢复时从同一线程的累计统计扣除此前基线，取消但未取得新统计时保留原基线。未取得计量只表示未知。服务不一定在每轮返回思考摘要，界面不补造摘要；公开工作说明和工具事件仍按实际事件显示。

每个原生会话使用独立配置与空工作目录，不加载用户的全局 MCP、插件、技能或钩子。临时登录输入在退出时清除，刷新令牌继续由原 Codex 登录所有者管理；Hub 不进行独立登录或改变全局设置。Windows 为准确进程登记关闭保护，结束或停止时收口其子进程与管道，不使用进程名批量终止。动态工具所需的 code-mode host 传输保持启用，代码执行模式、Shell、浏览器和外部连接能力保持关闭；每项真实业务仍由 Hub 受控工具执行。

## Hub 技能运行层（0.16.305）

沿用上述原生 Codex Agent 循环。Hub 提供一份模型无关的技能目录，初始请求只携带名称、简介、来源、版本、自动使用策略和依赖状态。模型根据当前目标决定是否调用 `loadSkill(name)`，再按需调用 `readSkillReference(name,path)`；普通问题可直接交付，不强制加载技能，不按问题关键词在宿主路由成固定流程。结构化提供方路径消费相同目录、工具和真实结果，原生流式与运行中追加能力仍按提供方分别声明。

技能是从属的任务方法。模型解释目标、选择方法并根据反馈调整；Hub 决定当前工具、资料范围、版本、预算、草稿和保存权限。经技能加载工具返回的 `skillInstructions` / `skillReference` 可提供方法，其它来源和普通工具结果继续作为材料。技能不成为事实引用，不增加脚本、Shell、网络或 MCP 执行能力，也不能替代具体业务授权和保存回执。

内置资料分析、闪卡质量、笔记整理、阅读归档四份 `SKILL.md`。用户可在输入区“技能”查看真实目录，点选后将 `$技能名称` 加入当前消息；默认仍由模型按需选择。点击“打开用户技能文件夹”才创建并打开当前 Hub 数据根中的 `agent-skills`。添加内容无需修改全局 Codex 设置：

```text
<Hub 数据根>/agent-skills/study-audit/
  SKILL.md
  references/check.md         可选文字参考
  agents/openai.yaml         可选显示、调用策略与依赖
```

`SKILL.md` 使用 YAML 元信息，必填 `name`、`description`，后接方法正文。name 与目录一致，使用 1–64 位小写字母、数字、单连字符。description 最多 1024 字符；正文文件最多 64 KiB；最多发现 32 份用户技能。例：

```markdown
---
name: study-audit
description: 用户要求核对个人学习计划与复习方法时使用。
---
理解当前学习目标，需要详细规则时读取 references/check.md。
只使用当前材料与工具，以实际返回结果核对。
```

`agents/openai.yaml` 支持 `interface.display_name`、`policy.allow_implicit_invocation`，false 时只能由当前用户用 `$name` 明确指定。声明 `dependencies.tools` 时，当前仅接受 `type: hub` 与已存在的 `hub_工具名`；其它依赖显示为未接入且拒绝加载，不自动安装或借用全局连接器。也可在 SKILL 元信息 `metadata.hub.required-tools` 声明 Hub 工具清单。工具存在不等于当前资料或业务动作已经获准，仍以本轮 capabilities 和领域检查为准。

参考资料只能在已经加载技能的 `references/` 内，支持有界 UTF-8 md/txt/json/yaml/yml/csv，每份最多 32 KiB，同一原生会话最多保留 32 份参考依赖。拒绝目录穿越、绝对路径、链接、目录联接、脚本和二进制资源。每次正式使用记录实际技能版本；界面显示读取了哪份技能或参考资料，保留版本和来源。目录可用性、模型声明使用和实际加载是不同事实，只有真实工具结果形成“已读取”。

下轮重新发现技能；SKILL.md、配置或目录变化使原生会话指纹失效。已经提供给原生线程的参考资料版本也作为依赖回读，变化后建立新线程。运行中技能或已读参考变化时停止发布旧结果，已准备成果保留，可继续新一轮。更换模型仍使用同一 Hub 技能目录；模型选择变化沿原会话指纹建立新线程，业务对话和草稿继续归 Hub 管理。

本轮证据归 `artifacts/agent-skills-20261022/`；验收结果以最终 report / verification 为准。用户全局 Codex Skills 不自动继承，任意脚本执行、技能市场、依赖安装和其它模型真实服务质量不属于本轮交付。

2026-10-22 验收：235 项定向普通检查与 2 项真实 Codex 测试通过；后者涵盖六个技能场景和四个业务场景。实际制卡流程由模型自主读取闪卡技能，只预览未导入，明确导入才写入一份隔离收件箱。320/380 像素界面回放与几何检查通过；已修正窄菜单裁切和参考资料版本显示。完整便携包四项内容校验、源码冻结复核及独立数据目录冷启动通过。界面证据是正式组件回放真实记录，未声明完整原生鼠标端到端或其它提供方真实服务质量。预览缓存删除被自动审批策略拦截，缓存、解压验证目录和启动诊断均明确保留；本轮预览页面、服务和启动进程已退出。最终结果见同目录 `verification.json`、`report.md`；完整包在 `artifacts/releases/0.16.305-agent-skills-final-20261022/`。


## 共享能力与知识库工作规则（0.16.306）

内置助手与外部 MCP 通过 `hub_capabilities` 消费同一份工具定义和业务执行边界。标签、媒体、质量与建议的确定性服务继续由原领域模块拥有；MCP 负责传输，Agent 运行时负责模型与工具的往返。运行时不新增任务分类器、关键词路由或固定执行步骤。助手搜索不再自动读取最高排名结果，由模型选择是否读、读哪个结果以及是否调整查询。

共享目录保留每项工具的输入格式、说明、只读及破坏性标记；内置助手另外提供当前授权下的 `available` 与 `unavailableReason`。笔记授权只允许对应笔记或页面；库级分析必须有库范围授权，支持 `libraryIds` 的工具由宿主注入授权范围，模型不能扩大。读取全局状态需要覆盖全部启用资料库。直接接受、应用、撤销、附件导入及绕过草稿的卡片提交，不会因为工具可发现而获得对话写入授权。现有对话草稿、具体确认与回执入口继续承担这些变更。

对话专有的制作上下文、预览和归档工具需要真实 Work/Run 及桌面连接；它们属于当前运行时的上下文能力，并不伪装成无条件可用的外部 MCP 操作。共享 Skill 目录按该入口实际可用工具核对依赖。工具的业务方法可按需加载 `hub-tool-guide`，不在 MCP 初始化时塞入整份方法说明。

知识库规则使用独立 `libraryInstructions` 通道，带来源、作用范围和内容版本。优先级为当前用户要求与宿主权限高于规则；规则在相应范围内按以下顺序应用：Hub 数据根的 AGENTS.md、Hub 管理的资料库规则、Obsidian 库根规则、笔记父目录逐层规则。每层优先使用非空 AGENTS.override.md。不同资料库的规则不能相互覆盖，普通笔记、检索摘要和历史回答不能成为这个通道的指令。

- Hub 通用规则：`<Hub 数据根>/AGENTS.md`。
- 各来源独立规则：`<Hub 数据根>/agent-rules/<libraryId 的 SHA-256>/AGENTS.md`；`hub_get_library_rules` 返回实际 managedDirectory。Craft 等无本地根的资料库可使用这个位置。
- Obsidian：从正式已连接库的 location 取得根，仅沿目标笔记相对目录加载到其父目录；不扫描旁支、父库或用户全局配置。
- 每份规则最多 32 KiB UTF-8，单个范围合计最多 64 KiB，拒绝越界路径、符号链接、目录联接和二进制规则。
- 内置助手在首轮模型调用前加载当前授权范围和锚点的规则；后续读取新的笔记时补充对应目录规则。MCP 通过共享的 `hub_get_library_rules` 获取规则，读取笔记也返回所属规则。
- 规则与 Skill 分别记录读取版本。规则新增、改变或移除使旧上下文失效；内置 Codex 恢复前核对实际依赖，变化后重建线程。运行期间变化阻止旧交付发布。

规则提供工作约定，不授予来源、脚本、连接器或保存权限，也不充当正文事实证据。能力是否相同按同一业务合同判断；具体可用性取决于当前资料授权、连接、运行时上下文和实际确认能力。

验证证据在本轮独立报告中记录；未完成的检查不由本节实现说明背书。

## 多材料、可核验统计与菜单关闭（0.16.307）

对话设置、技能和回答选项可显式关闭，也支持 Esc、外部点击和焦点移出收起；设置仅在应用成功后关闭，失败保留错误。关闭状态的内容显式隐藏，避免浮层样式覆盖原生 details 的关闭呈现。

新对话的“材料”入口按需读取实际本地文档清单，可跨库选择最多 31 份附加文档，加上当前笔记共 32 份。只提交明确选中的文档身份，不因选中一篇而授权整库。授权在发送时固定；更换范围需新建对话。原有当前库整库授权另行保留。当前来源可以是 Craft 精确页面，附加入口枚举的是文档，明确选中父文档时才授权该文档；不存在的页面不降级为父文档读取。笔记修改与制卡草稿仍以当前锚点为目标，未实现混合来源制卡。

内置助手和 MCP 共用新增两项能力：`hub_list_note_sources` 按稳定快照分页枚举授权笔记；`hub_analyze_notes` 在同一读取快照中实际扫描正文，计算字符数、字面关键词出现次数与提及单位数。模型自行决定是否调用、选择哪些参数、是否补读及如何纠错。Hub 没有新增固定日记流程或关键词路由。自定义和内置技能均可按需调用这些能力，新增 `hub-statistics` 提供统计口径。

文档单位为授权文档或精确页面；按日单位只识别独占一行的有效日期标题，可按月、年或库分组，每库内同日期合并。重复日期的文本次数仍累加，提及天数按日去重；不跨库自动消除同日记录。返回重复日期数、无法归入日期的字符、未读取来源及分组截断。关键词统计说明文本提及，不代表事件发生率。正文无法读取时完整性标为 false；扫描限额失败不返回抽样总数。

上限为单个范围 5000 份文档、单次扫描 32 MiB 正文和 10 秒、12 个关键词，最多返回 120 个分组。清单筛选为标题/路径字面包含，非全文搜索。只对 Hub 已有本地缓存负责，不承诺远端资料完整。统计与清单记录来源快照，分页变化要求重新枚举；发布、当前答案、历史及会话重用都核对依赖，增加文档造成分母变化也会使旧结论失效。

用户技能仍由 Hub 数据根的 `agent-skills/<name>/SKILL.md` 管理，界面显示实际目录。不会自动与 Codex 用户技能合并，也不写进 Obsidian；外部 Codex 可通过 Hub MCP 读取同一份 Hub 技能。Obsidian AGENTS.md 继续承担库/目录规则。通用 Python、Shell、技能脚本执行、图表、长任务和其它提供方真实服务验收没有因本轮统计工具而自动完成。
