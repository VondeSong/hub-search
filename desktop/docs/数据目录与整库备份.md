# 数据目录与整库备份

Windows 桌面端入口：**设置 → 数据管理**。首页显示 Hub 数据总量和当前文件夹。展开 **管理空间** 查看分类占用和维护操作；展开 **备份与迁移** 备份、换电脑或更改位置；自动同步和索引工具位于 **索引与高级设置**。

**打开数据文件夹**用于在系统文件管理器中查看当前位置。Craft、滴答的正文与附件原件日常就保存在这里，新增内容也使用同一目录。换机完全退出 Hub 后直接复制整个文件夹，无需额外的复制前检查。账号授权仍可按需加密携带。

文件位置分开显示：已在数据文件夹内的 Craft 原件随整个文件夹复制；独立管理的 Obsidian 原库由你自行移动、重新加载。界面显示普通 Windows 路径，内部长路径前缀不影响数据实际存储位置。

## 像微信一样整体搬家

Hub 使用一个软件数据文件夹。**Hub 数据**下方显示当前文件夹，点 **打开数据文件夹** 可查看。更换位置时，展开 **备份与迁移 → 更改数据位置…**。重启迁移期间，先将当前软件数据复制到新目录，再在新磁盘收拢 Hub 管理的原件与附件，校验后使用新位置；原目录保留。旧盘不需要先腾出容纳外部原件的额外空间。

换电脑时，完全退出 Hub，复制整个软件数据文件夹；新电脑打开 Hub，在 **备份与迁移** 选择 **打开已有数据目录…**。需要携带账号时，可在 **复制数据文件夹到新电脑** 中按需选择账号、设置迁移密码并点击 **更新加密授权副本**；这不是普通数据迁移的必需步骤。新电脑在该目录打开后输入迁移密码恢复授权。

**Obsidian 原始库由用户自己移动后重新加载，不随此流程搬运。** Craft 导出的 `空间 - Craft` 文件夹是独立的 Markdown 阅读库，`空间 - Craft - 备份` 是 Craft 原始恢复点；它们都不能单独代替包含数据库的完整 Hub 软件数据目录。

## 先选对操作

| 需求 | 入口 | 结果 |
| --- | --- | --- |
| 把本机正在使用的数据移到另一块磁盘 | 备份与迁移 → 更改数据位置… → 自定义文件夹 → 更改并迁移 | 重启期间复制到空目录，在新磁盘整理并校验后切换；原目录保留 |
| 让数据跟着免安装程序放在一起 | 数据存储位置 → 便携模式（程序旁边）→ 更改并迁移 | 数据位于程序旁的 `Craft Search Data` |
| 使用从旧电脑复制来的完整数据目录 | 备份与迁移 → 打开已有数据目录… | 先检查内容摘要，再确认打开并重启；不向其中覆盖当前数据 |
| 保存一个便于拷走的文件 | 备份与迁移 → 备份到文件… | 生成并校验 `.hubbackup` 文件 |
| 从备份文件恢复 | 备份与迁移 → 从备份恢复… | 检查后恢复到新的空目录，可选择恢复后重启使用 |

“更改并迁移”要求目标为空。已经复制好的 Hub 数据目录应使用“打开已有数据目录…”。两者都保留原数据目录，不把两个资料集合并。

## 备份包含什么

默认备份包括本地数据库、已保存的正文和资料状态、个人收藏与视图等设置、已保存的草稿，以及 Hub 管理的本地附件。还包含 Codex 的模型、推理与并发偏好（不含凭据），以及闪卡备份目录中已完成的顶层 `.hubfc` 文件；未完成的 `.partial` 文件和嵌套目录不会打包。数据库采用一致快照；每个归档文件和整个备份都带内容校验。

Craft 原始恢复点保存在数据目录内；普通同步的正文进入数据库，下载的原件进入本地附件存储。滴答任务与稍后读正文也进入数据库，附件保存到同一数据目录。导出到 Obsidian 等位置只是额外副本，Hub 不依赖导出文件提供附件。旧版外部数据首次打开时自动收拢，验证成功后才更新引用；原文件保留。缺失原件仍会列出，不能把未下载内容当作完整离线资料。

Obsidian 原始库和用户独立管理的 Obsidian 阅读库保留位置清单，换机后自行移动并重新加载或定位。它们不属于软件搬家的缺项。缺失的 Hub 管理原件、附件仍会列在结果中；“备份文件通过校验”只说明文件完整，不代表云端所有内容都已下载。

X 书签和喜欢的原始笔记与附件只保存在所选 Obsidian 库，Hub 保留阅读索引、正文快照、阅读状态和附件引用，不再额外持有视频原件。导出、附件云副本下载、整库备份和目录收拢均遵守此边界；Obsidian 不可访问时提示修复保存库，不退回 Hub 保存。离线阅读需要该 Obsidian 库在本机可用，换机时它仍由用户自行移动并重新加载。

旧版已收拢的 X 附件可通过离线维护先修复引用、再清理重复副本。维护仅对已核对大小与完整内容校验的两份文件建立对应关系；提交附件路径并保留本地序号、正文与阅读状态后，才允许清理 Hub 副本。缺失、不同内容或仍被其他内容引用的文件保留，Obsidian 原件只读。维护同时保留数据库快照与逐文件回执。

以下内容需要区别处理：

- Craft、滴答清单等云端资料，备份只能保存 Hub 已取得的本地内容；未下载内容和云端历史不会因此自动补全。
- 在“复制数据文件夹到新电脑”勾选账号选项并更新副本后，Hub 保存的授权、服务密码、API 密钥及已保存的 X 网页登录连接会加密写入数据目录的 `account-transfer.hubauth`，随整个目录和整库备份携带。用户选择具体项目并自行保管迁移密码，密码不写入个人设置或备份。新电脑可检查后恢复，默认保留已有账号授权。
- 支持迁移的是 Hub 管理的连接凭据；完整 Windows/浏览器用户目录受系统绑定，不能保证复制后恢复任意网站会话。授权也可能被服务端撤销或过期。
- 搜索索引、日志、界面缓存和机器位置设置不打包；索引在打开数据后重建。自动备份计划在新电脑重新设置。
- 原来留在旧版浏览器存储中的个人设置，需要先在旧电脑打开新版 Hub 完成迁入。不要直接用旧版数据目录假定已包含这些设置。

`.hubbackup` 当前采用单文件归档，正文、附件和路径清单**不压缩、不整体加密**。其中可选的账号授权副本使用用户密码独立加密；请在自己控制的位置保管整个数据目录和备份。

## 直接复制到新电脑

1. 在旧电脑打开新版 Hub，旧版外部数据会自动收拢。确认需要的内容与附件已同步、下载完成，个人数据保存正常。账号授权仅在需要时选择项目、设置迁移密码并更新加密副本。
2. 在“Hub 数据”点 **打开数据文件夹**，记下当前目录。需要便携形式时先完成“便携模式”的迁移。
3. **完全退出 Hub**，并结束访问此数据目录的 Hub MCP 进程。关闭窗口可能只是隐藏到后台，应使用应用的退出入口。
4. 复制整个数据目录，不要只复制 `craft-search.sqlite3`。便携模式复制程序和完整 `Craft Search Data`，保留其中的隐藏标记文件。已收拢的 Craft 原件和加密授权副本在同一目录中；Obsidian 原始库由你单独移动后重新加载。
5. 在新电脑运行同版或支持此数据版本的新版 Hub。便携模式可识别程序旁的数据；其他位置使用 **打开已有数据目录…**，核对资料库、内容和个人设置数量，再点 **打开此目录并重启**。
6. 如果带入加密授权副本，在“本目录已包含加密授权副本”中输入密码，检查后恢复所需账号。也可重新连接账号。Obsidian 原始库按新位置重新加载。

不要让两台正在运行的 Hub 通过同步盘共用同一活动数据库。拷贝和备份文件可以放入同步盘，活动数据应由各电脑独立使用。

## 通过备份文件恢复

旧电脑点 **备份到文件…**，选择一个新的文件名，等待“本次备份结果”，检查缺项后复制 `.hubbackup` 到新电脑。

新电脑点 **从备份恢复…**，选择文件；检查时间、版本、文件数量及覆盖范围，然后点 **选择空文件夹…**。目标必须为空，现有非空目录不会被覆盖。

默认勾选“恢复后打开此目录并重启 Hub”。取消勾选后，恢复只生成独立目录，当前使用的数据不变；之后可切换打开。Craft 原件恢复在新目录中并更新路径；加密授权副本随目录恢复，输入迁移密码后可选恢复授权。Obsidian 原始库自行重新加载。

如果检查后文件发生变化，或检查结果已经过期，需要重新选择并检查。操作失败或取消时遵循界面给出的实际结果和保留路径，不把未完成的暂存目录当作可用备份。

## 缺失来源与重新登录

“备份与迁移 → 独立管理的库与外部文件”展示外部位置是否可用。Obsidian、阅读保存库和 Craft 原始备份支持 **重新定位**，请选择原来的同一个库或备份，系统会核对身份后更新引用。

Craft 请选择包含原始恢复点的备份目录，并保留原文件夹名称；同级 Obsidian 阅读库与第二份备份位置也需核对。无法直接重新定位的附件，在对应来源中重新连接或恢复文件。

账号授权可随数据目录加密迁移，也可在新电脑重新连接。恢复授权本身不发起联网请求、不启用自动同步。没有外网的公司电脑可以读取已经保存的正文和本地附件；未下载内容、外部网页和令牌刷新仍需要网络，搬家前应在有网络的电脑补齐需要的内容。

## 自动备份与空间占用

展开 **自动备份**，选择数据目录之外的独立文件夹，设置间隔和保留份数，然后点 **保存自动备份设置**。

- 默认关闭；默认间隔为 24 小时，保留最近 7 份。
- 间隔可设 1–720 小时，保留份数可设 1–100 份。
- 仅在 Hub 运行期间检查是否到期；自动包含 Hub 管理的 Craft 原件，Obsidian 原始库单独管理。数据目录中已有的加密授权副本会随同保存，搬家前可更新它以取得最新授权。
- 新备份成功且没有缺失或未包含的来源时，才按保留份数轮换属于同一数据集、同一保存位置且可核验的自动备份。有来源未打包时仍会保存新备份，但不会触发轮换。手动备份不参与轮换；关闭自动备份会保留已有文件。
- 最近成功时间和失败原因显示在本区。自动备份位置随电脑变化时，应重新选择并保存。

**管理空间**显示当前数据目录中的文件内容大小，区分正文和个人设置、附件、可重建索引、日志及其他文件。它不是磁盘实际分配空间；数据目录外的原始库不计入这里。

各分类旁的 **查看大文件** 按文件大小降序列出真实文件，支持大小门槛、类型和标题/文件名/路径搜索，每页 50 个文件。阅读附件按已登记路径匹配关联内容标题，文档附件按 Blob 引用匹配文档标题；没有匹配记录时显示文件名，不猜测来源。展开文件位置可复制完整路径，**定位文件** 在系统文件管理器中显示对应文件。此入口只查看与定位，不删除文件或更改下载、云同步策略，也不扫描 Obsidian 原始库。

点 **检查可清理项目** 可预览有程序清单证明的重复整理副本。只有已终止、当前未被引用、内容与当前保留副本相同的文件才可安排删除；独有文件、附件和没有可靠清单的旧文件保留。确认后在下次启动执行，启动前可取消。需要先退出访问同一目录的其他 Hub 或 MCP；执行前会再次核对文件和引用。

**压实数据库**也在下次启动执行。它先生成一致备份，检查结构、全部记录、完整性和外键，再切换到压实结果；失败时保留可用原库。压实会保留恢复副本，所以数据库缩小量不等于总目录立即减少量，也需要足够空闲磁盘空间。
