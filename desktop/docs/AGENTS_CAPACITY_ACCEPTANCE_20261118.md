### 长对话自动整理和接续

原验收对话绑定另一模型账号，Hub 拒绝向当前账号发送其历史。本次用当前账号新开一条真实对话，使用同一份 T28 原表。首轮核对前 200 条记录并保存 `evidence_start.csv`，随后分批抽查。独立复算核对 47 个不重叠批次的 51,700 条明细，逐条比较工作表、行号、坐标和已留存的原值前缀。

- 整理前最近一次观测为 **447,266 / 475,000 token（94.2%）**。下一轮在同一原生会话收到配对的开始与完成事件，间隔约 53.3 秒，Hub 手动整理请求为零次。该轮结束时用量为 102,089 token，并交付当轮 5 批核对。这里的 94.2% 是前一轮的观测值，自动整理的确切触发点由模型运行时决定。
- 整理后的第一轮追问找回了前 200 条的范围、Wire list 200 条、坐标与源行号不符 0 条、重复坐标 0 条，也找回三个最初待办和原 CSV。中途曾做一次回忆检查。压缩后的回忆追问沿用同一原生会话，回执显示分析重跑、成果新增和外部业务操作均为零。原成果经文件内容校验并再次确认包含 `sheet`、`records` 两列及 `Wire list,200` 一行。
- 助手回查时默认获得最近 32 批索引，共 35,200 条，有提示更早的批次被省略。独立核验可回读保存在本机的全部 47 批。该次答复准确说明了回查方法，但省略了所问的两个 CSV 列名，交接检查单也需要一次点名追问。

### 早期批次回查整改

第一次点名回查第 30,001 条起的批次时，助手复述了原来的交接事项和两个 CSV 列名，也明确说明旧批次已超出最近索引，无法核验实际条数。Hub 现可按批次的起始记录号检索同一对话的历史回执，每次仍核对当前授权、材料版本和回执状态。默认概览继续显示最近 32 批。

用升级后的正式助手重开同一条 Hub 对话。运行时构建变化后新建了原生模型会话，从已保存的回执找回 30,001–31,100 共 1,100 条，均属于「原始记录」，重复坐标和行号不符均为 0。独立复算与助手答复一致。该轮仅回读，分析执行、成果文件和外部业务操作新增均为零。

整改后 26 项定向 Rust 检查通过，1 项按既定条件忽略。新回归验证了超过默认索引范围时按批次定位，也验证了对话授权撤销后拒绝回读。真实 7.21–10 MiB 表格、真实缺公式保存值及余下故障组合继续在 #58 跟踪。
