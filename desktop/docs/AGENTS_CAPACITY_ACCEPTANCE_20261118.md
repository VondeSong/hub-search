## 表格容量和边界

| 操作 | 实测结果 |
| --- | --- |
| “一次读完这八份资料，逐份给我核对结果。” | 经 Hub 正式分析服务提交 1 份真实 CSV、7 份真实 XLSX，共 8,249,079 字节。隔离 Python 逐份处理，CSV 中 84,009 个源坐标全部匹配，重复和行号不匹配均为 0。7 份工作簿共 33 张工作表，与独立扫描的行数及 1,650 个公式格完全一致。 |
| “结果留给我，稍后还能核查。” | 生成 1 份 JSON 统计产物。用独立 CSV 统计与 SAX XML 解析复核，八份原件及运行输入副本的哈希一致。JSON 哈希与回执一致，回执从日常库重新读回。全程无模型调用，统计由人工编写的脚本经正式隔离运行时完成。 |
| “再加一份真实资料。” | 第 9 个文件在提交材料时被拒绝，提示每项分析最多 8 个文件。没有开始计算或产生新分析执行回执。 |
| “换成这份更大的工作簿。” | 22,283,154 字节的原样工作簿在导入阶段被拒绝，提示单文件最多 10 MiB。两条拒绝路径核对过原件及上一份成果哈希。 |
| “公式没有存上次计算结果时，查得出来吗？” | 只读检查日常库缓存的 10 份 XLSX，以及上轮清单的 7 条真实公式样本记录。去重后为 15 份，其中 5 份含公式，2,294 个公式格均含非空缓存。未找到真正缺缓存或空缓存的原件，保留该现场用例。缓存存在也不能证明缓存新鲜。 |

本次单文件最大为 7,558,139 字节的真实 CSV。8 份文件数上限有真数据通过和拒绝证据，10 MiB 有实际超限拒绝证据，缺少正好到达字节上限的真实文件。耗时为整条原生驱动 22.27 秒，其中运行时完整性检查约 16.50 秒、隔离脚本执行约 2.70 秒。这是单次固定脚本测试，与此前模型完成整题的 Hub/Codex 对照采用不同口径。CSV 数量是单元格明细行，XLSX 行数按文件内的行元素统计。

## 长上下文与跨端恢复

- 日常库中读取 111 个工作项的 181 条已报告上下文观测。最大单次报告为 209,791 token，提供方声明窗口为 475,000，界面口径为 44%。累计线程用量不用于计算占用比例。临界窗口与自动压缩极限仍缺真实现场。手动压缩、迟到回调及冻结预算恢复已有既定实测和本轮相关回归。
- 从现有 VPS 回读原 T29 交接，保持 1 个会话、1 轮模型回答、4 个文件共 17,545 字节。对照桌面已有交接清单，四份内容的哈希一致。实体手机切网、Windows 关机关联验证、真实订阅自然过期或耗尽及公开摘要，仍在 #32 逐项跟踪。
- 图片选择器的已有输入法回归遗漏了正式桥接的 `page: 1` 字段。本轮更新了测试契约，恢复中文输入法合成期不发请求、确认回车才发请求的检查。App 模块职责检查的两个既有直连点分别属于阅读/闪卡定位和日志入口，沿用原归属处理。
