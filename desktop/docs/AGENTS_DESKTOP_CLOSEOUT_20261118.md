## 本轮改变了什么

1. **换一份资料，只重做受影响的成果。** 分析输入有稳定身份，每份成果记录实际输入；同次检查缓存验证结果。整份对话授权版本变化，不再一律让无关成果失效。显式选择有效输入仍检查授权；缺少依赖清单的旧成果继续保守处理。修订保留成果身份和版本；失效旧文件不提供给脚本。
2. **分析结论能交给既有任务流程，并返回原分析。** 保存并回读的滴答对象更新现有本地索引；任务详情增加只读“查看原分析”，精确匹配资料库、对象与 verified 回执，撤回对话不显示。回答的“查看保存结果”只回查，不再次创建。切换任务后的迟到响应不能挂错入口。
3. **公开过程与窄表更易读。** 过程文字沿用既有次级颜色，提高对比度；表格每列至少 8em，保留局部横滚、键盘入口和焦点。不是展示隐藏思维链，也不以图标数量证明模型质量。
4. **分析耗时可定位。** 分别记录输入/依赖检查、完整性校验、复制、隔离执行、输出检查。保留环境与隔离检查，未用取消保护换速度。

## 性能与图表质量

同一真实力矩题、同一模型 gpt-6.1-sol / medium，修正后的正式 Hub 驱动三次 198.781 / 201.000 / 206.078 秒，中位 201.000。此前 Hub 中位 203.469 秒，Codex CLI 中位 110.813 秒。当前三次都包含正式 runner 收集；不是新一轮交替产品试验，不由约 2.5 秒差异推断稳定提速。Hub 表格任务仍明显慢，不能宣传全面达到 Codex 性能。

本轮每次运行的输入/依赖约 36–41ms、复制 11ms、运行时完整性约 15.4–16.3 秒、隔离执行约 5.6–6.4 秒、输出校验 35–50ms。模型记录耗时 192.6–199.7 秒包含工具等待，不能把它全归因于模型推理，也不能断言已解释全部差值。逐成果验证缓存消除了同次重复检查，但收益不能从这三次总耗时单独证明。

三份 CSV 均 41 行，每份逐行核对 16 列业务值，共 656 个值/份一致；图表均从零开始，20+2、17+2 正确、中文可读、参考项区分。首份图的底部说明与项目第二行标签相碰，保留原始证据并在同一成果中修订布局；CSV/Markdown 要求保持原字节，修订另核验，不把修订运行并入原三次性能成绩。

## 失败、整改及证据边界

- 初次 T16 聚焦测试有无效夹具和一次实际依赖失效问题，保留原失败；补齐逐成果依赖后正式单元与真实局部重算通过。真实差异模型曾输出非完整 JSON，系统拒绝并保留未完成活动；后续在同轮纠正，最终差异文件独立核验通过，不抹去过程中的失败。
- 初次公式任务成功后，采集驱动写入相对输出路径失败。通过正式只读续查恢复现成结果，没有重新计算或以驱动失败声称公式算错。
- 网络故障首次在发送消息前遇到数据库占用，未抵达提供方，不计网络失败成绩。保留记录后顺序重跑，取得实际网络错误与恢复证据；不声称已验证生产多进程同库并发兼容。
- 新前端测试首次缺少 jsdom 环境声明，导入失败；补正后整组 8 文件 104 项通过。没有隐藏首次失败。
- Sites 原型构建因 Windows 深路径解析失败；迁移本轮 checkout 到短路径，沿用既有框架、正式导入与锁定依赖构建通过，不修改产品运行 API。

截图按实际性质标记：正式客户端关键步骤、原型演示、真实执行记录回放、产物渲染。后台运行没有逐秒连续截图，不补造每个工具调用的现场图片。截图证明界面，回执证明执行，独立原件核对证明数据，三者不互相替代。
