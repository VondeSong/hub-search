# 稳定版准备：当前兼容边界与日常进程诊断

对应 [#13](https://github.com/VondeSong/hub-search/issues/13)。源码基线 `3433e2a`，产品版本 `0.16.396`。本轮不修改产品版本，不制作或发布候选包。这里只签收已取得的证据；日常 Windows 窗口尚未恢复，不能得出稳定版已就绪的结论。

## 本轮日常 Windows 进程诊断

通过 PID、精确创建时间、实际 EXE 路径与 SHA-256 核对原进程；核对原主 HWND 的所属 PID/UI 线程，避免误用后来出现的空标题辅助窗口。私人绝对路径、线程身份及逐项原始回执只留在忽略目录。

本轮 3 次采样跨度约 4.4 秒：原窗口持续被系统判断为无响应，目标累计 CPU 保持不变；工作集约 273 MiB，private bytes 约 92 MiB，40–41 线程、762–764 个句柄。这些短时样本不能证明泄漏、长期稳定或永久死锁。

读取 UI 线程及 4 个累计 CPU 较高线程的 Windows Wait Chain Traversal。5 次查询均成功，仅得到 blocked 的线程单节点，没有报告可识别的等待环。WCT 不覆盖所有同步方式；单节点/无环既不能定位源码阻塞，也不能排除未知等待或死锁。本轮没有证据支持将异常归因到数据库锁、WebView、某个初始化调用或某项后台同步。

两个既有标准输出/错误日志为空。此前的一致 SQLite 保存副本及任务内容保全记录继续保留；本轮不重复生成副本、不改变任务状态。尚无法确认进程内未落盘内容。

诊断入口：[windows-readonly-health.py](../qa/windows-readonly-health.py)。必须显式提供 PID、原启动时间、EXE/hash、HWND 和新的输出路径；校验身份后才观察。等待链在独立诊断子进程查询，单次 4 秒上限，只结束超时的诊断子进程。没有提升调试权限、挂起线程、注入、发送界面操作、终止/重启 Hub 或另开同数据客户端。

## 回退与剩余签收

本轮限定原生回归：数据库 recovery 3 通过/1 忽略、个人设置 2 通过、凭据发布 4 通过、加密账号迁移 6 通过、整库备份与相关文件保全 54 通过/2 忽略，合计 **69 通过、3 忽略、0 失败**。忽略项没有按通过计数，没有启用真实账号/日常数据的额外测试。使用项目正式 Windows 测试入口生成的、已核对字节一致与 Common Controls manifest 的测试程序；这仍是夹具测试，不是重新运行真实安装或迁移。

`windows-readonly-health.py` 的 Python 语法检查通过，实际只读运行完成了身份、SDK 结构大小、窗口归属、3 次采样和 5 次等待链查询的断言。原生日常进程始终保留。

工具复核后再次以相同原进程身份做有限采样，窗口仍无响应，目标 CPU 增量仍为零，5 个 WCT 仍仅返回 blocked 单节点。另以错误 EXE 摘要执行反向检查：在窗口/等待链采样前拒绝，退出非零且未创建结果文件。每次校验重新读取进程身份，避免复用 psutil 缓存的创建时间/EXE 信息。

1. 当前日常窗口恢复须由已接手恢复的对话按用户实际授权处理。本轮不接管，也不重复索取同一许可；恢复前保留数据库/原件/已知任务证据，仍须明确内存草稿未知。
2. 覆盖升级前保存完整旧数据与对应程序版本。需要回退时使用与旧程序匹配的升级前数据副本，切勿让旧程序直接写入当前升级后的活动库。业务导出不代替完整恢复点。
3. 在获准的空目标目录核对升级、迁移中断、索引重建、整库恢复、路径失效与重新定位；逐项记录数据表/正文/附件/个人设置范围，区分未下载云端内容。
4. 需要实际的干净 Windows/缺组件/断网首次运行，以及约定规模和时长的持续同步、监听与资源观测。当前没有新的统一时长承诺，短采样不替代它。
5. 只有后续真实候选具备源码冻结、正式包、哈希、必要检查和目标环境回执，才签收当前版交付组合。本轮不触发标签、Release、安装或部署。

#13 保持打开；完成的是当前矩阵、有限只读诊断和对应检查，未完成的实窗/环境/长期运行验收继续保留。
