### 完整结果保存

原漏标结果约 120 KB，其中候选清单约 89 KB。它含候选片段、建议及审核预演，直接复制到 64 KiB 单条调查记录会失败。

修复使用既有 `agent_records`：完整 JSON 按 UTF-8 边界分片，以 SHA-256、大小、顺序及数量核对不可变快照；描述记录提供同一权威建议 ID，标签收件箱仍读取原建议。每片、Run 及 Work 的既有配额均未提高，配额不足时整笔回滚。旧的内联记录继续可读。

续查前保存同一断点的完整快照，后续批次不改变历史；损坏或缺片会拒绝读取，不用当前可变缓存补造。模型上下文不再附带尚未逐项核对的全部候选片段，明确保留候选数量及完整快照引用；已分析的审核依据不被静默截掉。新续查的完整结果为 146,869 字节、19 片，回读与原结果一致。

续查成本改为累计报告相减后的本批新增量：12,595 + 4,347 = 16,942 字，实体 5 + 5 = 10。重复响应已保存任务复用结果；正式定义过期、授权改变或范围不匹配时拒绝复用/续查。

### 只读答复与业务操作

原生 Agent 使用标签目录、画像和比较工具后给出了正常 final，实际未调用批准或写回；宿主却将这些已受范围约束的只读工具计为未知业务工具，拒绝自然答复。

修复仅把标签目录、画像、比较、证据及内部关系读取列入观察操作；建议提交、批准、关系修复、未知工具和已拒绝的 finish 仍保留结构化交付要求。普通答复不推定业务完成、批准或来源修改。
