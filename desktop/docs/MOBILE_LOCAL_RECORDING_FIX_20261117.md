# 手机本地录音入口与旧草稿隔离

## 截图暴露的遗漏

- 新建日志和已有日志使用不同编辑器。新建页有 Mic，已有日志的 MobileJournalEditor 未向底栏传入录音操作；上一轮仅覆盖新建和已保存原音追加路径，不能证明已有日志编辑可录音。
- v30 仅折叠已保存记录的原音。旧版本留下的全局未保存草稿会优先替代当前笔记，7 段草稿录音被当作本次新增全部展开。
- 已连接供应商时会自动转写新段，没有独立的仅本地录音选择。

## 修复

- 已有日志底栏补上直接可见的麦克风。录音作为嵌套面板打开；保存音频先写回当前编辑草稿，保留未提交的正文、附件和原记录版本，未提前提交整条日志。
- 默认仅本地录音。只有显式选择“录音并转写”才检查云端并启动识别；本地模式不向识别服务发请求。保存后的笔记附件同步继续沿用原设置。
- 无关旧草稿保存在同一份持久语音草稿的 pendingDrafts 中，切换当前笔记前先持久保留，不自动替代当前笔记。恢复入口折叠并标明日期与段数；显式恢复后，恢复前已有的音频也默认折叠。
- 保存、关闭或清理当前草稿时保留其他待恢复草稿。失败不清草稿；旧原音不删除、不拼接、不覆盖。原生正在录制的段不能切换到其他记录。
- 复用原有 quick_journal_voice_draft 原子保存及校验，不改 Rust 命令、数据库结构或原生录音协议。超过原草稿容量限制时保留原草稿并返回错误，不绕开限制。

- 前端针对 JournalVoice、MobileJournal、QuickJournal、JournalTranscription 的 4 个测试文件共 62 项通过，类型与前端构建通过。覆盖编辑页入口、7 段旧草稿隔离、新音频回写当前编辑草稿、清理后仍保留其他草稿、本地模式零云端请求，以及显式启用转写。
