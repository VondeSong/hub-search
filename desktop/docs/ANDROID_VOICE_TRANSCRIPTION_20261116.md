# 阿里与 OpenAI 录音转写接入和验收（2026-11-16）

本轮接续 #22／日志与速记，父任务 #40，平台跨端。用户已授权配置两家服务并使用同一段音频测试。两家的密钥已保存在 VPS，真实鉴权和转写均成功；不需要把供应商密钥填进手机。

## 使用方式

新版 Android Hub 沿用 Agents 已保存的 VPS 地址和设备连接。日志长按＋进入语音速记，选择阿里或 OpenAI，开始录音；每段只使用所选一家。实时文字单独显示，完成后校对，再点击“加入补充文字”，保留此前正文。

原音始终保留。可以先保存录音，稍后从同一条记录的“继续录入”查看转写结果；已有原音可主动选择另一家补转写。失败或网络中断时先核对同一任务的接收进度，不自动创建第二次付费任务，也不自动切换服务。

## 本次实现

- Gateway 复用 HTTPS 和设备认证。语音任务按设备归属隔离；同一任务编号、原音身份、服务及音频分段校验一致才能复用回执。VPS 重启把未完任务标为中断，保留结果，不自动重新计费。
- 阿里 `paraformer-realtime-v2`、OpenAI `gpt-live-transcribe`，统一单声道 24 kHz PCM16。句子修订、完成顺序和迟到错误按真实任务／音频项核对。
- Android 使用同一个麦克风来源，编码 M4A 原音，同时提供有界 PCM 分段。暂停不计入时长，离开应用结束并保留本段。有效压缩原音已保留且分段已交付后，才清理临时 PCM。
- 补转只读取用户选择的真实本机附件，核对哈希后上传到个人 VPS，再由 FFmpeg 解码；不创建公开音频 URL。只允许音频容器，阻止播放列表借音频请求读取其它文件。
- 识别原文、校对稿、是否已加入文字和服务任务身份随原记录保存。迟到结果不能覆盖校对稿，不能写入“下一条”草稿；清空全局录音草稿不清除已保存记录的转写回执。
- 录音上限单段 30 分钟、原附件 20 MiB、服务同时两段；服务端空闲及总时长有界。供应商密钥不进入 APK、公开原型或 Git。
