# Hub Codex 套件

Hub 启动的 Codex CLI 调用共用「设置 → Codex」中的模型、推理强度、标准/Fast 速度和同时运行数量。模型列表及可用参数从本机 Codex CLI 读取，不硬编码账号可用模型或速度倍数。空模型表示 CLI 自身默认模型。Hub 使用 CLI 已有的登录态；Hub 中的模型设置独立于 Codex 桌面聊天的模型选择。

Hub 核对本机 Codex 桌面应用随附、npm 安装及 PATH 中的原生 CLI 版本，优先使用已验证的较新版本。模型查询和分析执行共用这一选择；刷新模型目录时会重新核对，避免旧的全局安装遮住新模型。Hub 不安装或更新 CLI，也不迁移账户。

模型目录通过短时、只读的 CLI app-server `model/list` 查询取得，并处理分页；不会创建聊天或发起生成。只展示该查询实际返回的可选型号及推理档位，模型可见性随账户和目录变化。Fast 优先取此目录的能力信息；旧协议缺少该字段时，仅从同一 CLI 的原始目录补充已可选型号的能力。补充失败时保留可选模型，未知 Fast 能力保持不可用。

分析执行使用 `exec --ignore-user-config`，不加载用户 config.toml，并禁用 shell 工具。只读调查还显式关闭原生网页、连接器、插件、记忆、技能检索、图像读取、浏览器和子 Agent 等旁路，由 Hub 执行受授权的结构化取证请求；只读沙箱本身并不能代替这些边界。图像读取使用本机 CLI 已识别的 `view_image` 功能开关，移除被忽略的 `tools.view_image` 配置项。目录查询的 app-server 当前不支持忽略用户配置这一选项，因此显式选择与分析相同的内置 OpenAI 提供方；其余用户配置仍可能由 CLI 读取。两个流程共享 CLI 认证，不修改全局配置、登录信息或外部聊天。

旧的 OpenAI 兼容 API 地址、API Key 配置和连接测试已退出当前应用接口，授权迁移也不再导出该旧服务密钥。历史授权包中的旧项不参与选择，其它受支持的授权仍可导入；现有数据库和系统凭据不作破坏性清理。内部生成统一使用本套件，外部 MCP 客户端继续使用自己的模型和登录态。

## 覆盖入口

| Hub 功能 | 模型职责 | 后续处理 |
| --- | --- | --- |
| 标签定义 | 根据所选资料库证据起草定义 | 用户确认定义与范围 |
| 查找补标建议 | 检索候选、核对内容、提出建议 | 待审核区确认 |
| 逐篇补标检查 | 按已保存定义和预算检查正文 | 保留断点、待审核区确认 |
| 标签关系分析 | 根据标签证据提出关系建议 | 待审核区确认 |
| 收藏复制到 Craft | 选定技能整理内容、定位归档位置 | 沿现有写入和附件核验流程执行 |
| 收藏复制到滴答 | 提取有依据的行动，或保留原文为笔记 | 沿现有任务/笔记和附件适配器执行 |
| 笔记／阅读条目受托调查 | 根据获准来源自主搜索、读取、补查并提出有依据的下一步 | Hub 核验引用、授权与版本，保存事项；不执行业务写入 |
| 受托事项的补标建议 | 根据选定定义和当前页面节选准备一条具体建议 | 用户明确提交后进入原标签待审核流程；事务核验授权与业务回执，不改源标签 |
| 受托事项的闪卡草稿 | 根据当前笔记全文、学习目标和适用质量规则准备 1–5 张有原文依据的问答卡 | 明确确认后由原导入入口进入闪卡收件箱；原审核与复习流程继续拥有接受和排程 |
| 受托事项的 Craft 归档 | 对真实阅读条目复用原归档定位、材料和附件整理，形成具体方案 | 明确确认后复用原写入及正文／附件回读；未知结果保留身份，禁止自动重建 |
| 已明确启用的条件复查 | 已知依赖变化或约定时间到达后，按原快速调查预算重新取证 | 最多 3 轮、7 天到期；仅空闲准入，手工请求取消自动运行；不自动执行任何业务动作 |

收藏的视频只提供来源与附件信息，不让模型分析视频。Craft 超过 5 MB 的附件仍跳过上传，本地原件保留。滴答只选已有标签，参考内容使用笔记类型。

外部 Codex 通过 Hub MCP 读取证据、提交闪卡草稿或建议时，其模型由外部客户端控制。Hub 套件不会修改外部聊天或 Codex 的全局配置。

## 设置与队列

持久设置由应用数据目录中的 `codex-suite-v1.json` 拥有。前端不再用每个功能各自的 localStorage 选择模型，也不能通过调用参数覆盖套件设置。

同时运行数量可设为 1–4，默认 2。模型操作通过同一个 FIFO 队列取得空位；各功能原有的重复运行保护、正文预算、审核规则继续有效。一次操作进入队列时冻结模型、推理强度和速度，期间保存的新设置适用于后续操作。并发设置调整后，已运行工作继续，新的准入按当前上限执行。

队列和运行记录是当前 Hub 进程的状态，重启后不将模型运行记录视为可恢复的远端写入。收藏副本和补标的持久断点仍由各自业务模块保存。

条件复查通过同一套件的 `try_start_background` 准入，空闲且没有手工等待时才启动，不占等待队列；手工调用到来时取消它的共享 Control，再走原 FIFO。模型发现、设置快照、认证、超时和释放仍属于同一 Operation。条件、来源范围、3 轮/7 天及全局每日预算由事项宿主保存并核对，模型不能改变；元数据没有变化且未约定到期时不创建模型操作。普通业务的原并发、审核与写入流程保持不变。

任务与附件条件继续使用此入口。任务从原统一投影按精确来源装载；绑定关系或 Markdown 行身份改变时暂停。附件只有原 PDF／OCR 管线提交的当前输入版本文字片段可引用，旧片段等待重提取时不调用模型、不消耗轮次。附件的整库授权独立保存，旧笔记／任务授权不自动扩大。自动运行至多预读 4 个已知实体（含锚点），额外片段每个至多 2,000 字符，计入原调查预算；模型仍决定后续补读和结论。历史定位先检查本轮范围，未读依赖的并发变化不在发布时被确认掉。该能力只复查与交付，不自动修改源任务、标签、归档或闪卡。

AG 04.3 已在真实隔离桌面完成图片 OCR、输入换版后的条件复查及扫描 PDF OCR 调查，复用同一套件，共 3 次模型调用。旧 OCR 页面与缓存下载路径现在按当前输入版本决定复用，预览按精确附件身份清理旧内容；这两项修复由原附件管线和预览控制器拥有。合成条件最终暂停，未产生业务动作。

真实 Craft 的有限试用另走已有单页只读核对器，不属于模型调用：仅专用隔离进程、CLI 绑定库／页面、桌面明确点击后最多两轮，不刷新凭据或自动启动同步。上一轮 `PROBE_AUTH_NOT_FRESH` 的失败保留；本轮经用户明确授权，由独立的默认忽略验收入口调用原凭据恢复所有者续期并回读，未改变只读核对器的凭据权限，也未导出凭据或创建新授权。

普通无附件页面现可完成此单页核对，存在但未缓存的附件仍拒绝。真实笔记《文件夹下新建还是页面内嵌套子页面》两轮读取通过，共 36,186 字节元数据，无附件 GET 或真实资料写入；原白板页面因资源地址变化且旧缓存缺少版本证明，继续保留为未通过。后续有限 Agent 调查仍仅授权这一笔记页面，使用原 `gpt-6.1-sol`、high、标准速度配置，资料和实际模型用量按独立运行登记，不把服务读取成功当作模型成功。

该真实调查首轮两次请求耗尽 120 秒，没有交付；从同一事项继续后约 39 秒、1 次调用完成有引文的有效交付，累计 3 次调用。实际读取一篇笔记的 1,193 字符，形成 4 项发现、3 项下一步和 2 个待决定点，状态为需要用户决定。重启保留交付且未自动重跑，没有标签、归档、闪卡或条件写入。继续成功不替代首轮失败，模型上游偶发停顿仍是扩大试用前的限制。

调查通过可选的宿主 `Control` 复用同一队列。快速/深入模式的总期限分别为 120/240 秒，包含排队、目录读取、取证与所有模型调用；取消会移除本次等待项，或结束本次拥有的 CLI 进程。旧调用不传总期限时仍保留原有单次 240 秒默认。调查事项、取证及用户决定保存在正式 SQLite 中，和当前进程的套件状态分开；中断后重新核对证据并创建新运行，不复活旧进程。

带总期限的调用单次等待上限为 90 秒；快速调查进一步收紧为 75 秒，给同轮恢复预留时间，总期限仍为 120 秒。只读调查只对宿主确定的单次生成超时自动恢复一次，而且至少还须剩余 30 秒与一次调用额度；恢复仍消耗原运行的总期限、调用与材料预算。登录、额度、授权失效、来源变化或任意模型文本不能触发这一重试。后续响应存在且交付核验成功才清除已恢复错误；旧领域调用的失败记账规则保持有效。当前本机 CLI 不允许覆盖内置 OpenAI provider，Hub 不为调整流空闲参数而更换 provider 或认证。

补标动作准备同样使用有期限的 `Control`，总期限 120 秒、最多一次模型调用；中断后重新准备，不自动提交。草稿、确认及业务回执由事项的动作记录保存，执行仍委托原标签提交边界。确认与业务建议、回执同事务提交，因此本地中断不形成“业务已写入但动作没有回执”的恢复空档；后续远端动作不能借用这一保证。

归档和闪卡继续共用同一套设置、CLI 登录态、FIFO 和取消控制。闪卡准备最多一次调用，提供最多 12,000 字符的完整当前页文本，超过上限直接说明范围不足；不把节选当作全文，不分析图片／附件。适用制卡规则由原质量模块选择，反馈再限制到获准的精确来源，确认时重新校验。原导入所有者提供调用者事务入口，草稿、同步标记和动作回执一同提交；Agent 使用独立来源标记 `agent://hub/flashcard-drafts`，与 MCP 提交执行相同质量约束。

归档准备使用 240 秒的有界控制、最多两次原模型调用，单次宿主文本材料与 schema 等最多 64 KiB、合计最多 128 KiB；每次最多 6 张图像、单张 8 MiB、合计 24 MiB。来源限于一个不超过 15,000 字符的真实阅读条目。目标目录、承载页和附件沿原归档所有者读取，不将目标资料库扩大为一般调查授权。用户选择目标后的准备仅产生方案；带 `agentActionId` 的方案不会被原自动保存或重启重试接管。

归档确认与领域处理意图同事务落盘，再使用原资源预约、资料库准入、写入及回读。写入中止也保留已经返回的远端身份，并按 `source_operation_id` 绑定本次操作；结果未知时只允许沿原入口核对关联，不能自动创建。已有身份的安全继续仍检查原方案、来源、决定、授权、目标连接及取消状态。回执是上次领域核验的事实，不冒充本轮重新查询远端，也不代表事项目标已经完成。

Craft 核验的范围是正文覆盖和所登记附件的目标块 ID 存在，未下载远端附件逐字节比对。正文与附件标记在同一读回事务提交，缺少任一附件 ID 或本地提交失败时不留下部分成功标记。旧记录没有单独保存附件核验标记时，模型读取投影使用 `verified: null` 和 `notRecordedIndividually`，不把它解释为核验失败、不回填旧证明；历史回执原样保留。

调查的 `Control` 同时检查资料库控制代次，避免撤回后的旧正文在下一轮再次发送。每次模型请求前还复核事项授权和全部上下文依赖，包括未读候选的摘要；发布前再原子核验。运行选项参考 [Codex 非交互运行](https://developers.openai.com/codex/noninteractive) 和 [官方配置参考](https://developers.openai.com/codex/config-reference)，本机实际能力继续由现有 CLI 发现与验证。

## 调查共享记忆与跨模型复用

调查开始前可以展开「共享记忆」，选择个人通用或项目范围并明确启用；默认不启用。Hub先创建事项并登记记忆范围，登记失败保留可继续的事项，不调用模型。已有事项和新事项使用同一管理入口；切换模型沿用套件设置，不复制或重建一份模型专属记忆。

正文与检索由Basic Memory 0.23.2和本地Markdown负责；确认、稳定主题、版本、替代、停用、遗忘及重复请求由Hub数据库负责。Hub在每轮调用前后核对项目、权限、当前修订、正文哈希和代次。规则按启用范围加载，决定至多5条候选，由模型结合当前问题判断适用性。规则与决定各最多2000 UTF-8字节，整个共享上下文最多4000字节，包含JSON，不称精确token计数。

Windows 分发包内置共享记忆组件。展开面板读取设置和已保存的记忆，查看状态无需解包组件。首次可以明确点击「准备本地记忆」，已启用的记忆在实际使用前也会核验组件。无需选择 Python 或模型目录。「修复本地记忆」只修复组件缓存。安装与开发入口见[运行组件与安装](运行组件与安装.md)。

新对话输入问题后，Hub 可以在本机从同一资料页、所选项目或未归类的独立对话中找相关旧提问，命中才在输入框旁提示。它会匹配近期对话的标题和用户提问。点「继续旧对话」会保留当前草稿，含待发送附件时需先移除附件再切换。「引用到本次」把一段可移除的旧对话摘录放入当前草稿，发送前核对内容和可用性。旧回答只供参考，旧附件及授权不会随摘录带入。历史查找无需开启共享记忆，手动历史搜索也可同时搜标题和提问。[Codex、T3 Code 对照与验收记录](https://github.com/VondeSong/hub-search/issues/21)

面板中的「本轮使用」只对应当前run，展示实际记忆及版本；新一轮尚未取得记录时不显示上一轮使用结果，撤权后隐藏。主动停止在套件中保存为cancelled，界面显示「已停止，可继续」；真实生成错误仍显示失败。调查的持久状态为interrupted，已读材料和有效历史交付保留，继续时重新核对并创建新run。

2026-10-20正式桌面已用4篇真实项目文档完成GPT-6.1-Sol与GPT-6-Sol各4项完整回答，另做一次主动停止后继续，合计15次调用、35处精确引文。相同记忆ID/修订跨模型复用、版本更新与停用排除、重启、来源变化和撤权均有正式窗口及管理记录证据。此结论限于现有CLI两个实际可选型号，不代表独立提供方已接入。详细边界和证据见[实施方案9.42](INSIGHTS_IMPLEMENTATION_PLAN.md#942-正式桌面真实项目资料与跨模型验收2026-10-20限定范围已完成)。

## 底部信息栏

底部统一显示 Codex 正在运行、等待、完成和失败的状态，展开可查看近期操作及其提交时的模型与速度。记录不包含提示词、原文或凭据。标签与收藏功能的临时提示和运行错误发送到底部；方案正文、证据、待确认字段和操作按钮继续在原功能中使用。

Codex 分析完成仅表示模型输出及对应分析流程完成。Craft/滴答的正文和附件写入结果由资料库处理状态单独报告，附件失败不会因模型已经成功而被显示为保存成功。

保存方案使用原生模态窗口，窗口内底部也显示当前操作状态，避免主界面底栏被遮住时看不到失败原因；关闭窗口后仍可从主界面底栏和处理记录查看。

## 实现边界

原生 `codex_suite` 命令提供 `get`、`status`、`models`、`save` 四项操作。原生套件拥有设置、准入、CLI 执行和运行状态；各领域模块拥有提示输入、模型输出语义核验、审核与外部写入。前端共享一份状态订阅与轮询，不为每个功能重复读取模型目录。

调查原生入口为 `agent_investigation`，负责创建、读取、运行、取消、用户决定、撤回分析授权，以及准备／明确提交标签、闪卡和归档动作、关联已有归档结果；模型不能直接调用这些控制操作。`agent_work` 只通过 `Operation` 使用模型，不拥有第二套模型设置或执行队列。后续调查读取 `businessActionRecords`：包括已确认但结果未知的尝试、实际导入结果及当前审核状态；未完整核验的尝试不叫“已核验回执”。来源范围与分析授权不代替业务提交确认；业务结果来自原领域记录，调查与提交成功均不代表事项目标完成。数据选择、阶段进展和验收边界见 [Hub Agent 与洞察实施方案](INSIGHTS_IMPLEMENTATION_PLAN.md)。

## 完成事件与 LIVE 02 验收

生成使用同一 CLI 的 `--json` 事件流，原 `--output-schema`、认证、模型与设置快照继续有效。输入完整发送后，最后一条已完成的 `agent_message` 必须是 40 KB 内的有效 JSON，并在期限内收到 `turn.completed`，套件才停止和回收本次拥有的 CLI、把结果交给原消费者；不把进程收尾等待算成模型生成。缺少完整结果或终止事件时继续走原文件／进程路径，推理、部分输出或超期事件不能构成完成依据。总期限、取消和来源核验继续有效，业务模块仍核验各自输出与确认。事件协议参考 [OpenAI 非交互运行文档](https://learn.chatgpt.com/docs/non-interactive-mode)。

`modelExecution` 保存固定生命周期时间、计数与错误类别，不记录提示、事件正文、推理或凭据。CLI 的 JSON 错误与原 stderr 均保留登录、额度和模型错误分类；这不新增重试权限。`completedOutput` 表示已取得终止完成的结果后主动回收进程，因此其进程退出码不代表模型失败。正常业务不增加模型设置、provider 或队列。

LIVE 02 实测保留了真正未完成的 75 秒调用，并发现一次在完成事件后等待退出、最终耗尽 120 秒的误判。修复后，同一事项约 40 秒、1 次调用有效交付，完成事件至返回约 44 毫秒；另一个精确单页约 46 秒、1 次调用有效交付。两项均通过原引文和来源核验，未启用整库授权、自动复查或业务动作；这不承诺上游永不超时。

白板单页验证在隔离 CLI 范围内增加显式原件读取，继续委托原附件所有者，最多 3 次请求尝试、3 MiB 原件响应数据、两轮及 120 秒。计数由原下载边界产生，不把地址解析次数或缓存大小当作网络读取；元数据另受 4 MiB 限额约束。实际白板预览 PNG 的两轮版本绑定通过，但跨重启地址变化且缺少资源修订时，零下载核对仍拒绝旧绑定；不以块时间或旧哈希补造证明。Agent 不接收此验收器结论作为正文事实，仍按本地证据表达新鲜度。

## 附件版本核验与缓存复用

HTTP 表示证明由原附件下载器产生，与 Blob、当前资源代次和任务领取在同一原提交事务中绑定；`attachment_download_cache::revalidation` 只承接这项职责。没有新下载器、缓存库、模型客户端或调度器。来源清单仍负责识别准确块和临时地址变化，地址变化时旧 Blob 绑定仍先失效，不能把旧证明直接提升为当前版本。

只有同库、同来源、同准确块、兼容资源修订和大小、且本地文件完整核验通过的旧 HTTP 证明，才能作为条件请求候选。下载器发送 `If-None-Match` 和禁止直接使用陈旧响应的请求头；只有最终资源身份相同、响应保留同一强 ETag、本地文件再次核验有效的 `304` 才复用字节。弱／缺失／不同 ETag、最终资源变化或本地损坏均不能授权复用，至多退回一次无条件原件请求，仍受原期限、请求数、字节数、取消和资源代次保护。`no-store`、不支持的 `Vary` 或编码不产生可条件复用的 ETag。协议依据见 [HTTP 验证器与条件请求](https://www.rfc-editor.org/rfc/rfc9110.html#name-validator-fields)。

没有可靠验证器时完整读取当前响应并核对字节。相同内容沿原 BlobStore 完整性检查复用已保存的文件；内容变化或文件损坏则保存新内容或修复对象，不把相同大小当作相同内容。`lastRepresentationCheck` 只保存来源代次、Blob 身份、核验类别、正文接收字节和本地文件复用事实；强 ETag 与最终资源摘要留在来源的私有证明中，不进入模型正文或通用诊断输出。该回执没有扩张 Agent 的材料或业务权限。

隔离单页入口分别保留纯本地缓存核对、强制读取原件以及显式“核验版本并复用附件”三种选择；两项网络模式互斥。后一模式允许条件核验及必要的完整读取，不能把它显示成“未下载附件”。正常配置不显示这些验收入口，也不因启动或读取证明自动执行核验。上述请求数、正文和元数据上限保持不变。

Agent 的原报告提示同时约束用户语言：用自然中文表达来源范围、已确认决定、执行回执及局限，内部协议名保留在结构化交互中；只有来源本身讨论这些名称时才需要引用。记录为空表示当前材料没有相应证据，不能推断现实中未发生、接口失效或权限不足。该约束复用原模型调用，不增加独立润色调用；实际效果与首次未通过的报告见实施方案 LIVE 03。

## 原服务恢复与隔离诊断

Craft 原传输的 HTTP 502／503／504 由原恢复判断识别，先消费该传输产生的状态码，再判断请求是否允许安全重复；永久 HTTP 错误的正文不能授予重试资格。原最大尝试数、限流、期限和业务命令保护保持不变，不另建服务重试队列。LIVE 04 取得了修复前后同一实际 HTTP 测试的失败／通过证据，这不等于查明 LIVE 03 那次已丢失底层错误的历史原因。

明确绑定单页的隔离核对才启用 `craft_cache_probe::diagnostics`，在原 `mcp_post` 记录有界、无凭据的请求事实。版本 2 原生回执附带版本 1 诊断：轮次、步骤、最多 64 条请求的序号、固定方法类别、HTTP 状态、耗时、完成或中断类别，及已核验轮数和溢出状态。没有地址、认证头、参数、正文或远端自由错误文字；普通运行不保存此状态。界面从白名单解释中断，不根据任意错误文字推断原因或触发整轮重试。两次真实单页核对均通过，历史中断仍开放，扩大真实事项仍等待前置条件；详见实施方案 LIVE 04。
