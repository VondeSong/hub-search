# 助手附带资料与仅技能请求修复

日期：2026-11-16。关联：#31（统一助手）；不重开已完成的 #29。

## 问题与原因

日常库中，将已有日志加入对话后只发送 `$record-to-log`，用户消息没有展示附带页面，生成结果沿用了上一轮不同的短口述。

真实记录表明：页面已通过 `addNotes` 加入授权，预读了前 6000 字符；技能正文和格式参考也已加载。因此修复对象是消息中的资料归属和本轮处理意图，而不是补造一次技能调用或扩大资料库范围。

## 实现

- 从初始授权及每条消息保存的 `addNotes` 投影只读资料卡，旧消息也能显示其实际附件。只查询页面标题与路径元数据，不因展示卡片额外读取正文。
- 资料卡描述选择，不代表模型已读完。范围撤回后不再展示已撤回来源的名称与路径；历史卡片没有移除按钮。
- 将本轮附带资料传入模型上下文。仅技能请求明确处理当前选择，保留原记录日期、事实和不确定性，按需补读截断部分，不将历史成稿当成本轮输入。
- 后续仅技能请求可以继续使用当前已授权的明确资料；消息卡片仍按真实初始选择或新增附件归属展示，不把未新增的附件伪装为再次附加。
- 普通模式没有内容或明确资料时拦截空技能发送并保留技能选择；原有标签任务对象不受此拦截影响。技能前缀支持末尾没有空格。
- 保留既有授权、来源版本检查和写回确认流程，不自动保存整理稿到来源。
