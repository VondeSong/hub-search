## 四种版本分别判定

| 边界 | 当前合同 | 不能替代的证据 |
| --- | --- | --- |
| 应用版本 | 平台包的 `versionName/versionCode` 及构建内容身份 | 同为 0.16.396 不能证明同一源码、签名或具备相同运行验收 |
| 数据库版本 | 由数据库迁移所有者决定；高版本数据库不供旧应用直接打开 | 备份协议兼容不表示可用旧程序打开升级后的 SQLite |
| OSS 变更外层 | `hub-flashcard-changes` 写入 v4，当前读取 v2/v3/v4 | 外层 v4 不限制或证明内部快照仅为 v4 |
| 闪卡内部快照 | 平级 v4；存在父牌组关系时 v5 | `.hubfc` 文件头 `HUBFC001`（文件协议 v1）不决定内部快照版本 |

生产选择器是 `flashcard_snapshot::records::wire_version`，备份、检查点及变更记录沿用领域所有者的版本。当前 `flashcard_scheduler::validate_snapshot` 接受 v1—v5，拒绝 v4 及以下携带非空 `parentDeckId`，也拒绝未知快照版本。备份解析与领域合并在写入前使用此校验。

“旧客户端拒绝 v5”指只支持 v4 的旧协议读者应在版本门禁拒绝整份层级数据，不能忽略未知父关系并继续写回。现有 `hierarchy_wire_marker_rejects_old_client_writes_and_retains_flat_compatibility` 回归实际覆盖当前读者拒绝伪标 v4、正确产生 v5 及恢复平级 v4，**不是本轮启动了旧客户端二进制**。不能据其测试名宣称所有旧安装包已经实际拒绝。
