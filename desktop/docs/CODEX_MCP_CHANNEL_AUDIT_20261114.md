- 移除笼统的“双端完整任务尚未验收”，说明改为实际行为：通过 MCP 调用 Hub 工具，沿用本对话的资料范围、累计预算与保存权限；每轮从已保存记录继续，不自动继承其他聊天的工具或权限。
- 本轮不添加“已连接”“已通过”等替代状态，不改变设置值、默认选择、应用确认、工具授权或原生执行。

## 三条不同的路径

| 路径 | 含义与源码依据 |
| --- | --- |
| 当前“工具连接 → Codex MCP 通道” | `externalMcp` 切换 **Hub 管理的 Codex 调用 Hub 工具的传输方式**。`runner/native.rs` 创建 `mcpStdio-v1` 绑定，每轮禁用旧线程复用；`model_runtime/cli/agent.rs` 建立受控 Bridge，并拒绝旧线程/压缩请求。它不是给外部 Codex 自动安装插件。 |
| 独立外部 Codex → Hub MCP | 外部客户端通过 Hub 暴露的受控业务入口访问已授权资料与成果；有独立的历史代表性验收，不能直接等同于当前下拉选项的桌面验收。 |
| “外部工具（MCP）”服务列表 | `mcpServices` 是另行发现、选择并应用的服务授权，与上述传输开关、`webSearch` 搜索设置分别保存。选中通道不自动授权全部服务。 |

首次核对时尚未找到以下与**当前桌面入口及源码版本**绑定的完整实测记录；后续已通过隔离原生 WebView、正式组件、真实 IPC、Codex MCP 读取及合成本地保存补齐。此处状态仅表示这三项完成，不代表 #31 所有视觉和来源平台验收完成。

- [x] 在当前 MCP 传输下跑一条限定资料读取 → 引用/报告 → 用户预览确认保存的代表链，核对真实 `mcpStdio` 调用、当前授权、来源版本及保存回执；不能用原生路径或旧独立客户端记录替代。
- [x] 在上述当前版本的代表链补充停止/失败后显式继续与正常重开，核对同一事项、新上下文恢复、授权收窄及未知保存结果不重复写入。已有协议负例按未变源码复用，没有为此重新调用全部旧模型场景。

## 不属于上述待验收项的能力边界

- MCP 模式不复用/压缩旧模型线程是当前明确实现；同一事项从保存记录继续。若需要同线程压缩，属于另行设计与验证，不能仅改标签就宣称支持。
- 独立外部客户端首次抽取、全部图表/来源写回、所有技能语义、任意客户端和长期规模，均未由 V5 单例证明，也不是已完成核心范围的缺漏补验。按实际需求进入已有事项。
- 私有认证/OAuth、第三方 stdio 与写插件等保持 [#14](https://github.com/VondeSong/hub-search/issues/14) 的暂缓决定；桌面/VPS共享复杂技能跟随 [#48](https://github.com/VondeSong/hub-search/issues/48) 的待处理方案。不启动这些扩展，不把它们列为当前通道可用的前置条件。
