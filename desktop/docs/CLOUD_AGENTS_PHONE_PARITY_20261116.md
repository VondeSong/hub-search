## 已完成的真实操作

| 项目 | 实际结果 | 证据边界 |
| --- | --- | --- |
| 选图、预览与移除 | 实体手机通过原生照片选择器选中原有真实图片，看到缩略图；打开完整预览、关闭、移除后重新选择成功 | 未把自动化键盘输入当成中文输入法验收；正式请求均为图片单发 |
| 发图时保留图片 | 发送后图片立即留在消息区，等待服务确认时仍能看到预览入口 | 本轮不代表所有图片大小、相机权限或完整视频均已覆盖 |
| 断网后恢复 | 实体手机关闭 Wi-Fi 后发送，首个截图仍显示“正在上传附件”；恢复原网络后同一发送成功、清除待发送状态并收到回答 | 没有点击原编号重试；没有观察到完整 180 秒超时，不能冒称本次实测了丢失回执后的手动重试 |
| 同包模拟器发图 | 使用用户提供的真实异常截图，通过原生照片选择器发送至同一正式会话，完成真实回答 | 与实体手机使用同一 APK；系统照片选择器外观随 Android/厂商不同 |
| 材料、成果与过程 | 实际会话的附件、已完成回答及独立运行过程弹层均可打开；最终弹层显示四条真实执行记录、约 16 秒及“已完成” | 没有为检查保存动作重复写入速记或源笔记 |

前后服务记录由 13 个会话、25 轮消息、10 个附件变为 14 个会话、29 轮消息、14 个附件：本轮共发起四次真实图片请求，每次对应一条轮次与一个附件，全部完成；其余是同一会话的诊断与补验，没有把重复请求当成独立质量样本。最后一张 PNG 在服务端的 313,730 字节及 SHA-256 与用户提供文件一致。

## 公开摘要的实际发现与处理

上轮协议桩检查只断言线程配置为 `detailed`，不能证明正式运行时实际返回公开摘要。本轮读取官方 Codex 0.167.1 自带协议 schema，并检查真实会话的公开配置元数据后，发现其实际摘要模式仍为 `none`。

先补充逐轮 `turn/start.summary = detailed`，再以模型目录所列的 `low` 强度补验，均未取得公开摘要；最终移除了强度试验，继续沿用原来的模型默认强度。当前模型目录标记使用 Responses Lite，四轮实测均没有返回可显示的摘要。这里只记录实际结果，不据此断言所有模型或未来版本都不支持摘要，也没有修改官方模型目录来伪造能力。

最终保留协议中的公开摘要请求，并补齐由真实操作确认的执行记录：

1. 已准备选定图片或收到本轮文字。
2. 已连接 Codex，并确认订阅登录。
3. 已建立或恢复原对话。
4. Codex 已接收本轮请求。

记录只在对应操作成功后写入，进入原有过程面板；已有模型进度和公开摘要仍独立保留。没有摘要时显示“本轮没有可显示的模型摘要”。因此，本轮完成的是可核对的执行过程反馈，**没有把 Claude 式思考摘要记为已在当前 Codex 运行时通过**，也没有生成模拟思考文字。
