## 真实任务和核验结果

任务使用两版 T29 主清单和一份 T28 单元格明细 CSV。先核对 T29 版本差异，暂留前门门压传感器与车型分配待核对。随后分段抽查 T28，最后交付两部分的核对结果。两版 T29 的首轮结论与独立复算一致，部件数 68 → 75，新增 7、删除 0、内容修改 7、仅换行位置 34、不变 27，共 18 个内容单元格变化。

## 整改及复测边界

Hub 成功生成文件成果后，原会话检查点只更新了图表状态。下一轮看到新的文件成果，就因检查点不匹配重新建立提供方会话。修复允许已交付的一轮接纳该轮自己生成并校验过的新增文件成果。旧成果及其报告、执行能力、授权和来源检查继续参与会话复用判断。来源、旧成果或修订状态变化仍可以触发重建。

初次试跑另遇到模型脚本输出多个 JSON 对象，以及只读计算后直接答复未调用正式交付接口。后续把单一 JSON 输出与正式交付要求写入验收提示，这两项在七轮复测中均通过。压缩后续聊第一次打开原工作簿时触发损坏的可选自定义属性错误。后台驱动仍运行时在桌面另一个进程打开同一对话，界面将后台执行识别为中断。已保留该轮在中断前的准确复述和失败记录。

交接正文首次保留了七段 T28 抽查范围，并明确标出当时缺少分类和异常数汇总。独立逐条回读复核为 Wire list 14,269 条、原始记录 1,131 条，抽查样本坐标行号异常 0、含跨批重复坐标 0。将这些回读结果补给同一对话后，助手发布了汇总补充，会话状态为已完成。它只覆盖已抽查的 15,400 条。

针对源码的复用检查 4 项、原生压缩与分析相关 21 项通过，另有 5 项按既定条件忽略。Rust 格式和 Git 差异检查通过。后台驱动、真实原件路径、完整回执及独立核对记录保存在本机忽略目录 `desktop/.local/auto-compaction-20261118/`。
