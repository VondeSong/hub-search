# X 书签与喜欢收集

入口为 Hub 的“收集与待读”；移动布局位于“浏览”中。手机以阅读、状态和标签修改、归档及恢复为主，不提供来源采集连接、资料库保存位置或删除管理。

## 连接与读取

书签和喜欢是两个独立来源，各自保存连接、账号、游标和限流状态。书签原有连接继续可用。喜欢连接在 X 的历史 → 喜欢页 (`https://x.com/i/history/likes`) 复制 Network 中返回帖子列表的 `Likes` 请求；书签使用 `Bookmarks`。两个来源都使用 Copy as cURL (bash)，支持 Vivaldi 的 `curl --url` 写法。Hub 只解析请求，不执行命令。

只接受 X 官方域名下的 GraphQL GET 请求。喜欢请求的 userId 必须与当前登录账号一致。凭据保存在设备凭据库，不进入数据库、导出页面或附件请求。媒体请求不携带登录 Cookie，并且不跟随重定向。

重新同步从第一页扫描，继续上次从已提交游标继续。每页内容和游标在同一事务提交。每轮最多 100 页，间隔至少 1.5 秒。401/403 提示更新连接；429 记录冷却时间，冷却后按自动同步计划重试，也可手动重试。不会删除已取消书签/点赞的本地记录。未知响应与异常分页不会当作成功。

## 可配置的本地保存位置

在“保存位置”选择：

- **Hub 本地数据库**：正文、媒体地址和阅读状态保存在当前本地数据库，下载附件放在当前 Hub 数据目录的 `collection-files/99_Meta/assets/X_assets`。数据库只记录附件位置，不把大视频塞入数据库字段。
- **Obsidian 库**：用户选择已存在的库根目录。自动创建 `X/书签`、`X/喜欢`、`99_Meta/assets/X_assets`；每条推文按稳定 ID 创建一个 Markdown 页面，重复同步复用同一路径。两种来源中都存在的推文在各自文件夹各有一页，附件共用。Hub 仍保留标准化内容缓存、阅读状态和导出索引，以支持搜索、重试和切换位置。

选择后会补写已有内容；同步完成后也自动保存。本地数据库和 Obsidian 均**不限制单个附件大小，也不限制一轮下载总大小**。可以关闭自动下载，只保留媒体链接。切换位置不会删除原位置的文件；优先流式复制已经下载到本机的完整附件。

库文件夹改名或移动时，在“保存位置与同步频率”中使用“重新定位原库”，选择原库的新位置。Hub 核对原笔记的内容或来源身份后，统一更新保存根目录、已登记附件路径及资料库监听，保留原有副本标识、保存历史和手动修改保护；不会复制或改写笔记。这个入口也支持尚未加入 Hub 资料库列表的保存目录。旧位置失效时，界面可建议经过核验的同级目录，由用户选择；多个候选不会自动采用。正在写入时需等待结束再定位。

“选择文件夹”用于更换新内容的默认保存库，与重新定位原库分开。即使旧库离线，也可以另选默认位置；旧内容仍关联原库，不会自动迁入新库。

页面属性按以下顺序生成：

```yaml
---
喜欢: false
标签: []
状态: "待读"
发布时间: "2026-10-05T10:00:00"
作者: "作者名 (@handle)"
地址: "https://x.com/i/status/123"
创建日期: "2026-10-05T11:00:00"
---
```

喜欢来源固定为 true；书签使用响应中的 favorited。历史缓存没有该字段时暂为 false，重新同步会更新。标签是自定义列表；状态初始待读，Hub 标记已读后更新未被手动修改的页面。发布时间为原推文时间，创建日期为首次导入时间，采用本机时区。未知发布时间留空。

保存页面前核对上次生成的文件摘要。用户手动修改过正文或属性、或存在不属于本次导出的同名页面时跳过并提示；不会覆盖用户笔记。Obsidian 修改暂不反向同步到 Hub。路径校验拒绝越界目录和指向库外的链接。页面与附件先写临时文件，再提交到最终文件名。

## 图片和视频

视频选择 JSON 中最高码率的 MP4 直链，流式写入磁盘，不将完整大视频读入内存。只接受 pbs.twimg.com / video.twimg.com 的 HTTPS 媒体直链。没有 MP4 直链的媒体保留原链接。图片和视频按 URL 摘要命名，共用已完成的下载。界面区分“本地”与“原链接”，可直接打开本地附件。

暂停会停止后续文件；等待中的网络读取最多 30 秒无数据后超时。失败或中断不会留下冒充完整附件的最终文件。点击“补写 / 重试”会复用已下载的完整附件，对失败文件重新下载；**当前不支持视频文件内部的断点续传**。磁盘空间不足会显示失败并保留正文/原链接。

## 同步边界与验证

阅读正文、状态、标签、已登记附件和只读资料库副本记录已接入当前活动 OSS/WebDAV 服务，设置与边界见 [Hub 云同步](CLOUD_SYNC.md)。手机显示本机已有或实际同步接收的阅读数据；附件需按现有下载策略获取，不代表电脑资料库目录或全部文件已复制到手机。云端历史保留，只有显式维护入口可以清理被完整核验覆盖的不可变记录；云同步不上传 X 凭据，也不在接收设备自动执行来源取消或资料库保存。

退出应用后的系统后台扫描、外链全文和完整 X Article 仍不在当前范围内。前文本地采集/Obsidian 保存的附件限制不等同于云附件策略；云传输有独立的类型、大小、网络、每轮/每日额度和缓存上限。

定向测试包括：请求规范化与账号限制、书签/喜欢隔离、长文/视频解析、游标事务、重复导入；临时库中的目录结构、七个属性的顺序和类型、重复写入、手动修改保护、越界路径；没有 Content-Length 的 65 MiB 视频流保存，以及错误媒体不留下最终文件。界面测试覆盖来源切换、保存位置、补写、连接凭据清空与失败提示。

2026-10-05，0.16.195 已在真实账号导入 544 条书签。新功能的构建与在线验收结果以交付记录为准；内部接口可能变化，测试不代表可获得所有历史内容。

## 0.16.198 数据库视图与后台同步

收集页沿用任务页的来源统计、视图标签和筛选摘要。支持列表、表格、按待读/已读分组的看板，点击内容在右侧阅读；窄屏切换为详情。可新建、命名、复制、删除视图，分别保存来源、阅读状态、内容类型、排序、密度和表格显示属性。视图保存在本机界面设置中。筛选与排序先作用于整个本地数据库，再每页显示 60 条；看板分组数量明确标为“本页”。

默认自动同步间隔为 30 分钟，在保存位置设置中可改为 5–1440 分钟，0 表示关闭。书签与喜欢共用间隔，各自记录最后尝试、成功、分页和冷却状态；每 15 秒检查是否到期。旧连接首次升级后从第一次检查开始计时；同一来源的一轮工作结束后重新计时。到期时从第一页扫描，读取与附件保存串行执行，上一轮大文件仍在下载时不会叠加启动。暂停操作会推迟自动启动至少一个设定间隔。登录失效后停止该来源自动重试，重新保存连接恢复。程序在托盘运行时仍可同步，完全退出后停止。

保存位置设置持久化成功后，命令立即确认并关闭弹窗，后台任务由应用持有，切换 Hub 页面不影响执行。主界面显示已处理/总条数、剩余条数、本轮下载量和当前附件下载量，可暂停；详细结果折叠显示。读取阶段总页数未知时使用不定进度。下次打开应用保留已完成文件并提示中断记录，未完成附件仍从头重试。更新同步频率不改变页面内容；大文件仍不限制大小。

收藏、X 喜欢与 Telegram 仍在同一个数据库中。预览页增加「保存到」，每条收藏只选择一个正式资料库。Hub 保留浏览所需索引与附件缓存，不构成第二个正式保存位置。

- Hub 或尚未添加到 Hub 的 Obsidian 目录不显示资料库图标。添加对应 Obsidian 库后，以实际目录匹配显示图标和名称。
- 表格、列表、画廊和卡片属性支持显示「保存到」，排序支持该属性。当前支持 Obsidian、Craft 和滴答资料库。
- 更改同步设置中的默认目录只影响新收集内容；原有条目保留已保存位置。移动原有条目需在预览属性中选择资料库。
- 归档把条目移入「归档」视图，保留正文、附件、标签和原阅读状态；可以从状态菜单恢复。
- 删除先展示受管副本范围，再移出收藏数据库，后台删除对应 Obsidian 页面、专用附件及已登记的 Craft 页面或滴答任务，并清理对应本地索引。共享附件或其他笔记引用的附件保留；不删除未登记的同名内容。
- 删除后只保留必要的来源墓碑和未完成清理记录，避免 X、Bot API 或 tdl 历史把同一条内容重新导入。删除不会取消 X 书签或喜欢；「放弃」仍使用原有按频率同步的取消收藏规则。
- 迁移先保存并核验新页面和全部附件，再清理旧副本，最后提交新的正式位置。目标不完整、离线或旧页面有手动修改时保留旧副本，处理记录可重试或核对范围后确认清理。

### Craft 与滴答

运行时读取实际安装的 `craft-general-archive` 或 `content-to-tasks` 及参考规则。模型只生成只读结果；宿主核验真实资料库、来源版本和附件身份，并作为唯一写入者执行保存。Craft 归档与行动转换可以查看方案；0.16.220 起，已经选定滴答位置的纯参考内容直接保存，不再要求二次确认。凭据不进入模型上下文。

Craft 根据实时目录与承载页定位，创建独立受管子页面或新文档，保存完整正文和原生附件，读回后才迁移。删除新建 Craft 文档使用其废纸篓接口；嵌入的受管子页仅删除该子页，不删除承载文档，同时刷新承载文档的本地内容。

滴答读取实际清单与候选任务，根据来源和用户目标生成行动、完成条件、依据与原生检查项。自 0.16.219 起，选定滴答保存位置后，没有可提取的行动也会生成一条参考任务：原文地址作为任务名，完整正文、有序引用和回复由宿主保留，原附件全部关联这一条任务，不要求先补充用途。不生成虚构行动或检查项，也不自动设置日期或完成任务。没有地址的资料沿用原题或文件名；连接、清单或明确行动的关键约束有缺口时仍提示实际问题。原生附件复用网页登录态和私有上传适配器，先核对附件账号与任务账号，持久化上传标识，再核验文件字节、任务引用与读回内容。上传超限或失败显示部分成功，保留原内容，不通过删除任务掩盖附件失败。

首期开放行动、清单、正文、原生检查项及附件；原生排程、提醒、循环、优先级、责任人、子任务和依赖尚未开放。必要约束依赖这些能力时返回待补充方案，不将普通正文冒充原生字段。图片实际送入模型最多 6 张；文本文档和 PDF 有读取上限，音视频未转写时明确列出缺口，不据此编造任务。

方案与执行阶段分开，任务及文件身份在写入后登记。响应丢失时禁止重新创建，先核对实际页面或任务 ID 再关联恢复；重试保留用户对任务正文和完成状态的修改。成功迁移后的收藏源同步继续更新 Hub 材料缓存，不会周期性重新转换或覆盖用户维护的 Craft 页面和滴答任务。

### 本地验证边界

自动检查使用隔离数据库和临时专用目录，验证生命周期、墓碑、共享文件保护、迁移保护、真实目标 ID 校验以及前端审阅流程。构建验证不操作个人资料库；真实账户的归档正文、原生附件上传及删除由界面中的具体操作确认后验证。

### 参考内容直接保存与登录复用（0.16.220）

提取不到行动时，参考内容直接写入选定滴答清单：原文地址作为任务名，正文保留作者、完整内容、有序引用和回复，原附件使用现有私有上传通道。已有本地缓存不重新下载，已有参考方案可直接沿用真实清单和附件身份继续保存。正文不带 Obsidian frontmatter、模型依据、完成标准或操作检查说明。

后台优先复用 Hub 主窗口的有效网页登录会话，并核对目标账号；现有附件登录窗口的有效会话可作为候选。界面仅在实际检测到附件会话缺失、失效或账号不匹配时显示登录入口。超限、限流、超时和一般服务错误报告对应问题，不要求重新登录。未知创建结果继续要求关联真实任务，已有部分写入沿用绑定和附件 ID 补齐，不盲目重新创建。

### 旧方案取消与授权恢复（0.16.221）

取消方案同时覆盖待确认、失败及旧版本的待补齐记录。只有当前目标尚无受管副本时才移除该处理记录，保留来源正文、本地附件、原保存位置和其他资料库的已登记副本；已写入部分内容或结果未知时保留恢复关联，并在方案弹窗内显示原因。写入前检查方案身份，取消或重新选择位置后，旧流程不能继续写入或更改新处理记录。

收藏保存不再把进程内会话暂未恢复当作未授权：先等待启动恢复，并在需要时通过设备凭据库中的现有授权和刷新令牌重建滴答连接。正文的 OAuth 连接与附件的网页登录会话是两种认证方式，附件仍复用现有 Hub 会话，无需另建账号。

附件校验识别网页同步响应中的 `projectProfiles`、`syncProjectBean` 的新增/更新清单及 `inboxId`。不把任务、已删除清单或未知/空响应当作清单访问证据；收件箱别名需要核验双方实际收件箱 ID，不能把不同账号的收件箱 ID 当成相同。响应无法核验时说明实际问题，不以空解析结果宣称账号不匹配。

### 部分保存也可取消及附件补齐（0.16.222）

取消方案表示停止后续保存，不删除收藏原文或本地附件，也不自动撤回已经创建的滴答任务或 Craft 内容。目标已有受管副本时，处理记录进入 `cancelled`，保留方案、远端对象身份和附件映射，界面显示“查看已取消记录”，允许重新选择保存位置。自动恢复、按频率处理、直接批准和通用重试均不续传已取消方案。新保存只替换已取消的处理记录，保留远端绑定供去重、迁移或删除清理；重新选择原保存位置也能处理这些残留副本。正在写入及结果未知的操作仍需等到结果可核对后处理。

新附件先持久化稳定上传标识，再上传、读回并核对原文件字节，最后写入任务的附件引用。不能先下载一个仅在本地预留、还未上传的标识：服务可能返回 HTTP 500 而非 404，使空任务停在待补齐。旧映射重试时先核对网页同步任务的附件登记；完整任务省略空附件数组时结合正文引用判断，不把不完整或异常记录当成文件不存在。已有附件不重复上传，不明确的响应仅在读回确认同一文件后继续。

附件读回对暂时的 404、限流、服务端错误及网络中断最多尝试三次；401/403 和文件字节不同立即停止。持续 HTTP 500 报告服务错误，保留任务、原件和稳定标识，支持继续补齐或取消，不误报为账号登录问题。定向测试使用隔离数据和本机 HTTP 服务，覆盖登记状态、部分成功后的取消、取消记录不可自动恢复、改选保存位置、读回重试和完整性核验；不操作个人远端内容。

### 滴答任务更新参数与属性弹层（0.16.223）

收藏内容与附件引用写入滴答时，更新请求同时提供 MCP 顶层的 `task_id` 和任务对象中的 `id`，二者取同一已登记的真实任务身份。内部 `task.id` 不能替代路由必填参数。待补齐沿用已有任务和附件映射，更新只提交所属清单和受管正文，不重新创建任务或重置其余属性；继续读回同一任务核验内容及附件引用后才提交保存位置。

状态、标签和保存资料库的二级弹层在点击外部、焦点移出当前属性或窗口失焦时关闭；内部选项间移动焦点不关闭标签编辑，也不因关闭弹层触发保存、迁移或删除。标签输入失焦时只关闭选项，不自动创建尚未选择的标签。

定向验证通过本机 MCP 模拟服务检查真实更新请求与读回流程，验证顶层路由身份、正文附件引用和原任务属性保留。界面检查覆盖内部操作、键盘离开、无新焦点的失焦、窗口失焦和属性间切换，不操作个人滴答任务或 Craft 页面。

### Craft 自动归档、实际保存位置与图标（0.16.224）

在收藏与待读中选择 Craft 资料库即授权这条材料的归档，无需再次确认宿主方案。模型继续读取 craft-general-archive 的定位与整理规范并只生成方案；宿主核验真实目录、锚点、来源版本和附件后执行。有效的 planned 方案直接保存，已有无错误的待确认 Craft 方案也进入自动保存；需要补充关键信息、已失败、部分写入、结果未知及已取消的记录不会自动续传。滴答行动任务继续原有审阅流程。
