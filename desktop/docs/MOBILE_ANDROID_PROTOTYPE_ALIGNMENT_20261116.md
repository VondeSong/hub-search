## 实测修复

- 文件输入的 `cancel` 事件会冒泡；新建和旧记录弹层现在只处理自身的取消事件，取消选图不再误关整层。原型也同步修复。
- 已打开输入层时重复点磁贴，会再次请求当前编辑器聚焦。Android WebView 默认在原生焦点恢复时选择第一个可聚焦元素，实际会抢到关闭按钮并收回键盘；使用 [WebSettings 的焦点控制](https://developer.android.com/reference/android/webkit/WebSettings#setNeedInitialFocus(boolean))，保留当前 DOM 焦点，再在窗口与编辑器就绪后请求 IME。
- 自动同步暂停时，输入层及保存回执明确提示暂停和原页重试，不再承诺后台继续上传。
- 旧记录尚在读取编辑草稿时，返回可以关闭当前层，保留未读完的持久草稿；迟到的读取结果不会重开编辑器或清空正文。

## 变更协议

原 `records/<id>.json` 与 `receipts/<id>.json` 保持不可变；编辑追加 `journal/edits/<operation-id>.json` 与 `journal/edit-receipts/<operation-id>.json`。每项带父版本、修改前后正文/日期/附件及删除状态，回执核对确切内容哈希。按父版本依赖重放，避免云清单排序或设备时钟改变结果。

手机只提交变更并核对回执，指定电脑负责受控改写自己原先写入的 OS 区块。旧版本、来源手工修改、分叉、命名空间变化和附件权限均有检查；未知结果不会通过重复追加掩盖。新旧客户端混用时，需要更新电脑原生接收端才能处理编辑回执。

## 验证方式与证据

模拟器检查使用标准 Android instrumentation，操作实际 MainActivity/WebView、输入法、系统返回、添加磁贴确认与系统分享；未替换生产 IPC。系统相册的打开/取消与选中文件后的实际存储分别检查，不把构造文件输入事件写成系统相册选图成功。

冷启动由独立验收进程运行，先确认原客户端进程已退出，再点击真正的系统磁贴；随后用生产原生接口核对草稿并重新加载 WebView。独立验收 APK 只用于测试，不进入普通 Hub 包或 Release。

测试前保存已有草稿/个人偏好，结束后恢复；不对个人卡片评分。合成测试记录获用户授权，保存到真实应用数据；本轮成功创建的记录移入可恢复回收站，临时闪卡牌组删除。失效的早期截图、测试失败和恢复文件留在本机证据目录，未当作通过。

当前源码回归限定 `--dir src`。曾误纳入历史快照的两次运行已中止，不计入最终数字。原生检查中的真实 OSS 专用测试需要额外显式入口，忽略项不计为通过。
