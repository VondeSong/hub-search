# 知识库助手的真实脚本统计验收

日期：2026-11-17。接续 #14 的能力对齐讨论和 #56 的活动展示；不重开已完成的原生接入总范围，不把产品定位讨论缩成只做这一项。

## 结论

Hub 在“仅依据材料”、联网关闭、独立工作区和子代理均未启用的情况下，能够让模型编写并实际运行短计算脚本。它适合知识资料的计数、核对和整理；本轮不是新接通终端或 Python，也没有证明与 Codex 的全部分析环境等价。

使用日常真实库中两篇既有线束笔记完成同一聊天两轮任务。两次 `hub_compute` 均返回 `backend=codex-mxc`、输入和脚本哈希、完整 JSON 结果及 `businessWrites=false`。逐章合计与全文直接扫描一致，另用独立本地扫描核对；两轮 23 + 27 = 50 处引文逐字对应证据片段和当前原文，两篇来源正文哈希未变。当前工作没有业务动作草稿或写回，原图输入均为 0 字节。

发现并修复了两处展示问题：计算活动展开后仍叫“调用工具”，折叠组只叫“运行命令”；续问完成后历史列表仍缓存首轮的消息数。现在按结构化 `operation=compute` 显示“运行计算脚本”，使用终端图标，折叠、进行中和展开行共用同一文案规则；旧历史记录也按真实操作类型展示，不改写执行回执。打开历史时刷新真实列表，实窗已从旧的 2 条更新为实际 4 条消息。

## 用例说人话

1. “帮我看看这两篇笔记的图片和问题集中在哪些章节。请实际用脚本数，逐章列出图片引用、带问号的原文行和合计。”
2. “再跑一次脚本，把每章加起来和整篇直接数的结果比一比。没有问号也可能有问题，请指出这些线索，再建议先补哪三项资料。”
3. 展开工作过程、计算活动和完整工具记录，确认确实运行过；点历史记录的引用核对原文，再返回回答。
4. 从历史重新打开同一聊天，核对两轮结果保留。截图按实际步骤收集，不把完成后的截图当成执行中画面。

两篇材料分别为 2,497 和 2,624 字符，均完整读取。统计按二级标题分章，小标题并入所属章；独占一行的图片引用每次出现计一次，重复引用不去重；一行含中英文问号即计一条。第二篇没有二级标题，主口径按全篇处理，一级标题分布仅作额外定位，没有擅自更换口径。

## 保留的中间失败

首次真实流程驱动在首轮完成后失败：该驱动把 `nativeResponseDelivery` 记录数当作唯一交付条件。本次模型实际使用已支持的 `hub_finish` 交付，存在正式 `delivery`、`finishAcceptance` 和 `nativePublication`，所以该特定记录数为 0。未修改断言以把首次失败记成通过；第二轮改由正式 Hub 界面继续同一聊天，并独立核对脚本回执、交付与引用。驱动的第二个提示词因断言而未执行，不重复计算为额外一轮。

首次前端命令漏了项目的 `--dir src`，误扫描被忽略的历史副本目录，已中止；不计为通过。随后按正式入口运行上述 76 项。原始失败、停止和成功结果都保留在本地证据中。

## 能力对齐该怎么理解

| 用户要做的事 | 当前依据与边界 |
| --- | --- |
| 从选中笔记里计数、汇总、查重复、做一致性核对 | 短脚本能力已有，本轮用真实材料证明计数和双算法核对可执行。查重复等不同任务仍需自己的实测。 |
| 更长的数据处理、产生独立文件 | #14 已有另行授权的独立工作区。本轮未启用，不能把它与资料计算的权限混为一谈。工作区产物也不自动成为知识库保存回执。 |
| Python/pandas、Excel 多表、复杂图表、安装新包 | 本轮短计算入口实际运行 Windows PowerShell；没有验证这些完整任务。不能把“会写一段 Python”算作已具备对应运行环境、依赖、文件导出和可复现能力。 |
| 读取飞书原图、分析 PDF 页面 | 与脚本统计不同。上一轮已记录原图进入助手的缺口，本轮只是计数图片标签，没有补齐该缺口。 |

短计算的实现限制为 Windows、20 秒、输入含编码至多 131,072 字节、脚本 16,000 字节、完整 JSON 输出小于 16,384 字节；系统环境与网络受限。这些边界解释了它能处理哪类任务，不构成“Hub 无法运行脚本”的结论。更大数据、表格/图表导出和 Python 环境应按实际知识库任务单独验证，不为追求编程工具完整清单而扩大本轮范围。

本轮没有同条件 Codex 对照或昨日版本复测，不声称新增模型智力、全面提速或没有任何能力差距。两轮持久化运行起止间隔约 114.1、116.0 秒，仅为本次任务观察，不充当界面首反馈或正式性能对照。没有发布安装包、标签或 Release；日常 Hub 保持开发运行。

私有证据保存在忽略的 `desktop/.local/knowledge-compute-20261117/`：材料快照、原始失败日志、两轮正式记录、脚本及 JSON、逐引用核对、来源哈希、实窗截图和补充报告。业务正文、图像、数据库和私人报告不提交 GitHub。

补充报告为 13 页 PDF，附 10 张步骤截图，已逐页渲染检查；截图包另含两轮回答和核对摘要。历史消息数来自同次界面的可访问标题与正式记录，截图行内只显示时间，不把图片当作该数字的唯一证据。飞书发送回执在关联事项的最终评论中记录。
