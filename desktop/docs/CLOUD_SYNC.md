# Hub 云同步

## 当前交互与附件策略（2026-11-12）

云同步按已确认的 Craft 文档风格原型组织为「概览／同步设置／云连接」，诊断、恢复、来源清理、缓存与速记位置收进关联入口。一个立即同步动作覆盖已启用的闪卡、阅读与 OSS 速记；模块失败分别报告，继续处理其余模块，不以连接检查成功表示内容成功。

附件上传和自动下载各自按闪卡／阅读／速记选择图片、视频、PDF、其他及单个大小上限。设置只作用于下一次传输；未选或超限保留原件／云副本与已有下载，正文独立同步，放宽策略可补传。显式手动下载绕过自动偏好，仍受模块、网络、文件硬上限和校验约束。文件支持硬上限分别为250／100／20 MiB，不因输入偏好放宽。

新策略持久保存为 `cloud_attachments_<module>_v1`，字段 `upload`／`download` 各有 `image,video,pdf,other,maxMb`。首次读取从旧设备实际偏好保守映射，闪卡原按需保持全类型手动；阅读原关闭保持关闭，原自动仅图片/PDF且统一大小采用旧值较小者；速记保留原先全附件语义。两个方向独立保存，不改连接、删除标记或原内容。

每轮／每日传输额度已从日常界面及运行时准入取消，旧额度不再阻断阅读附件、正文／清单读回。保留原有限量分页、文件硬限制、缓存上限、网络检查、哈希校验与退避重试。旧流量账本只为诊断及降级兼容保留，不再充当用户预算；下文较早版本的每日额度验收记录是历史证据。

速记先接收正文和完整附件清单并写入日记，再按本机策略补齐附件。未下载项写成明确占位说明，Hub速记中仍可手动保存／下载；补齐后只替换自动生成的附件占位，保留人工修改，不重放正文、不恢复用户已删区块。上传正文与附件独立排队，正文已上传后仍可补传附件。已绑定速记的云空间阻止直接切换，直到统一迁移覆盖速记；旧连接和数据保留。


源码实现阶段验证（2026-11-12）：前端完整测试1935项通过、11项按既有条件跳过；相关原生测试159项通过，另有2项需显式启用的联调/fixture入口当时未运行。覆盖三模块双向筛选、旧偏好、补传、正文先写与占位补齐、人工修改及删除保留、取消预算、网络/缓存/硬上限、固定离线和迁移读回。生产前端构建、原生开发构建、改动文件格式及差异检查通过。Windows实际开发窗口已检查概览和同步设置；使用独立数据目录验证真实配置落库、重启保留、非法300 MB不保存、模块与方向独立，测试未操作个人云内容。该实现阶段尚未重跑真实云账户双端或Android实机；速记跨云空间迁移仍按上文阻止，不承诺完整日记库双向同步。

后续真实服务验收见 [2026-11-12 专项记录](CLOUD_SYNC_ACCEPTANCE_2026-11-12.md)：三个模块经真实 OSS 的两份独立 Windows 数据库传输已通过，包含方向、补传、反向更新与大小限制。Android 编译、包身份与实体设备验收分别记录，不能以 Windows 后端或模拟器结果代替手机实机。

Android 模拟器与 Windows 实际互传、三模块附件规则及断网恢复的后续检查见 [模拟器专项验收](CLOUD_SYNC_EMULATOR_2026-11-12.md)，其中记录本地来源上传、Android 原件发布和恢复状态刷新的修复；实体手机仍单独待验证。


本文件记录共享同步中心、阅读同步、来源恢复与长期维护的当前合同。闪卡协议与恢复细节继续由 [FLASHCARD_CLOUD_SYNC.md](FLASHCARD_CLOUD_SYNC.md) 维护。

当前交付验收分别记录在 [云同步后续联调](CLOUD_SYNC_FOLLOWUP_0.16.237.md)、[滴答专用清单联调](READING_DIDA_R5_0.16.237.md) 与 [本轮同步收尾](CLOUD_SYNC_CLOSURE_0.16.237.md)。下方有日期的阶段记录保留当时边界，后续实测结果以对应交付记录为准。

## 已确认的采集范围

不实施通用网页剪辑、Hub 独立添加链接入口或浏览器剪辑入口，也不增加“指定标签＋收件箱”组合筛选规则。滴答沿用已有的精确“稍后读”标签规则，在已授权清单范围内采集；不限定必须位于收件箱。资料库保存继续使用已有 Obsidian/Craft/滴答入口。

## 当前实现：共享入口与本设备策略

- 设置新增“云同步”，桌面和手机可见；闪卡的云按钮打开同一设置页。
- 连接配置、服务切换、手动同步、最近记录集中在全局设置。闪卡本地备份仍由闪卡页面的“备份与恢复”入口拥有。
- 本设备总开关、自动同步、闪卡与阅读模块开关分别保存。总开关关闭不会清除模块选择、自动偏好、云配置、已有内容或待同步记录。
- 关闭自动同步仍允许手动同步；总开关关闭时停止内容传输。模块开关控制日常同步；明确迁移包含全部模块，不因关闭某模块而遗漏其云历史，仍需开启总开关并确认其它设备已暂停。已下载附件继续可用。
- 保存开关与内容传输使用同一同步锁：如果已有传输，界面显示等待；保存成功才表示暂停生效。尚未启动的排队任务取得锁后重新检查策略。不会把“正在等待关闭”显示成“已经关闭”。
- 连接测试是明确的手动操作，暂停时仍可执行；它可能创建连接测试对象或 WebDAV 目录。不会因此开始内容同步。
- 云同步后刷新闪卡列表和统计，保留活动复习队列；只有用户明确恢复本地备份时结束旧轮次。
- 阅读默认关闭，支持阿里云 OSS 与 WebDAV；启用后可独立手动同步，或随全局自动偏好运行。阅读页面的云按钮打开同一设置页。

## 兼容与数据归属

控制层为 `src-tauri/src/cloud_sync.rs`，界面为 `src/CloudSyncSettingsSection.tsx`；连接表单为 `src/CloudConnectionOptions.tsx`，在访问设置时懒加载。

设备策略保存为 `cloud_sync_enabled`、`cloud_sync_auto`、`cloud_sync_flashcards`、`cloud_sync_reading`。第一次初始化从旧配置推导：已有有效云配置沿用启用状态，自动偏好沿用 `flashcard_sync_auto`；未配置的新设备默认关闭，阅读默认关闭。初始化幂等，之后不再从旧偏好覆盖新值。

原 `flashcard_cloud_provider`、OSS/WebDAV 配置、系统密钥、设备 ID、云对象目录、上传基线、待上传日志和远端合并协议保持兼容。现有 Tauri 连接命令保留名称，不建立第二份连接配置。旧自动设置命令更新统一偏好；只保存 WebDAV 连接且 `autoSync=null` 时不改变自动偏好。

总开关控制 Hub 云副本传输。资料库索引更新、来源采集、保存到 Obsidian/Craft/滴答是不同操作，继续使用各自设置。策略和密钥属于设备，不随内容同步。

## 阅读网络：当前实现

- 设置 → 云同步 → 阅读网络提供“不限制网络”“仅非计费网络”“仅非计费 Wi-Fi”。兼容旧设备默认不限制；选择限制模式时，必须确认当前已联网、系统标记为非计费，Wi-Fi 模式还必须确认网络类型。设置仅保存在本设备的 `reading_cloud_network`，保存等待当前阅读传输结束。
- 本机设置值损坏时暂停阅读传输并显示原因，仍可明确选择策略重新保存；不会因此阻止闪卡或连接测试。界面保存成功后忽略此前发出的旧状态查询，避免旧结果覆盖新策略。
- Windows 读取系统互联网连接配置和计费状态；Android 通过既有原生插件读取活动默认网络、网络能力和计费/流量限制状态，增加普通 `ACCESS_NETWORK_STATE` 权限。未支持的平台或读取失败时返回未知；限制模式暂停，不将未知或 VPN 推断为 Wi-Fi。系统的计费标记不等同于运营商账单，热点和 VPN 应以当前显示结果为准。
- `src-tauri/src/cloud_network.rs` 拥有策略与原生读取，OSS 与 WebDAV 阅读适配器在每个阅读 HTTP 请求发出前重新检查。正文、资料库副本记录、附件清单、文件上传/读回/下载、列表及分页均受约束，手动操作与自动同步一致。闪卡传输及明确发起的连接测试保留原有策略。
- 已开始的请求仍可能完成；网络变化会阻止后续新请求，不能承诺瞬间终止在途流量。被阻止的待同步内容保留；被网络策略阻止的附件保留待处理，不消耗用户预算（预算已取消）。
- 已验证的本机文件继续预览、检查和离线保留，不因网络被限制而重新下载。类型、大小、缓存上限及总开关/模块开关仍分别生效。只读取网络能力，不读取或同步 SSID、IP、主机名或网络标识。

## 阅读正文与状态：当前实现

- `src-tauri/src/reading_sync.rs` 拥有阅读协议、持久队列与独立调度；消费端仍为既有阅读查询，不创建第二份用户可编辑阅读库。
- 沿用采集条目的稳定 `item_key`。正文、状态、生命周期分别使用逻辑版本，标签逐个保存增删版本。同一字段冲突按逻辑计数和设备 ID 排序，不用设备墙上时钟决定胜负；归档可恢复，永久删除优先于离线旧修改。
- 编辑接口携带所见状态与标签基线，只应用用户实际改变的字段和标签，避免陈旧编辑器覆盖刚到达的云端改动。
- OSS 对象位于已有前缀下的 `v2/reading/v1/changes/<sha256>.json`，WebDAV 使用所配置目录下相同的 `v2/reading/` 布局；两种服务复用同一阅读协议与合并入口，与闪卡对象分离。上传内容先持久化，读回校验后确认；接收校验哈希和协议后，在同一 SQLite 事务中保存合并结果和已应用标记。中断可重试，不上传整个 SQLite。
- 单对象上限 2 MiB；每轮最多上传 100 个对象且正文批次不超过 32 MiB；接收最多 100 个新对象或约 32 MiB（最后一个对象可能额外增加不足 2 MiB）。读回校验、列表、请求重试另有流量。这是正文批次保护，尚非完整月度流量预算。
- 桌面运行时约每 60 秒检查一次。手机阅读仅在前台启动自动同步：打开或返回应用后，在既有约 5 秒调度周期内补同步；保持前台时沿用约 60 秒检查间隔。总开关、自动同步、阅读模块和网络策略仍须允许传输，后台不启动新的阅读自动同步，已经开始的轮次可以结束。手动同步不受前台自动调度门禁影响，仍受同步开关与网络策略约束。闪卡和来源采集保留各自既有调度。设置页显示运行状态、上一轮结果、待同步数量与错误，阅读页通过原有轮询读取最新数据。
- 云端接收只更新阅读数据，不调用 X 取消收藏、滴答删除或资料库导出。接收的条目/更新排除在自动 Obsidian 导出之外；桌面用户仍可明确选择单条保存。采集凭据、本机文件路径、外部写入队列、串帖采集游标均不属于同步内容。
- 手机保留阅读、状态、标签、归档和恢复，隐藏采集连接、内容刷新、保存位置和删除入口；后端同时限制手机删除及资料库写入。旧的保存位置设置与整库 Obsidian 导出接口也会在获取锁、修改配置或启动任务之前拒绝手机调用。云端引入条目的“放弃”不会创建来源取消队列。
- 删除记录接收后清理 Hub 正文，并取消未完成的外部副本创建请求；不删除接收设备上已有的外部副本。原设备明确发起的本地删除继续按原删除确认流程处理。
- 阅读附件文件通过下面的独立策略同步。阅读云同步模块启用时，滴答来源清理默认关闭；开启后也只有来源级完整恢复回执与删除前当前来源复核全部通过，才允许原有删除流程继续。此时仅关闭总开关或自动同步不会解除来源保护；缺失大附件、未知正文或历史成功记录均不能解锁来源删除。关闭阅读云同步模块时，沿用原来已验证本地副本的采集与删除流程，来源清理开关不是所有滴答导入操作的总删除开关。

## 阅读附件：当前实现

> 本节以下为早期阅读附件协议的兼容说明；本设备上传／下载偏好与额度行为以文首2026-11-12规则为准。

- 阅读开关下另设本设备附件开关，默认关闭。开启后默认按需下载，可选自动下载图片与 PDF。总开关、阅读开关和附件开关共同约束云端传输；已下载的有效缓存和原设备文件仍可离线使用。保存附件策略等待当前阅读传输完成。
- 只上传采集过程已经记录并保存到本机的原附件和缩略图，不额外访问文章中的第三方链接。实际文件头决定格式：JPEG、PNG、GIF、WebP 默认限 10 MiB，PDF 默认限 20 MiB；支持的音视频与 ZIP 需逐项手动上传或下载。未知格式跳过，单文件硬上限 100 MiB。较大文件还受单轮与每日额度限制，上传及读回所需额度约为文件大小的两倍。
- 清单记录条目、原始 URL、正文版本哈希、文件哈希、实际类型、大小和 ready/missing/skipped 状态，不包含本机路径。与正文协议分离，旧客户端可继续处理正文。对象在既有前缀的 `v2/reading/media-v1/manifests/<sha256>.json` 和 `v2/reading/media-v1/blobs/<sha256>` 下；正文改变后必须有对应新清单才能恢复附件，避免关联旧文件。
- 清单、待上传队列、失败原因保存在本机 SQLite。文件上传成功并读回校验后才发布清单；已有云对象也要读取实际内容验证，不能仅凭 HEAD 元数据确认。每轮至多准备、上传、接收各 100 份清单，自动下载至多尝试 100 个附件；未处理项保留待后续同步。上传和自动下载使用轮转游标，失败条目不会一直占据队首。
- 默认每轮附件额度 64 MiB、每日 256 MiB，传输前持久预留，失败也计入，按 UTC 日期递增重置；系统时间倒退不会重复重置当日余额。包括文件传输、上传读回及清单载荷，接收清单按单份 16 KiB 上限预留。**这不是运营商或云服务账单上限**：不包含常规正文同步、对象列表、请求头等流量；暂停自动同步后，打开未下载附件仍可能按需下载，需关闭总开关或附件开关才能全面阻止云端传输，或用阅读网络策略限制允许使用的网络。
- 下载先验证哈希、大小和实际格式，再原子写入数据库旁的 `reading-media-v1` 目录，交给既有阅读预览/打开入口。相同内容复用有效缓存，不重复下载；发现缓存损坏可重新下载校验，不改写采集文件或 Obsidian 副本。
- 本机缓存默认 512 MiB，达到上限停止新增下载，可提高设置中的额度或使用下面的缓存清理入口；不自动删除缓存和用户文件。中断留下的临时文件也计入容量。云端历史清单与孤立文件暂不自动清理。
- 阅读详情新增“附件云副本”，逐项显示云端已校验、待上传、策略跳过、原设备未下载和错误；原设备可上传/重新校验，接收设备可下载/校验本机附件。单项 ready 只表示该版本附件已验证过，不保证未来云端不会丢失，也不表示整篇完整恢复。

## 阅读缩略图：当前实现

- 同步正文中 `previewUrl` 引用且采集时已有本机登记文件的封面，复用附件清单、队列和缓存，不新增开关或存储目录。包含正文、回复和引用中的登记引用；不额外抓取网站封面，不生成或压缩图片。仅有远程缩略图地址而没有本机文件记录时，显示原设备未下载。
- 独立缩略图必须是实际 JPEG、PNG、GIF 或 WebP 图片，硬上限 2 MiB，同时服从用户单张图片上限；逐项手动操作也不能绕过。若同一个 URL 同时作为原附件，按原附件策略处理。缩略图与原附件共享网络限制、每轮/每日额度、缓存上限及内容哈希复用。
- 当前正文版本的已就绪云封面通过独立 `cloudPreviewUrls` 投影交给图库；`savedMedia` 仍只表示本机存在的登记文件。图库在封面接近可见区域时才按需获取缩略图，通过本机媒体预览入口显示，不因此下载原视频。总开关、阅读开关或附件开关关闭后不提供云封面能力；已有本机封面继续展示。
- 主动清理的缓存封面不因自动同步或再次浏览图库而重新下载，可在“附件云副本”中手动恢复。封面可单独离线保留；“本文离线”继续只检查原附件，封面成功不表示原视频或整篇可恢复。正文变化后，旧清单不用于新封面。
- 继续使用 `media-v1` 格式 1，不在清单增加角色或本机路径字段，正文哈希不变。接收设备需升级才能识别独立封面；旧客户端仍能处理正文和原附件，但尝试自动下载新封面清单时可能报告 URL 不属于当前附件。

## 本机离线保留与缓存管理：当前实现

- 阅读附件可“离线保留”或“下载并离线保留”。先通过既有下载入口验证实际文件，再保存保留状态；失败时显示原因，不提前显示“已离线保留”。未下载内容仍受总开关、阅读/附件开关、类型限制和传输额度约束；已下载的有效附件可在同步暂停时保留。
- 保留按文件内容哈希生效，同一文件用于多篇文章时共用一份缓存、共同受到保护。保留状态属于本设备 SQLite，不同步到其它设备；取消保留只撤销清理保护，不立即删除文件。正文或附件版本变化不会自动把旧保留转移给新文件，旧保留可在设置中单独取消。
- 设置 → 云同步 → 阅读附件 → 本机阅读缓存显示当前文件容量、保留容量、可清理容量及保留列表。原设备采集文件与资料库文件不属于本功能的缓存管理范围；保留列表即使原文章已删除仍可管理，文件缺失时显示提示。这里是单附件保留，不宣称整篇文章完整离线可恢复。
- 清理采用“预览 → 确认”，预览签名绑定候选文件名、哈希、大小、修改时间和保留状态。确认时在阅读同步锁内重新枚举；变化则拒绝旧预览。与下载/保留互斥，只清理登记的普通缓存文件；跳过保留项、待上传文件、未知文件、临时文件、子目录、符号链接和 Windows 重解析点。旧版本已记录的缓存经实际字节与格式校验后接管，不能仅凭文件名接管任意文件。
- 清理成功后移除指向该文件的阅读缓存记录，保留正文、标签、阅读状态和云端副本。删除前持久化本机清理意图，自动“全部下载”跳过这些内容，避免清理后马上占回空间；用户再次打开或主动下载该附件，校验成功后取消这项限制。被占用的文件报告未清理，可再次预览并重试。
- 容量统计为缓存目录中普通文件的逻辑字节，不等于磁盘实际释放量；未知子目录和特殊文件仅报告数量，不递归扫描或删除。外部程序移动、破坏保留文件或云端副本仍可能导致无法恢复，后续来源清理依旧需要整篇恢复回执。

## 本文离线检查与批量下载：当前实现

- 阅读详情在桌面和手机新增“本文离线”。先主动检查当前已同步正文及登记附件，再展示已校验数量、保留数量、预计新增文件载荷和逐项原因；打开阅读详情不会自动执行整篇下载或文件哈希检查。无附件的正文也可以检查。
- 默认只批量下载图片和 PDF；音视频与 ZIP 需要勾选“同时下载音视频和 ZIP”，仍遵守现有类型、单文件大小、每轮、每日和缓存上限及阅读网络策略。整批共用一次附件额度，不为每个文件重置额度；预计大小按内容哈希去重，已存在的共享缓存可能进一步减少实际传输。请求开销另计。
- `src-tauri/src/reading_sync/media/offline.rs` 复用附件清单、实际字节校验、下载和离线保留，不另建一份文件库。范围绑定当前正文哈希与清单版本，预览摘要还包含云命名空间、本设备附件策略、音视频选择及本机文件/保留状态；执行前变化则要求重新检查，执行中正文变化则停止关联旧附件。
- 单次最多检查 100 个登记附件、清单大小合计最多 512 MiB，超过范围明确拒绝批量操作并提示逐项下载，不悄悄截断为“完整”。下载前持久保存本机批次与范围；每个成功附件立即校验并离线保留，部分失败仍保留成功项。重启后未结束的批次显示中断，用户重新检查后可继续；不在后台自动重放批次，已完成文件复用且不重复计费。
- 新下载与缓存保留、清理及阅读同步共用互斥边界。本机有效缓存在总开关关闭时仍可检查并保留；需要网络的新下载必须通过总开关、阅读和附件策略。原设备有效文件只验证，不接管、移动或删除；缓存保留可在既有设置中逐项取消。
- “可离线使用”只针对检查时的当前已同步正文和全部登记附件，并要求缓存附件已保留或为已校验原设备文件；缺失清单、跳过附件、下载失败、损坏文件，以及已知不完整的正文/引用/回复均不能通过。缩略图、原文网站及链接页面不在范围内，新正文也不会自动继承旧的完整性结论。此结果不是来源级恢复回执，不能据此授权滴答原项删除。

## 云端恢复检查：当前实现

- 桌面和手机阅读详情提供“云端恢复检查”。打开详情不发起检查；先预览当前已同步版本的范围和预计载荷，再明确执行。当前正文、状态和标签需已同步，合并后的完整快照需上传完成；否则提示先同步阅读。它与“本文离线”分开，不把本机文件、保留状态或历史 ready 清单当作当前云端证据。
- `src-tauri/src/reading_sync/media/recovery.rs` 实际读取既有 `reading/v1` 正文对象，验证 SHA256、协议和条目身份，再通过正式合并/投影入口在空的内存数据库恢复正文、状态、标签和原附件引用。每个可检查的当前原附件清单也实际读取和验证，原文件按内容哈希去重读取并验证大小与实际 MIME；同一文件本次失败也复用该失败结果，避免重复读取。每次显式重新检查均重新读取云端，不借用本机缓存。没有新增云协议、文件缓存或离线保留。
- 原附件包括正文、回复和引用中递归登记的原地址；缩略图不计完整范围。未知或已知不完整正文、缺失引用/回复、空原附件地址、缺失清单/文件、策略跳过、超限或未明确包含的音视频/ZIP，都不能通过完整检查。纯正文可以单独通过。有原附件时需开启阅读附件同步，音视频/ZIP 需勾选；单次最多 100 个原附件，规模检查按单项至多 100 MiB 累加并限制为 512 MiB。超大的清单可展示部分检查范围，原文件仍受单文件上限限制，不能算完整通过。
- 总开关、阅读模块、活动 OSS/WebDAV 云空间、阅读网络策略、类型/单文件大小及每轮/每日额度继续生效。手动检查不受自动同步开关限制。恢复检查的正文、清单和去重原文件载荷**全部计入现有附件额度**，不另设额度或重置余额；请求前按载荷上限预留，已预留请求即使失败也不退还，执行前被开关或网络策略拒绝则不预留。预估只针对当前可检查的文件载荷，请求头等开销另计，异常响应不构成账单上限。
- 预览摘要绑定云空间/连接配置、完整正文快照、原附件清单、附件策略及音视频选择；执行前改变则拒绝旧摘要，执行中改变则撤回检查结论。接受操作后持久记录本机检查尝试和终态；新尝试取代旧成功，部分结果保留逐项原因。重启后的 running 显示中断，不自动重放。历史成功只作当时时间点的记录；新正文、清单或策略变化后不显示为当前通过。
- 界面同时绑定当前条目的正文、状态、标签及生命周期版本；相同条目发生本机刷新也立即撤回旧结果并忽略在途返回。相同内容的列表轮询保留结果，不触发自动云端请求。
- “完整通过”只确认当前已同步聚合快照及全部登记原附件在本次检查时可读取和恢复；不扫描全部云端历史证明最新全局状态，不保证未来对象持续存在，不验证原文网站、外部链接页面或资料库副本。独立版本检查不能授权来源删除；来源清理使用下面的独立凭证。

## 跨设备资料库副本记录：当前实现

- 阅读详情在桌面和手机显示“资料库副本记录”，区分本机与其他设备。只从真实 Obsidian 导出回执、已验证的 Craft/滴答文档回执生成记录；保存位置选择、待执行任务以及附件回执不算正文副本。
- Obsidian 根据原设备上的文件是否存在区分“已有保存记录”“附件待补齐”“未找到文件”“暂无法确认”；不每轮读取整篇文件校验内容。Craft/滴答显示历史保存回执，不再次访问外部服务检查当前可用性。所有状态都不保证最新正文、全部附件或完整恢复。
- 同步内容仅含条目身份、设备标识、资料库显示名称、散列副本身份和状态；不含本机路径、文件名、资料库 ID、外部页面 ID 或操作队列。设备名称由平台和设备 ID 短码组成，不读取主机名；资料库名称无效时回退到通用名称，不从路径取名。
- `src-tauri/src/reading_sync/copies.rs` 在阅读正文之后、附件之前运行，沿用总开关、阅读开关和阅读同步锁，不依赖附件开关。对象位于 `v2/reading/copies-v1/changes/<sha256>.json`，与正文、附件协议分离，旧客户端可继续处理原有对象。
- 每台设备独立发布每个条目的副本清单快照，按逻辑版本合并；空快照撤回该设备的旧记录，过期重放不能恢复它，也不能覆盖其他设备的记录。待上传数据持久保存，接收校验对象哈希与协议后事务提交。接收只更新独立展示表，不写入本机保存映射或创建来源/资料库操作。
- 单条上限 64 KiB、128 个副本；每轮最多准备、上传、接收各 100 条，剩余后续处理。每个方向载荷上限约 6.25 MiB，上传核验、对象列表与请求开销另计；**不计入附件每日额度**。无变化不重新发布，界面“记录更新于”表示清单最后变化的设备时间，不是在线心跳或当前存在证明。
- 其他设备的记录仅供查看，不提供远程打开、保存、迁移或删除。保存设备离线期间，其他设备可能仍看到旧记录；需要回到原设备管理。副本记录不作为滴答原项清理的恢复证明。

## 服务切换边界

活动云服务切换、活动 OSS 位置变化及活动 WebDAV 目录/账号变化均经过全模块迁移。持固定顺序的闪卡与阅读锁，先排出正式待上传数据，合并目标闪卡，再复制阅读正文、原附件、清单、来源凭证、资料库副本、设备日志与检查点。目标逐项真实读回、原附件依赖闭包及当前范围复核通过后，最终事务再次核对本机内容与连接版本，才保存活动配置。失败保持原服务和配置，原云对象不删除。

迁移复制与核验使用独立持久进度，已复制不等于本轮已核验。每轮有界处理，阅读网络和每日额度继续生效；未完成时保持相同目标配置并再次执行，可跨重启或次日继续。正文、引用或非设备历史范围变化会使旧核验失效；设备日志仅严格追加时，将新增记录纳入后续核验，不重复作废全部已读取历史。最终仍重新核对两侧完整清单及 WebDAV 可变闪卡快照，已完成或失败的旧核验不冒充新核验。模块开关不排除迁移内容，总开关必须开启；其它设备需先完成同步并暂停编辑，迁移后逐台配置相同目标并恢复同步。旧云对象和历史保留，不自动撤销旧服务授权。大附件没有分块续传，单个文件仍遵守既有硬上限。

## 滴答来源恢复与清理

- 桌面阅读详情可明确预览与执行“滴答来源恢复核验”，不在打开详情时运行。凭证绑定当前账号、任务身份、原始来源快照、正文哈希、完整原附件 URL/内容哈希/格式/大小库存、云空间与策略。原始任务快照和库存保存到 `v2/reading/source-v1/<sha256>.json`，没有新增本机文件库。云凭证包含原始来源内容，仍受云目录权限保护。
- 必须实际读回来源凭证、当前正文与全部原附件，逐项校验内容身份和实际格式；缺失、损坏、策略排除、未知或不完整来源、子任务、超限等均保留原项。缩略图成功不代替原视频或全部附件。上传及验证载荷计入现有阅读额度。
- “设置 → 云同步”中的滴答来源清理默认关闭，仅桌面可开启；它是阅读云同步模块启用时的附加保护。此时暂停总开关仍保留来源；关闭阅读模块则遵循原来已验证本地副本的流程。开启清理后沿用既有采集与删除流程；它不会因手动核验按钮直接删除来源。真实删除前另做当前云验证，生成仅存于本次在途操作的短时许可；历史数据库成功状态不能单独授权删除。来源级凭证需要本机原采集回执，接收设备的阅读数据和资料库副本记录不能替代。
- 写入限速等待结束后、实际删除请求发出前，再从当前认证来源读取任务和完整附件清单，核对账号、快照、本机原附件、当前设置和操作状态；持同步锁直至删除确认。来源变化、暂停或许可过期都拒绝旧许可。阅读同步接收和来源清理核验不创建资料库导出操作。

## 设备、检查点与历史维护

- 设置提供设备列表、退休标记和从云端恢复同步记录。成功同步以最佳努力发布有版本的活动记录，心跳失败不撤回已成功的内容同步。记录表示上次已知活动，不声称设备当前在线；退休标记不撤销云密钥。
- 桌面历史清理采用“预览范围 → 准备并核验检查点 → 单独确认清理”。正式合并入口在独立数据库恢复实际读取的历史，导出兼容检查点，再在另一空库检验语义覆盖；删除记录、标签移除事实、复习事件和设备退休分量必须保留。只有真实云读回通过的替代对象才可覆盖旧历史。
- 清理前再次核验云检查点，精确删除预览中的已覆盖对象；并发新增历史、全部附件文件、来源凭证和 WebDAV 当前闪卡快照保留。日常同步不需要删除权限；显式历史清理另需本目录的精确删除权限。不自动按时间或容量清理云数据。
- 长期离线设备先预览、分批核验并合并当前云范围，再确认本设备。恢复保留本机待同步修改，经正式已应用/已知基线入口记录已验证数据，避免普通同步重复拉取同一历史；不替换整个 SQLite，不重新执行采集删除或外部保存。手机支持查看设备、检查结果和恢复云端记录，不提供设备退休、云检查点发布、来源清理、云历史删除或资料库保存位置管理；附件仍按现有下载策略获取，不把记录恢复显示为全部文件已离线。
- 每次请求最多 100 项或约 32 MiB；范围上限 200000 项，本机维护暂存最多 2 GiB，失败和重启后可继续。可在暂停同步时明确释放本机维护暂存，旧批次随之失效；此操作不删除云对象、阅读域数据或附件。完成的历史暂存载荷释放，保留必要的进度证据。

新增端到端加密、AWS S3、大文件分块和通用网页剪辑不属于本轮实现。私有 Bucket 与 HTTPS 不等于端到端加密；旧加密快照的兼容读取保留。

## 历史阶段验证记录

使用隔离 SQLite 测试旧偏好迁移、总开关/模块/自动组合、原子保存、调度重试门槛与待同步状态保留；前端覆盖设置保存失败、等待暂停、模块关闭、局部传输失败后的刷新、入口、复习队列及备份恢复入口。
