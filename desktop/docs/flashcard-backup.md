# 闪卡备份与恢复

入口：闪卡右上角云同步 → **备份与恢复**。电脑与 Android 使用相同的 `.hubfc` 文件。

- **备份到文件**：先生成并校验本机备份，再通过系统文件对话框另存。取消另存不会删除本机备份。
- **从文件恢复**：选择文件，校验后显示卡片、附件、复习事件和算法参数数量，点击“确认恢复”才写入。
- **本机备份与恢复前备份**：显示最近 10 份，可以再次另存或恢复；更早文件仍保留在数据目录的 `flashcard-backups` 中。

备份包含牌组和文件夹、所有卡片、收件箱（含处理状态）、质量记录、完整不可变复习事件（包含已撤销事件）、删除/撤销标记、学习设置、FSRS 参数及排程版本，以及以上记录引用的本地附件原始字节。云端凭据、其他资料库和未提交的编辑草稿不在备份中。外部附件链接只保留地址，界面会显示数量；它们的网页内容不属于本地附件备份。缺失或损坏的本地附件会让备份失败，不能把部分备份显示为完整成功。

首次在新设备备份前，请先在持有原附件的设备完成同步，再在新设备选择“全部下载，供离线使用”并同步。0.16.189 起，同步也会保留已处理收件箱和历史卡片引用的附件，使完整恢复所需的历史文件可以下载。

恢复是**合并恢复**，用于迁移设备、恢复缺失数据或从备份重建空资料库。现有较新的内容、复习事件、删除和撤销标记会保留，然后按事件重算学习状态。它不会把正在使用的资料库强制回退到备份时刻，也不会复活之后明确删除的卡片。当前暂停复习轮次在恢复完成后结束，已保存评分不受影响。

恢复前自动创建完整本机备份；校验或数据库合并失败不会提交部分卡片和复习记录。成功后标记为待同步，通过原有云同步路径合并到其他设备。文件校验可发现截断或损坏，但备份没有加密，也不是身份签名，请妥善保存并仅恢复信任的来源。

单份文件上限 2 GiB，清单上限 128 MiB。二进制附件以流方式读写，不经过网页界面的 Base64。Android 原生保存流程可在系统文件选择器中继续；“已打开保存对话框”不等同于文件已经另存成功。

## 文件协议 v1

8 字节 `HUBFC001`，8 字节小端清单长度，32 字节清单 SHA-256，UTF-8 JSON 清单，随后依清单顺序保存附件原始字节。清单含协议版本、应用版本、同步快照（平级数据 v4，含子牌组 v5）、附件 SHA-256/长度/MIME 和外部链接数量。不得附加未知尾部数据。恢复不从文件解压路径；附件仅通过内容哈希进入 BlobStore。

含子牌组的备份要求恢复端支持快照 v5；只支持 v4 的旧客户端必须拒绝，不能丢弃父关系后继续恢复。文件头 v1、数据库结构版本、应用版本和内部快照版本是不同的兼容边界，不能互相替代。具体双端版本及实际升级证据见 [闪卡最终证据核对](FLASHCARD_FINAL_EVIDENCE_20261115.md)。

数据库捕获使用一致事务；备份文件先写临时文件并同步、重新校验，再发布为 `.hubfc`。恢复先校验完整文件、参数身份和全部附件引用，再保存恢复前备份，最后用一个数据库事务合并快照、登记附件并标记同步。重复恢复不会复制评分事件。恢复失败时可能已写入去重附件缓存，但数据库保持原状态。
