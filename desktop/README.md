# Craft Search

独立的本地优先桌面搜索工具。Craft MCP 与滴答清单 MCP 负责同步授权账号的数据，Obsidian 以只读方式扫描本地 Vault；统一索引与搜索均在本机完成，并提供类似 Notion 的结果列表与完整页面预览。

## 当前能力

- 对话详情的“联网与工具 → 外部工具”可逐工具选择当前 Codex ChatGPT 账号已连接的 Apps；GitHub Issue 评论采用草稿、确认和精确回读。独立浏览器使用本机 Edge/Chrome 与锁定的 Microsoft Playwright MCP，首次需准备组件并明确允许的网站；不继承个人浏览器登录。支持范围、授权与安装前提见 [原生能力合同](docs/AGENTS_NATIVE_CAPABILITIES.md)。

- 正文旁的 Hub 助手支持连续对话、精确引用、笔记修改与闪卡草稿。Codex 路线采用持续 Agent 会话，由模型选择工具、处理结果并实时说明工作进展；可在运行中追加要求、停止后继续。提供方返回的公开思考摘要可以展开查看。保存与导入以 Hub 的授权和实际回执为准，详见 [助手交互与支持边界](docs/ASSISTANT_INTERACTION.md)。此路线使用本机已安装并登录的 [Codex 开源运行层](https://github.com/openai/codex)，协议参考 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)；Codex CLI 不包含在 Hub 分发包中。

- Hub 启动的 Codex CLI 共用「设置 → Codex」中的模型、推理强度、标准/Fast 速度与并发队列；标签定义、补标、逐篇检查、标签关系分析、收藏写入 Craft 和滴答转换均由同一套件管控，运行状态集中到底部信息栏。详见 [Codex 套件](docs/CODEX_SUITE.md)。

- “阅读”将 X 书签、X 喜欢、Telegram 机器人收件和滴答稍后读放在同一个数据库，共用列表、表格、看板、画廊、阅读状态、标签和多条件排序；Telegram 支持账号确认、重复收件去重、相册合并、消息编辑及本地附件与 Obsidian 归档，详见 [Telegram 收集说明](docs/TELEGRAM_COLLECTION.md)。
- 阅读使用独立中栏，提供阅读状态、我的视图、已保存副本和需要处理；我的视图显示对应布局图标，看板支持拖动更改状态。搜索智能集合保持独立，旧收藏视图自动迁移。详见 [阅读导航说明](docs/COLLECTION_NAVIGATION.md)。
- Obsidian 默认保存库的 X、Telegram 本地素材可手动接入阅读，或自设检查间隔；默认仅手动。与主界面资料库搜索并存，按来源与正文附件去重，保留阅读状态，原件只读。详见 [本地素材接入](docs/LOCAL_READING_SOURCES.md)。
- 阅读预览的离线、附件云副本、资料库副本记录与恢复核查统一放在右上角“更多阅读操作 → 本文管理”中，打开后才读取副本状态。手机使用横向来源栏和紧凑工具栏，点击条目进入独立阅读页，返回保留列表位置。
- Craft MCP OAuth 2.0 + PKCE 登录；Windows 刷新凭证保存到系统凭据管理器，手机端使用应用私有数据目录中的加密凭据文件。
- 滴答资料库以只读方式采集；任务界面启用 Craft 与滴答同步后，通过受控写入更新已关联任务。
- Craft 新建顶层任务（含标题带 `#项目` 的页面容器）默认进入所选滴答账户的收件箱，无需选择目标清单。已有任务移动到任意清单后继续按任务 ID 同步；新增子任务跟随父任务当前所在清单，无法确认父任务位置时暂缓创建。旧目标清单设置自动按新规则处理，已有任务保留原位置与绑定。
- 滴答任务首页日期只使用远端修改、完成或创建时间；时间均缺失时不再把本次同步时间伪装成修改时间
- 统一的多数据源“资料库”模型：Craft 空间和 Obsidian Vault 共用搜索、同步、筛选与索引管线
- 每库支持后台同步、持久暂停/继续、异步移除及独立的下载、OCR、PDF 与附件复制策略；添加时可选择稍后开始。详见 [资料库管理](docs/LIBRARY_MANAGEMENT.md)。
- 添加多个 Craft 空间和多个 Obsidian Vault，可切换单个资料库或搜索全部资料库
- Craft 原始备份保存在当前 Hub 数据目录内，与可重建索引分开，保存当前可访问页面、附件、集合与白板原始数据；核验通过后形成恢复点，并生成 Markdown 阅读库。支持自动备份、第二份副本、无连接恢复，原件随 Hub 数据目录整体迁移；详见 [备份与恢复说明](docs/craft-backup.md)。历史版本与权限不是该备份的覆盖范围。
- 不绑定任何机器的固定 Vault 路径；每台电脑首次使用时在设置中添加该设备上的 Obsidian Vault，路径只保存在本机
- Obsidian 递归增量扫描 Markdown，按内容 SHA-256 只更新发生变化的文件；删除文件会同步移除本地文档与全文索引
- Obsidian 扫描默认忽略 `.obsidian`、`.trash`、`.git`、`.basic-memory`、`node_modules` 和符号链接；每个 Vault 还可在设置中配置独立的目录、路径前缀或 `*` / `?` 通配排除规则，不修改 Vault 原文件
- Obsidian 只登记 Markdown 实际引用的 PDF 与图片；附件以只读方式流式复制到本地 Blob 仓库，未引用文件不会扫描、复制或索引
- Obsidian PDF 复用原生文字提取与按页 OCR，图片复用 Windows OCR；相同内容跨笔记、Vault 或 Craft 空间时按 Blob 哈希共享提取缓存
- Obsidian 结果通过 `obsidian://` 深层链接打开，预览直接渲染本地完整 Markdown
- 桌面 Markdown 预览可显式选择“当前／Craft 风格”，默认保持当前。样式偏好使用个人资料存储；仅调整阅读排版，保留目录、命中、折叠与来源入口，不修改正文或套用 PDF。实现、真实文档对照和日常窗口待验证项见 [Craft 阅读主题](docs/PREVIEW_CRAFT_THEME_20261115.md)。
- Obsidian 深层链接对 Vault 与文件路径中的空格使用 `%20` 编码，避免被 Obsidian 误识别为文件名中的 `+`
- Obsidian 预览双链通过后端校验资料库后打开，不受前端 URL 白名单限制；`[[页面#章节]]` 会保留章节目标
- Obsidian 双链支持当前页章节、相对路径、当前文件夹同名笔记优先和 YAML Frontmatter `alias` / `aliases` 别名解析
- Obsidian Frontmatter 别名以及 Frontmatter/正文标签作为独立加权字段进入索引，可直接通过别名或 `#标签` 找到笔记
- 每个已启用 Vault 使用文件系统监听；Markdown 保存、创建或删除后经过 750 ms 防抖，只对变化文件执行事务增量并排队更新索引，瞬时失败会自动回队重试
- 设置页按 Vault 显示监听状态、待处理文件数、最近成功增量时间和监听错误；单个 Vault 可手动重新建立监听，无需重扫全部内容
- 系统托盘常驻，关闭窗口时隐藏而不退出
- 单实例运行；重复启动会唤醒已有搜索窗口，避免 SQLite/Tantivy 写入冲突
- 全局快捷键：优先 `Ctrl+Shift+K`，冲突时回退到 `Ctrl+Alt+Space`
- 枚举各 MCP 连接授权的 Craft 空间、文件夹和文档
- 按修改时间执行增量同步；无修改时间时以正文 SHA-256 作为兼容回退
- 自动同步采用分层核对：日常只扫描文档元数据与变更正文，每 24 小时执行一次文件夹归属和删除完整核对；手动更新始终执行完整核对
- 每个空间持久化同步阶段与完整核对时间，异常中断后可诊断停留在枚举、读取还是提交阶段
- Craft 读取共享每空间自适应限速器，统一控制并发请求间隔；遇到 429 时遵循 `Retry-After` 或指数退避并加入抖动
- 文件夹与正文读取采用有限并发，正文每 100 篇分批落库，避免大空间同步时串行过慢或正文集中占用内存
- SQLite 保存资料库、文件夹、文档元数据、内容分块和可恢复的索引任务队列；旧 Craft 空间会兼容迁移为 Craft 资料库
- SQLite 启动迁移每个应用进程只执行一次；普通读连接不再重复运行建表和迁移语句
- 后台同步、附件、OCR 与索引状态提交统一经过进程级单写入通道，避免并发写事务争抢 SQLite 锁；搜索、预览和状态统计仍使用独立 WAL 读连接
- 原始内容同时进入 SHA-256 内容寻址 Blob 仓库；相同内容只保存一次，旧 Markdown 由后台自动回填
- 自动发现 Craft Markdown 中的 `r.craft.do` 图片和附件资源；同步时再从结构化 Craft 数据刷新短期资源地址，避免旧链接 404
- Craft 资料库同步保留精确附件块身份及已有缓存，旧地址来源原位升级，Markdown 回填不降低已知身份。附件版本或已知字节数变化时更新原件；有相同块版本证据的地址轮换、已知签名参数轮换和显示名变化复用已有原件。缺少可靠版本证据且资源定位地址变化时，保守重新下载。
- 重复扫描保留正在下载的任务、执行者和失败等待时间；下载任务发出网络请求前核验已有文件的 SHA-256 与长度，缺失或损坏的缓存重新下载。旧资源版本、旧地址的失败和过期执行者不能覆盖新附件状态。该策略用于资料库同步与索引扫描；完整备份的采集策略见备份说明。
- 后台下载与预览共享附件下载锁，同一资料库内相容版本的跨页引用复用原件；预览失败不会隐式再拉一次，视频按点击播放获取。已下载的实际文件类型若被策略关闭，会保留原件并结束下载任务，避免按旧类型提示反复拉取；已知长度与实际字节数冲突时按有界失败处理。
- 阅读云同步与闪卡同步保存已验证对象的远端版本凭据，当前强 ETag、长度与内容身份相符时复用；版本不明或变化时保守读回。阅读附件清单失败不会抹掉已确认的原件阶段，并保留有界重试等待。
- 附件下载使用 HTTPS 校验、受限重定向、100 MB 大小上限和流式 SHA-256 入库，不把大文件整体塞进 SQLite 或内存
- PDF 使用文件魔数与 HTTP MIME 双重识别，按页提取原生文本、分块写入内容索引，并在结果中标记为 `PDF`
- PDF 解析包含兼容修复回退，可处理 EOF 后附加数据、紧凑型 xref 头和损坏的增量 `/Prev` 指针；修复只发生在内存副本，不改写原始附件
- 使用 Windows 系统 OCR 识别扫描型 PDF 与图片，不额外捆绑 OCR 模型或 PDF 渲染 DLL
- PDF 按页判断文字层：原生文字页立即入索引，只把空白页送入 OCR；混合型 PDF 完成后按原页码合并，不覆盖已有文字
- PDF 原生提取与 Windows OCR 使用全局 Blob 哈希缓存；同一文件出现在不同页面或空间时，原生文本按整份复用，OCR 按页复用，不重复消耗 CPU
- 提取缓存使用原子缓存槽和超时租约；相同文件并发进入队列时只允许一个 Worker 处理，其余任务短暂让出并在缓存提交后继续
- OCR 使用单页持久化任务、Worker 租约和失败退避；后台每批领取 8 页并以双并发连续处理，长 PDF 中断后从未完成页继续
- 附件任务使用持久化成本估算：下载按文件大小、PDF 提取按大小与页数、OCR 按来源类型和单页负载估算；同一空间优先处理轻任务，并通过等待老化保证大型任务最终得到执行
- 多空间附件队列采用持久化轮转游标：每轮优先从不同空间各领取一项，再进入下一轮，避免附件较多的空间长期独占下载、PDF 与 OCR Worker
- 下载与历史图片回填共用 50 项背压阈值；OCR 积压时优先清空识别队列，不再持续追加数百个附件任务
- 底部状态每 3 秒分别显示附件（Craft 下载和 Obsidian 本地导入）、OCR、待发现和失败数量；设置页可以重新排队已停止自动重试的 OCR 页面
- “同步状态 → 附件下载失败”集中查看来源附件的下载问题，支持按资料库筛选以及单项或当前页“跳过 / 再次重试”。跳过保留缓存并暂停当前附件版本的下载，普通扫描不会重新打开；已跳过项可随时明确重试。正在下载的项目保留原执行者，重试提交到现有队列后再显示实际结果。
- `source_items` 与 `extractions` 统一记录页面、附件、PDF、图片及提取状态
- 索引任务使用批量领取、Worker 租约、失败退避和最大重试次数，并由后台 Worker 自动恢复
- 搜索只读取最近一次已提交的 Tantivy 快照，不等待后台索引积压；新内容由 Worker 持续提交后自动可见
- 默认每 15 分钟自动同步一次，可在设置中关闭或切换为 5 分钟至 6 小时；手动与自动同步互斥，不会重叠扫描
- 本地维护每天运行一次，也可手动触发：未引用 Blob 经过 7 天宽限后删除、24 小时以上暂存文件清理、保留最近两个退役索引代际用于回退
- 已完成后台任务保留 7 天后清理记录，并执行 SQLite WAL checkpoint 与查询规划优化；实际数据库空间回收使用明确安排的离线维护
- 当前任务状态使用随事务更新的计数，日常刷新不扫描全部已完成历史；详情和历史仍完整保留
- 设置页后台诊断显示同步阶段、待提交词法索引、Craft 限流次数和冷却状态
- Tantivy 磁盘全文索引，使用中文 2～3 字 N-gram、标题/章节/路径字段加权和 Top-N 搜索实体聚合
- 支持中文标题全拼与拼音首字母召回、英文/数字词项错别字容错；多词默认要求全部命中（AND），也支持显式 `OR` 与引号短语搜索
- 搜索结果按标题、章节、附件名、正文、路径以及 PDF 原生文字、PDF OCR、图片 OCR 分层加权；精确标题优先，拼音和模糊召回不会压过精确结果
- 后端返回实际命中词和命中字段，结果显示命中标题/章节/附件名/路径/正文、附件名称与 PDF 页码，避免只高亮用户输入但未解释真实召回原因
- 搜索结果按页面与资料库分组，默认展示两段命中摘要，其余可展开；只命中标题、路径、标签或别名时显示匹配依据，不铺开无关正文。列表区分页面数与正文片段数，同源重复摘要和同一定位点的重叠上下文合并，附件与 PDF 页码保留独立定位。
- 列表与预览统一使用浅黄关键词高亮；悬停不改变选中结果，键盘选到折叠片段时自动显示，收起时将选中位置移回可见片段。页内命中继续通过预览中的 F12 / Shift+F12 导航。
- 搜索列表支持“详情 / 紧凑”模式并记住选择；详情默认两段摘要，紧凑隐藏匹配说明、默认一段摘要。两种模式的第二行统一显示路径与更新日期，保持单行，空间不足时从路径中间省略，日期保持完整。
- PDF 搜索结果按命中页预览原始页面图像与该页完整提取文字，支持前后翻页；单页按需渲染，页面图像失败或过大时自动保留文字预览
- 一个查询跨多个字段命中时会同时显示全部命中字段，例如“命中标题、正文”
- 搜索词在结果和完整页面预览中高亮；高亮窗格显示命中总数，支持按钮及 `F12` / `Shift+F12` 在正文命中间前后导航
- Craft 嵌套页面导出的缩进 Markdown 会在只读预览时规范化，代码节点同样参与高亮；预览打开时 `F12` 会在捕获阶段由应用接管
- 预览关闭时按 `F12` 会自动打开预览并定位第一处命中，`Shift+F12` 会打开预览并定位最后一处命中
- 资料库、文件夹、修改时间以及页面/PDF/图片组合筛选会在本机持久化；搜索历史支持单条删除和全部清除
- 支持中文输入法组合输入，组合期间不触发搜索或误用 Enter 打开结果；支持方向键、PageUp/PageDown、Home/End、Enter 及搜索/筛选/预览快捷键
- Obsidian 完整 Markdown 预览支持结构化 YAML Frontmatter、双链与别名、嵌套 Callout、KaTeX 行内/块级数学公式、GFM 表格和任务列表；双链通过 `obsidian://` 打开，嵌入附件显示只读占位，其可搜索文字来自后台 PDF/OCR 管线
- Tantivy 使用代际索引：完整重建在新目录完成并校验后才原子切换，旧代际保留用于故障恢复
- Markdown 按标题和 Craft 子页面分块；正文块按 Craft 页面聚合，每张图片和每个 PDF 则按独立附件聚合，避免同页多个附件互相覆盖
- 左侧结果列表、空间/文件夹/时间筛选栏和右侧完整页面预览
- 通过 `craftdocs://` 深层链接打开 Craft 原页面
- 资料库索引只调用 Craft 读取工具；任务双向同步及用户发起的 Craft 保存使用各自的受控写入流程。
- Craft 分页出现重复游标或不完整结果时中止同步；远端连续两次完整扫描都缺失的文档才会从本地删除

## 开发

### 安卓模拟器热更新

在当前主工作区的 `desktop/` 中运行 `npm run android:dev`，默认连接已启动的 `emulator-5564`；其它模拟器用 `npm run android:dev -- -Device emulator-端口号` 指定。入口会启动或复用本目录的 Vite 服务，通过 ADB 将设备的 1422 端口连接到电脑，并覆盖安装开发版，保留应用数据。日志在 `.local/android-dev/`。安卓开发服务不会继承桌面的自动 Craft 连接开关，页面重载不会自行发起登录；需要时在资料库设置中主动连接。

安卓前端固定使用 `http://127.0.0.1:1422`，不占用桌面的 1420。修改本目录 `src/` 的界面会自动更新；其它工作树的修改先合并到此目录。Rust、权限、插件及原生配置修改后重新运行 `npm run android:dev`；若只重启界面服务，运行 `npm run dev:android`，无需重装。

开发版依赖电脑服务及端口映射，适合界面联调；独立 APK 的锁屏上传与正式打包验收另行执行。入口沿用现有 SDK/NDK 和 Java 21；Windows 无符号链接权限时，使用 Tauri 已编译的同一原生库组装 Debug 包，不更改系统权限或卸载数据。

### 桌面开发

要求：Node.js 20+、Rust stable、Visual C++ Build Tools、WebView2 Runtime。

```powershell
npm install
npm run tauri dev
```

本机开发连接可写入 `.env.development.local`：

```dotenv
VITE_CRAFT_MCP_URL=https://mcp.craft.do/links/.../mcp
VITE_AUTO_CONNECT=true
```

该文件会被 Git 忽略，并且不会进入生产构建。

## 构建

```powershell
npm run tauri build
```

生成不依赖本地开发服务器的免安装版：

```powershell
npm run tauri:portable
```

不要在生成免安装版前后使用普通的 `cargo build --release` 覆盖 Tauri CLI 产物；普通 Cargo 构建可能保留开发服务器地址。

正式候选使用 `python scripts/release.py` 冻结生产输入、核对候选并记录同一免安装构建的产物和回执；流程与历史保留边界见 [发布和历史制品保留政策](docs/发布和历史制品保留政策.md)。此入口不自动清理历史，也不上传或安装发布物。

本地数据默认保存在系统应用数据目录 `com.craftsearch.desktop`；Windows 的“设置 → 数据管理”支持分类占用、大文件排序与关联标题定位、安全清理预览、数据库压实、自定义目录、便携模式、打开已有数据目录及 `.hubbackup` 整库备份。具体搬家、恢复和自动备份步骤见 [数据目录与整库备份](docs/数据目录与整库备份.md)。

- `craft-search.sqlite3`：元数据、Markdown 正文、页面/PDF/OCR 内容分块、Blob 提取缓存映射和可恢复任务状态
- `tantivy-generations-v1/generations/`：活动、构建中及已退役的磁盘全文索引代际
- `blobs-v1/`：按 SHA-256 分片保存的原始内容、附件和提取文本；二进制附件不会写入 SQLite

收藏、视图、标签组织和已保存草稿等个人数据随数据库保存。Craft、滴答的正文与附件原件自动保存在当前软件数据目录，后续新增内容使用同一位置；旧版外部副本在首次打开时自动复制、核验并更新引用，原文件保留。换机只需完全退出 Hub 后复制整个文件夹，无需复制前检查。更改存储位置时通过“数据管理”整体迁移并校验，原目录保留。Obsidian 原始库由用户自行移动后重新加载。账号授权和服务密码可按需加密放入同一目录，新电脑输入迁移密码恢复。整库备份自动包含受管原件与已有加密授权副本；正文、附件和清单不压缩、不整体加密，索引会重建。直接复制前应退出 Hub 及访问它的 MCP 进程，不要只复制数据库单文件；尚未成功下载的内容需先补齐。

SQLite 和 Tantivy 均不保存 Access Token、Refresh Token 或密码。Windows 刷新凭证保存到系统凭据管理器，手机端保存在应用私有数据目录中的加密文件；OAuth 分片先写入新的完整版本并读回校验，再切换索引，失败时保留原版本。隔离测试入口使用独立凭据目录。

数据库结构版本由 `src-tauri/src/database.rs` 中的 `DATABASE_SCHEMA_VERSION` 定义；当前为 77。启动时按版本顺序执行迁移，保留已有内容和复习历史。全文索引结构升级后会通过代际机制自动重建，使别名和标签进入独立加权字段，无需重新扫描 Vault。旧版程序不能直接打开高于自身支持版本的数据库，回退前应退出应用并恢复升级前备份。

## 搜索质量评测

项目内置一组完全由合成数据构成的搜索质量评测，不会读取真实 Craft 页面、Obsidian 笔记、附件、Token 或 MCP 地址。固定用例覆盖精确标题、章节、正文、路径、多词 AND、显式 OR、引号短语、拼音、首字母、错别字，以及 PDF、PDF OCR、图片 OCR 和 Craft/Obsidian 跨资料库排序。

评测同时验证空间、文件夹、修改时间和内容来源筛选，PDF/OCR 开关组合，标题/章节/正文/附件权重，PDF 页码与命中来源，实体分块聚合及结果数量上限。运行命令：

```powershell
node scripts/test-rust.mjs -- search_index::tests::search_quality_evaluation_suite --nocapture --test-threads=1
```

成功时会输出 Top-1、Recall@3、MRR 和 P95 查询耗时。Top-1 与 MRR 只统计具有唯一首选结果的主排名用例；显式 OR 的次要合法结果只进入 Recall@3，避免同一查询的两个不同结果被错误要求同时排第一。P95 超过 250 ms，或固定结果的排名、字段、来源、页码和数量发生偏差时测试会失败；设置 `CRAFT_SEARCH_EVAL_DETAILS=1` 可输出非首位结果的实际排名、分数和命中字段，后续调整权重或扩展 Obsidian 解析前应先运行这组评测。

完整发布检查使用 `npm run check`。其中 `npm run test:rust` 仍由 Cargo 构建原始库测试，在 Windows 为字节一致的测试程序配备 Common Controls v6 外部清单，避免原生组件加载失败。每次运行的收集身份、构建日志、执行日志、程序摘要和真实退出码保存在 `.local/rust-test-runs/`；`--collect-only` 只收集，不执行用例。该入口不改变生产程序的编译特性，也不把直接执行 `cargo test` 的运行环境视为已修复。读取个人数据的操作验收默认忽略，必须另行提供明确授权及目录。

原生检查默认采用单编译任务及非增量构建，与正式发布的资源策略一致；可通过原 Cargo 环境变量明确覆盖，实际值写入测试回执。不会清理既有构建缓存。

界面检查使用官方锁定依赖、单个独立工作进程及零重试。真实懒加载渲染依赖在相关测试的准备阶段加载，避免把首次转译混入交互计时。若 Windows 环境初始化持续超时，先核对运行环境；可在快速本地磁盘的同摘要源码副本执行原发布入口，不修改第三方测试依赖或放宽业务断言。

真实数据验收或恢复时，可在启动程序时附加 `--manual-session`，仅本次不启动自动调度，窗口标为“自动任务已暂停”。个人设置、凭据和分析权限保持原状，手动调查及明确确认的业务动作仍沿现有入口执行；不要在此模式主动启动无关业务队列。该参数不能与隔离运行混用，下一次普通启动仍按原设置运行。

## 当前限制

- 如果 Craft 未提供文档修改时间，同步会退化为下载正文并比较哈希；仍只重写发生变化的索引记录。
- “全部资料库”模式下文件夹名称可能重复，因此文件夹筛选只在选定单个资料库时启用。
- Craft 专用 Markdown 标签目前按只读预览规则转换，复杂白板和集合需要继续完善渲染器。
- 当前搜索附件范围为 PDF 和图片文字；Word、Excel、ZIP、TXT 等其他附件格式只登记元数据，暂不下载或提取。
- OCR 依赖 Windows 用户配置的系统识别语言，低清晰度、手写体、复杂排版或语言包缺失时可能得到不完整文字。
- Craft 资源短链如果已失效或返回 404，会标记为 `unavailable`，不会计入 Worker 失败或在后台无限请求；文档重新同步并出现新资源地址后会重新排队。
- Obsidian 目前只提取被 Markdown 引用的 PDF 和常见位图（PNG、JPEG、WebP、GIF、BMP、TIFF）；其他附件格式及未引用文件不会复制或索引。
- Obsidian 附件单文件上限为 100 MB；图片开关关闭时暂停图片导入与 OCR，PDF 开关关闭时暂停 PDF 导入、原生文字提取与搜索，PDF OCR 仍由设置中的独立开关控制。

## 闪卡记忆算法

闪卡使用 FSRS-6（Rust 库 `fsrs = 6.6.2`，固定默认参数），目标保持率为 90%。
“重来”安排在 10 分钟后；其他评分按模型结果取整到天，范围为 1–36500 天。
已过去的时间按完整的 24 小时计算；暂不启用随机间隔或个人参数训练。
评分按钮、实际保存、撤销和多端历史重算共用后端算法。

数据库升级到 68 时保留旧卡到期日，将现存复习历史补录到不可覆盖的事件记录中，从下一次评分开始采用 FSRS。
有历史的旧卡根据历史恢复记忆状态；缺少历史的已学卡根据原间隔与难度作初始估计。
复制卡片或选择“保存为新卡重新学习”会从新卡状态开始。
排程在设备本地运行，复习与记忆状态通过现有 OSS 同步，不需要云端计算服务。

OSS 变更外层协议使用版本 4；内部闪卡快照在平级数据时为 v4，含子牌组时为 v5。参与子牌组同步或恢复的所有设备都须支持快照 v5，不能仅凭外层协议版本判断兼容。
新版可读取旧快照，旧版无法读取新协议。数据库升级后不可直接用旧版程序打开，
如需回退，应先退出应用并恢复升级前的数据备份。
算法排程版本 1 固定了本次间隔规则；更换模型权重或目标保持率会产生新的参数身份，改变排程规则则必须增加版本并保留历史重算路径。

### 本地保存与阿里云同步

每次评分在本地同一个数据库事务内保存原始事件、更新学习状态并标记待同步，断网也能继续复习。
原始事件独立于卡片存在；撤销通过撤销标记生效，删除卡片或重建统计不会删除事件。
活动复习列表只是一份可重建的数据，当前学习状态按事件时间与事件 ID 的固定顺序计算。
同步会合并双方事件后重算，远端“下次复习时间”不能覆盖本机已有事件推导出的结果。
先收到复习事件、后收到卡片时，先保存事件，等卡片到达后再恢复学习状态。

每次 FSRS 评分引用一份不可覆盖的参数版本，随同步传输完整的 21 个模型参数、目标保持率、算法和库版本、间隔规则。
参数身份由内容计算，历史重算使用当次评分实际采用的参数；接收同一身份的不同事件内容或不受支持的参数时明确报错，保留原记录和云端对象。
当前新卡使用默认 90% 保持率，暂未提供参数训练或编辑界面。

OSS 先校验并提交卡片、复习事件和参数，再上传或下载附件。附件按内容哈希校验，失败的附件进入独立的持久待同步队列，重启后继续重试。
附件失败不会回滚已经保存的评分，也不会阻止另一台设备接收已提交的复习记录；按需下载设置继续有效。
迁移同步服务时仍需完成附件校验才切换服务。
