# 按天速记（首版）

对应 [Issue #22](https://github.com/VondeSong/hub-search/issues/22)。本版只做 Hub 录入、OSS 传递、OS 日记追加及卡片流，不接入滴答采集。

## 使用入口

日志 → 日志视图设置 → **速记卡片**。支持文本、Markdown、`#标签`、照片和一般附件。日期默认采用手机当前本地日期，允许补记；记录保存后跨时区同步不重新计算日期。每条最多 9 个附件，单个最多 20 MB。草稿及附件先落本机，再提交持久化队列。

电脑在“速记保存与同步设置”中选择 OS Obsidian 库及库内日记目录（默认 `Journals`，应与实际库一致）。同一云目录只允许一台电脑接收并写入。手机无须保存或修改 OS 库。

手机和电脑复用“设置 → 云同步”中的阿里云 OSS 连接，分别开启本设备速记云同步。自动上传还要求云同步总开关及自动同步开启；手动“同步 / 重试”遵守总开关，不要求自动同步开启。速记默认不启用云传输，也不自动选定个人资料库。

## OS 文件格式

例如 `Journals/2026-11-07.md`，原有 frontmatter、标题和手写内容保留。在文件末尾追加：

```markdown
<!-- hub-journal:v1 begin 99aaaabbbbccccddddeeeeffff00001111 -->
今天的一个想法。 #日常

![照片](<_hub-assets/附件内容哈希.jpg>)
<!-- hub-journal:v1 end 99aaaabbbbccccddddeeeeffff00001111 -->
```

唯一 ID 不编码日期或时分秒。日记中的每个区块是一张卡片，不为记录创建独立 Markdown 文件，不生成逐条时间标题。JSON 仅作为云端传输信封和本机队列内容，OS 的长期正文仍是普通 Markdown。

同 ID 重试不追加第二份，不覆盖 OS 已有区块正文。卡片读取已写入的日记区块，因此在 Obsidian 中修改正文后可以回显；删除完整区块后该卡片不再显示。保留边界 ID，避免复制出两个相同 ID。区块损坏、未知版本、未闭合代码围栏时停止写入并显示错误，不猜测边界。

## 同步协议 v1

复用 OSS 连接及现有 `prefix/v2` 根目录，速记独占 `journal/` 子目录：

- `assets/<sha256>`：原附件字节，内容校验后保存。
- `records/<id>.json`：`version / id / date / text / attachments`；附件包含 `hash / name / size / image`。先上传并读回校验附件，再提交不可变记录。
- `receipts/<id>.json`：电脑写入并核验日记后发布回执，携带记录 ID 和传输内容哈希。
- `writer.json`：不可变的接收电脑标识，防止另一台电脑自动把相同收件内容写入其他库。更换写入电脑属于后续迁移能力，不能直接删除所有者记录后盲目重放。

记录首次尝试上传时绑定云命名空间；更换连接不自动搬运已经绑定的队列。附件和本机记录不会因为上传成功自动清除。首版不提供云端删除、双向内容覆盖或垃圾回收。

界面区分“已保存到本机”“已上传，等待电脑写入”“已写入 OS”。保存成功后可以锁屏，但不承诺锁屏当刻已经上传。Android 使用 WorkManager 持久任务及有网络约束的重试，并周期检查回执；休眠、省电、强制停止可能延后执行，强制停止后需重新打开应用。电脑开启时自动检查收件内容，关闭时手机仍可记录。

## 展示与边界

卡片显示日期、正文、图片、附件保存入口、状态；支持日期/资料库/正文筛选、标签筛选、长内容展开、分批渲染及跳转 OS 日记。首版编辑在 OS 中完成；手机版展示自己的捕获副本和回执，不反向同步电脑编辑后的正文。

首版扫描云收件清单并在本机按 ID 去重，卡片加载读取本机队列和相关日记。大规模历史库的增量清单与服务端分页留待后续性能阶段，不将分批渲染冒充后端分页。

后续保留：置顶、热力图、随机回顾、OCR、语音转写、AI 洞察、历史导入、受控双向编辑、关联笔记、多写入端、接收电脑迁移、附件清理与大文件传输。

## 验收

开发侧检查包括 Markdown 边界、原文保留、去重、手工编辑后重放、附件缺失不落盘、回执、唯一接收端、草稿恢复与失败重试，以及桌面和 Android 编译。

仍需真实 Android + OSS + OS 联调：离线拍照保存、立即锁屏、断网恢复、进程回收/重新启动、电脑关闭后补传、真实库目录与附件打开。未完成这些检查时 Issue 保持打开，不能把构建通过当作实机验收。
