# Codex 补标定义草稿

在标签的「内容补标 → 补标定义与范围」点击「用 Codex 生成定义」或「用 Codex 优化定义」。Hub 读取当前标签的代表样本和内部关系，使用本机已登录的 Codex CLI 在后台生成 description、include、exclude 三项草稿，并自动回填。无需复制任务；原复制入口保留在「手动交接」中。

「选择模型」浮层从本机 Codex 模型目录加载可显示的模型，并在本机记住上次选择。首次为「Codex 默认模型」；也可点击「刷新模型」。旧选择不再可用时提示重新选择，不自动回退。目录可见不保证账号始终有权限，服务端拒绝时会显示错误。速度显示「跟随 Codex 默认」：传用户选择的 `--model`，速度不覆盖 service_tier；推理强度默认不覆盖，手动选择时传 `model_reasoning_effort`，也不承诺固定生成秒数。

直接生成期间显示等待状态，阻止重复生成和保存。生成期间未编辑时直接填入；期间有编辑则保留当前输入并展示新草稿供选择。外部 MCP 生成的草稿每 5 秒检查，切回窗口也会检查。资料库选择保持不变，用户编辑后点击「确认并保存定义」才产生正式版本。

后台通过桌面专用 `generate_definition` 操作调用 Codex CLI，使用已登录账号、只读沙箱、关闭 shell 工具、不加载用户 MCP 配置、限定 JSON 输出，最长等待 240 秒。缺少 CLI、登录失效、额度不足或超时时显示错误并允许重试。生成结果经过字段长度和定义版本验证才保存为草稿；生成操作不暴露为 MCP 工具，避免递归发起生成。

新增 MCP 工具 `hub_submit_tag_assignment_definition_draft`：参数为 tag、expectedVersion、definition、idempotencyKey。草稿不会确认定义或变更来源标签；已确认版本变化时拒绝旧版本写入。同一键同一内容可安全重试，同一键不同内容拒绝。

`hub_tag_assignment_definition` 额外返回 draft，definition 仍只表示用户已确认版本。没有已确认定义时不能直接用草稿开始补标。

数据库 schema 62；MCP 工具总数 32。便携包更新后应同步更新本机 MCP 启动器，以便新会话发现新增工具。直接生成不依赖当前 Codex 桌面会话的 MCP 工具缓存。

模型入口采用胶囊按钮、圆角浮层、选中勾号和分段滑条。推理档位从模型目录读取（reasoningLevels/defaultReasoning），按模型独立记住用户选择。支持恢复默认、方向键选择模型、原生 range 键盘调节，以及 Escape 关闭并回到触发按钮。选择默认模型时不指定推理强度；选择具体模型后可调整。后端拒绝不支持的模型与推理组合。
