# 安卓界面与手机原型对齐

对应手机原型：<https://hub-mobile-lab-von11.song02211368537057.chatgpt.site>。

## 已落实的交互

- 主导航保留搜索、浏览、任务、复习。合入主线手机 Agents 后，保留顶部和浏览入口，对话全屏展示并提供返回。搜索改为顶部输入，顶部统一设置和速记加号；浏览第一项是日志，其后为阅读、收藏、最近浏览和标签，资料库及同步状态归入数据区。
- 速记采用底部输入层，直接写正文；底部提供标签、照片、更多和“记下”。更多包含日期、普通文件、加粗及列表。不增加任务或链接分类。
- 文字、日期和附件继续使用原生草稿及附件存储；关闭后恢复。草稿写入串行，重新打开等待之前的写入。空草稿跨天默认今天，有内容的补记保留原归属日。
- 每条最多 9 个附件、单个 20 MB，先保存附件再入队；纯附件可以提交。失败保留内容与唯一 ID。保存成功后回到归属日的卡片流。
- 手机日志固定为按记录展示，支持全部、今天、待同步、正文/日期/附件名搜索、标签筛选、长文展开和附件保存；卡片只展示日期。未分配 OS 库的本机记录仍可见。
- 卡片保留真实的本机保存、已上传等待电脑、已写入 OS 三阶段。同步设置集中在云同步页面，保留开关、队列和手动重试。
- 外观增加跟随系统、纯白、纯黑、暖纸及三种强调色，使用原生个人设置持久化；字号与原有显示偏好继续生效。
- 任务查看、完成、恢复，阅读附件/离线管理，以及闪卡今日、牌库、收件箱、备份继续使用现有真实功能。

## 数据边界

沿用 [按天速记协议](QUICK_JOURNAL.md)：手机原生入队 → OSS → 唯一电脑追加 OS 日记区块 → 回执。稳定 ID 去重，不为每条记录创建文件，不显示时分秒。手机展示捕获副本与回执，不提供归档后双向编辑或云删除。

原型的浏览器附件库、演示云阶段、JSON 备份与示例模型回复均不作为 APK 的实现。APK 保留原生上传调度、附件导出和闪卡备份格式。全局资料搜索仍依赖真实索引，未写入 OS 的速记可在日志内搜索。

## 开发验收入口

- `src/QuickJournal.test.tsx`：原生草稿、保存失败、落盘后导航、附件限制及文件保存、纯附件、日期与附件名搜索、卡片图片稳定性。
- `src/MobileQuickCapture.test.tsx`、`src/useMobileOverlayHistory.test.tsx`：弹层关闭、焦点恢复、键盘可视区域、系统返回及同步设置交接。
- `src/MobileAppEntry.test.tsx`、`src/MobileAppearance.test.ts`、显示/设置/导航与日志测试覆盖布局和偏好兼容。
- `desktop/qa/mobile-native.html` 使用真实 React 组件和隔离的原生接口适配器核验界面。示例数据不访问个人文件、账号或云端；未列出的调用直接失败。预览使用 `node node_modules/vite/bin/vite.js --config qa/mobile-native.vite.config.ts`。
- 浏览器核验覆盖 360×740、390×844、390×430，检查正文输入、更多选项、保存回卡片、搜索布局、主题及横向溢出。

APK 打包与签名通过后仍需实机检查 Android 输入法、锁屏上传、断网恢复、进程回收和实际 OSS → OS 日记链路；相关 Issue 在这些必要步骤完成前保持打开。

## 安卓构建

`desktop/src-tauri/tauri.android.conf.json` 覆盖桌面专用打包资源，避免安卓依赖 Windows 记忆组件的本机分发目录。安卓构建继续使用 Tauri 的 ARM64 APK 入口，桌面资源配置保持原有内容。
