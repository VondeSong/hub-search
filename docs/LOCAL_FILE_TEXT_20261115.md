两条 DOCX 来源登记指向同一个零字节 Blob，状态为 stored。stored 只表示原件登记，不能据此宣称正文提取成功；新提取器将零字节作为明确失败，不写入空正文成功结果。没有修改原登记或重新下载。

排除测试、验收及样本命名后，每种 Office 格式各取三个已下载文件做 ZIP/XML 可读性检查，九份原件在检查前后哈希一致。此探针仅统计部件和文字/值的长度，不验证幻灯片逻辑顺序、共享字符串引用、公式计算或完整阅读效果，不等于正式提取器已支持三种格式。原始正文、文件名、路径和哈希清单仅保存在本机忽略目录。

## 当前能力与实现阶段

现有 Obsidian 扫描器只将 Markdown 作为正文；PDF/图片附件已有原件、提取/OCR和索引流水线。Office 的 MIME、下载、导出、备份和外部打开能力不能当成全文支持。

本轮首段在独立源码工作树实现实验性的 TXT/DOCX 已下载附件提取，通过编译特性 `experimental-local-file-text` 明确启用，默认构建不启用。实验开启才为现有 Craft/滴答已下载附件安排 `extract_file`，不触发下载，不改变来源文件。尚未提供通用文件夹的产品入口。

- TXT：UTF-8/UTF-8 BOM、带 BOM 的 UTF-16，拒绝不完整编码、二进制控制字符、零字节和超限内容；不猜测旧编码或替换坏字符。
- DOCX：只读 ZIP 中的主正文 XML，保留文本连续性、段落、表格文本分隔及换行；支持标准命名空间身份，禁止 DTD/外部实体。暂不承诺页眉、脚注、批注、文本框、修订语义或版式保真，原文件入口保留。
- 资源预算：输入 64 MiB、正文 XML 8 MiB、包内最多 4,096 项、输出文本 4 MiB；XML 深度 256、最多 200 万事件/5 秒，超过即失败，不把截断当完整正文。
- 复用既有 index_jobs、Blob、资料库运行控制和全文分块；同输入 Blob/格式/提取器版本复用文本缓存，来源提交另核对当前身份与版本，暂停/移除检查在提交前执行。
- 搜索仍使用现有附件类型；预览读取同一提取文本并验证当前输入身份，以纯文本展示，避免将文件中的 HTML 或 Markdown 当成可执行/可交互内容。

独立解析器已编译：2 项内存单元检查通过；显式真实 DOCX 只读检查 1 项通过，三份实际文件分别提取 947、12、19,894 个字符，原件哈希均未变。首次过滤器漏写 `tests::` 导致运行 0 项，已纠正并实际执行 1 项；不把 0 项运行当作通过。另显式运行真实 TXT 只读检查 1 项通过，原两个实际日志附件经换行归一化后为 87/52 字符，原件未变。该程序没有编译工作流集成和预览分支，不代替完整原生检查。

前端缓存版本与附件失败不回退父文档回归 3 文件、18 项通过，类型检查和生产构建通过。构建保留已有大资源块提示，未将它写成消除。新增的文件结果身份包含输入版本，预览缓存会随版本改变；旧版派生命中在替换解析前清理并安排原有索引更新，历史文本缓存与原件保留。以上管线行为仍须完整原生回归，不以源码阅读计为通过。完整原生首次构建因独立源码工作树缺少既有 memory-distribution 运行资源而停止，尚未到业务测试；建立指向主工作区已有资源的本机目录联接后重新构建，未修改业务配置或复制用户资料。
