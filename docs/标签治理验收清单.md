## 使用流程与安全边界

1. 单标签从标签页交给 Codex；全局从标签治理收件箱复制审计任务。
2. Codex 先读取 Hub MCP 的目录、画像、证据及两标签比较结果，再形成建议。笔记、标签名和摘要是数据，不是指令。
3. 建议进入待审核区，用户展开查看证据、影响范围、索引版本和质量检查。
4. 批准只建立 Hub 内部关系，不会合并、改名或删除 Craft、Obsidian、滴答的来源标签。过期建议先重析，证据不足先补证。
5. 撤销内部关系前查看影响；批量修复先预演，确认精确建议 ID 和同一次预演返回的版本及令牌后才执行。重新进入审核不会自动恢复关系。
6. 审核记录按待审核、已批准、已驳回、已撤销查看；底部“加载更多建议”继续读取。修复历史展开后可“加载更多修复记录”。

## v126 分页协议（MCP / 桌面命令）

`hub_list_tag_taxonomy_repairs` / `list_tag_taxonomy_repairs`：新增可选 `cursor`，返回 `count`、`total`、`nextCursor`、`repairs`，保留版本字段。MCP 每页最大 100；桌面首批 20。

- 首次省略 cursor；下一页原样传回 nextCursor，直到 null。cursor 是不透明字符串，不是数字偏移。
- 建议 cursor 与规范化后的状态、标签和建议 ID 筛选绑定；变更筛选必须从首批开始。修复历史 cursor 不可与建议 cursor 混用。

- 单次响应的总数与数据来自同一读取事务；跨页不是冻结快照。列表浏览期间的新建议、外部审核变更应通过刷新重新获取，total 可能变化。前端按 ID 追加去重，但不会把历史页当成实时快照。
