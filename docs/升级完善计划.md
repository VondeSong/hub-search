# Craft Search 升级完善计划

> 文档状态：已归档，持续维护  
> 基线版本：0.14.0  
> 工作区状态：0.14.0 后续开发，尚未发布  
> 建档日期：2026-07-27  
> 产品定位：面向 Craft 与 Obsidian 的 Windows 本地优先统一搜索工具

## 一、总体目标

Craft Search 后续升级围绕四个方向推进：

1. **可靠**：同步、索引、OCR 和数据库任务可恢复，升级不丢数据。
2. **好搜**：中文、拼音、短语、附件和跨资料库搜索结果稳定、可解释。
3. **好用**：搜索、筛选、预览和设置形成完整、顺畅的桌面工作流。
4. **可维护**：降低核心模块耦合，形成稳定的测试、迁移和发布流程。

## 二、现有能力基线

0.14.0 已具备：

- Craft MCP OAuth 2.0 + PKCE 只读接入。
- 多 Craft 空间、多 Obsidian Vault 统一资料库模型。
- Obsidian 增量扫描、文件监听、双链与别名解析。
- SQLite 元数据与任务状态、Blob 内容寻址仓库。
- Tantivy 本地全文索引及代际切换。
- 中文 N-gram、拼音、首字母、英文错别字和短语召回。
- 标题、章节、路径、正文、PDF、PDF OCR、图片 OCR 分层加权与命中解释。
- 固定搜索质量评测，输出 Top-1、Recall@3、MRR 和 P95 查询耗时。
- Craft/Obsidian Markdown 完整预览。
- PDF 原生文本、PDF OCR、图片 OCR 和按页预览。
- 后台同步、附件、OCR、索引任务的重试与恢复。
- 系统托盘、单实例、全局快捷键和便携版构建。

后续版本默认保持以下原则：

- Craft 和 Obsidian 均以只读方式接入。
- 搜索、索引和正文数据优先保存在本机。
- 不因增加新功能破坏已有数据库与索引的升级兼容性。
- 新的排序或解析规则必须通过固定搜索质量评测。

### 已完成专项：搜索质量与结果体验

搜索质量和基础结果体验已经在 0.14.0 及之前版本完成专项建设，不再作为后续版本从头开发。

现有成果包括：

- 中文 N-gram、拼音全拼、拼音首字母和英文轻微错别字召回。
- 多词 AND、显式 OR、引号短语和字段级命中判断。
- 标题、章节、路径、正文、附件名、PDF 原生文字和 OCR 的差异化权重。
- 按页面或附件实体聚合结果，避免同一内容块重复占据列表。
- 返回实际命中词、命中字段、内容来源和 PDF 页码。
- 结果与完整预览高亮，以及前后命中导航。
- 覆盖排序、筛选、来源、页码和性能阈值的合成数据质量评测。

`参考/clever-search` 是此前的搜索体验参考之一，主要用于研究库内/文内搜索、即时结果、结果计数和键盘导航等交互；Craft Search 当前的 SQLite、Tantivy、多资料源、附件和 OCR 实现仍是自身独立架构。

后续只在出现真实问题、新资料源或评测回退时调整搜索规则。搜索质量作为所有版本的回归门槛维护，不再单独占用一个“重新完善搜索”的版本。

### 2026-07-27 搜索增量完善记录

在 0.14.0 基线之后，参考 clever-search 的可取交互完成了三项高收益增强，但没有替换现有 Tantivy 架构，也没有引入语义搜索：

- **分组命中**：同一页面或附件的候选块在后端聚合为一条主结果，避免重复内容占满列表；曾加入的结果内展开列表因破坏浏览节奏已撤回，页内命中统一使用预览导航。
- **别名与标签索引**：Obsidian Frontmatter `alias` / `aliases`、Frontmatter `tag` / `tags` 及正文 `#标签` 进入独立索引字段和排序权重，不再只服务于双链解析。
- **Vault 排除规则**：每个 Obsidian Vault 可单独配置目录、相对路径前缀以及 `*` / `?` 通配规则；保存后执行完整同步，从本地索引移除已排除内容，不修改原 Vault。
- **多设备路径解耦**：移除开发机器的默认 Obsidian Vault 绝对路径和启动时自动登记逻辑；每台电脑独立添加本机 Vault，已有资料库登记不受影响。
- **界面整理**：修复筛选栏关闭时底部工具栏错误占据剩余高度的问题；顶部增加完整拖动区域，结果和预览使用独立的 Craft/Obsidian 来源色，整体界面改为更清晰的不透明分层。

兼容与验证：

- 数据库 Schema 升级至 15，自动创建并回填 Obsidian 标签表。
- Tantivy 索引 Schema 升级至 5，启动后通过代际机制自动重建。
- Rust 全量测试 70 项全部通过，包含新增标签、排除规则和分组命中测试。
- 前端 TypeScript 检查与生产构建通过；仅保留既有的大分块体积提示。

## 三、版本路线

### 0.15：稳定性与可诊断性

目标：把现有功能从“可用”提升到“长期运行稳定”。

计划：

- 统一同步、附件、OCR、索引任务的状态模型和错误分类。
- 为失败任务提供明确原因、最近错误、重试次数和下一次重试时间。
- 完善应用异常退出后的租约回收和任务恢复。
- 增加数据库、Blob 和活动 Tantivy 索引的一键健康检查。
- 增加“仅修复索引”“仅重试失败任务”“完整重建”的分级恢复入口。
- 完善同步中断、MCP 限流、Vault 暂时不可访问等场景的提示。
- 将日志划分为普通、诊断和敏感信息等级，避免记录 Token 和完整授权地址。
- 为数据库迁移增加升级前检查、失败回滚说明和迁移结果记录。

验收标准：

- 强制终止应用后重新启动，未完成任务能够继续执行。
- 单个资料库异常不会阻塞其他资料库。
- 用户可以从设置页判断问题发生在同步、下载、提取、OCR 还是索引阶段。
- 健康检查不会修改 Craft、Obsidian 原始数据。

### 0.16：预览与交互完善

目标：形成完整的“搜索—判断—打开原文”体验。

计划：

- 拆分搜索页、结果列表、筛选器、预览器和设置页组件。
- 完善键盘操作、焦点顺序、无鼠标操作和中文输入法行为。
- 增加预览目录、标题跳转和当前命中位置反馈。
- 完善 Craft 特有 Markdown、嵌套页面、白板和集合的只读呈现。
- 优化 Obsidian Callout、Frontmatter、双链、嵌入和任务列表渲染。
- 为 PDF 增加页码跳转、缩放和“只看命中页”模式。
- 为图片 OCR 结果增加原图与识别文本对照。
- 增加空状态、首次同步引导、错误状态和大型资料库进度反馈。
- 完善窗口尺寸、分栏宽度、筛选条件和预览状态的持久化。

验收标准：

- 核心搜索流程可以完全通过键盘完成。
- 搜索结果、预览命中和打开原文的目标保持一致。
- 大文档和长 PDF 预览不会明显阻塞搜索输入。
- 深色/浅色主题下主要页面均可正常阅读。

### 0.17：资料源与附件扩展

目标：在不破坏本地优先原则的前提下扩大可搜索内容范围。

计划：

- 抽象统一资料源接口，减少 Craft 与 Obsidian 专用逻辑对核心索引的侵入。
- 建立资料源能力声明：增量同步、删除检测、深层链接、附件、修改时间。
- 评估 TXT、HTML、DOCX、PPTX、XLSX 的只读文本提取。
- 为附件提取器增加文件类型、大小、超时和资源消耗限制。
- 保持附件内容按 Blob 哈希复用，避免跨资料库重复提取。
- 评估本地文件夹作为第三类资料库的可行性。
- 新资料源先以实验开关提供，不直接进入默认稳定路径。

验收标准：

- 新资料源不需要复制现有完整同步和索引管线。
- 关闭某类附件后不会继续生成对应下载或提取任务。
- 不支持的文件格式有明确状态，不进入无限重试。

### 0.18：工程化与发布体系

目标：形成可重复、可验证、可回退的正式发布流程。

计划：

- 将 Rust 后端按领域拆分为数据库、同步、资料源、任务、预览和命令层。
- 将前端主组件拆分为页面组件、业务 Hooks 和 Tauri API 适配层。
- 建立前端单元测试和关键交互测试。
- 将数据库迁移测试覆盖到支持升级的每个历史 Schema。
- 建立干净环境构建、版本一致性检查和发布清单。
- 自动生成便携版校验值、版本说明和数据库兼容范围。
- 验证新版本读取旧数据、升级中断恢复和程序回退边界。
- 明确开发、测试、预发布和正式发布四类构建。

验收标准：

- 同一源码版本可以在干净环境重复构建出可运行程序。
- 前端、Rust、Tauri 配置和发布文件版本号一致。
- 发布前自动完成编译、测试、搜索评测和产物检查。
- 每个正式版本都有变更说明、已知限制和回退说明。

### 0.19：发布候选与稳定性收口

目标：冻结大功能，集中验证升级、恢复和长期运行表现。

计划：

- 在真实规模资料库上执行连续运行、定时同步和文件监听测试。
- 验证旧数据库逐级升级、迁移中断恢复和完整索引重建。
- 固定 1.0 的数据库、索引、设置和深层链接兼容边界。
- 关闭非必要实验开关，整理默认设置和首次启动流程。
- 处理阻断发布的崩溃、数据一致性、搜索回退和资源占用问题。
- 完成用户手册、故障排查、备份恢复和版本回退说明。
- 形成 1.0 发布候选版检查清单并逐项签收。

验收标准：

- 发布候选期不再引入新的大型功能或资料源。
- 连续运行期间没有阻断性同步、索引或数据库错误。
- 旧版本升级和新安装两条路径均完成验证。
- 已知问题均有严重级别、影响范围和处理结论。

### 1.0：正式稳定版

目标：提供可以长期使用和升级的稳定版本。

发布门槛：

- 连续运行与多资料库同步无阻断性故障。
- 数据库迁移、索引重建和任务恢复经过完整验证。
- 搜索质量基准稳定，无已知严重回退。
- Craft、Obsidian、PDF、图片 OCR 核心链路均有自动化覆盖。
- 首次使用、异常恢复、备份和升级路径均有用户文档。
- 安全策略、凭据存储、日志脱敏和外部链接处理通过检查。
- 正式版保留明确的数据兼容和回退边界。

## 四、跨版本持续事项

以下工作不绑定单一版本，每次升级都应检查：

- 数据库 Schema 与迁移兼容性。
- Tantivy 索引格式与重建策略。
- Craft MCP 协议和 OAuth 行为变化。
- Windows OCR、WebView2 和 Tauri 版本兼容性。
- 大型 Vault、长 PDF、高附件量下的内存与磁盘占用。
- 搜索质量评测结果与查询延迟。
- 日志、数据库和备份中的敏感信息。
- 快捷键、托盘、单实例和窗口恢复行为。

## 五、暂缓事项

在 1.0 前暂不作为主线目标：

- 修改或写回 Craft、Obsidian 原始内容。
- 云端托管索引或跨设备同步本地索引。
- 移动端版本。
- 团队协作、共享索引或多人权限体系。
- 生成式 AI 问答、摘要和自动改写。
- 为所有办公文档格式提供完整原样预览。

这些方向只有在本地搜索核心稳定后再单独评估。

## 六、每个版本的完成定义

一个版本只有同时满足以下条件才视为完成：

1. 版本目标对应的功能和修复已经落地。
2. Rust 编译、前端构建和现有测试通过。
3. 搜索相关修改通过固定质量评测。
4. 数据库迁移和旧数据启动路径已验证。
5. README、已知限制和版本号已经同步。
6. 便携版产物可以在无开发服务器环境独立启动。
7. 已记录升级步骤、验证结果和必要的回退方式。

## 七、计划维护规则

- 新需求先归入对应版本，不直接堆入当前开发版本。
- 影响数据兼容性的变更必须单独标注。
- 调整搜索权重时必须同时补充或更新评测用例。
- 延期任务移动到后续版本并记录原因，不保留模糊的“基本完成”状态。
- 每次发布后更新基线版本，并将已完成内容移入版本记录。
