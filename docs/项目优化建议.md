# Hub 项目优化建议

本文基于当前 `0.16.3` 代码和现有功能整理，按影响和实施优先级排序。

## P0：可靠性和数据安全

### 1. 增加真正的导出与灾备

当前本地 Blob 和 SQLite 是搜索缓存，不是稳定、可移植的知识库导出。建议增加：

- Craft 导出为 Markdown + 附件目录
- 滴答清单导出为 Markdown、JSON 或 CSV
- 保留来源 ID、路径、修改时间和原始链接
- 导出清单与 SHA-256 校验文件
- 增量导出和完整导出两种模式

这是最值得优先实现的功能，因为它直接解决云服务不可用或账号迁移时的数据可控性。

### 2. 持久化每个资料库的同步错误

自动同步目前可能只累计失败数量，后台调用中还有忽略错误返回的路径。建议为每个资料库记录：

- 最近成功时间
- 最近尝试时间
- 同步阶段
- 错误类型和完整信息
- 下次重试时间
- 连续失败次数

首页或设置中应能直接看到“哪个库、哪一步失败”，并支持只重试该资料库。

### 3. 凭证健康检查

Craft 和滴答清单启动后先做轻量 Token 检查，并区分：

- Access Token 过期但 Refresh Token 可刷新
- Refresh Token 失效，需要重新登录
- Windows 凭据不存在
- MCP 服务暂时不可用

避免把所有情况都显示成“需要重新授权”。

## P1：架构和可维护性

### 4. 拆分超大文件

当前：

- `desktop/src/App.tsx` 约 2,800 行
- `desktop/src-tauri/src/lib.rs` 超过 15,000 行
- `desktop/src/App.css` 约 900 行

建议拆分为：

- 前端：SearchHeader、FilterBar、ResultList、RecentList、PreviewPane、SettingsDialog、IndexStatus
- 状态：search store、settings store、library store、preview store
- 后端：commands、settings、oauth、sync/craft、sync/dida、sync/obsidian、window、diagnostics
- CSS：tokens、shell、results、preview、settings

先做纯移动和模块边界整理，不同时改行为，降低回归风险。

### 5. 设置命令改为版本化结构体

当前设置项持续增加。建议前后端统一 `AppSettingsV2`：

- 单次读取和保存
- 明确默认值
- 增加 schema version
- 集中迁移旧设置
- 对字号、时间间隔和快捷键做统一校验

这样比不断增加命令参数更稳健。

### 6. 统一窗口状态来源

窗口位置、大小和左右比例应由一个版本化状态对象管理，避免后端元数据和前端 localStorage 形成两个事实来源。保存时增加防抖，并在显示器变化后自动限制到可见工作区。

## P1：性能

### 7. 拆分前端预览包

Markdown、KaTeX 和预览渲染依赖适合按需加载。建议：

- 首屏只加载搜索和列表
- 第一次打开预览时动态导入 ReactMarkdown、KaTeX 和相关插件
- Vite 配置手动分块

这会缩短启动时间并减小首屏 JavaScript 解析成本。

### 8. 滴答清单同步使用受限并发

当前逐个项目读取未完成任务。项目很多时延迟与项目数线性增长。若官方 MCP 的限流允许，可使用 2～4 个受限并发请求，并保留退避与失败重试。

如果以后 MCP 提供“自某时间后变更”或游标 API，应改为真正增量同步。

### 9. 预览和媒体继续虚拟化

长文档可进一步优化：

- 图片进入视口前只保留尺寸占位
- 视频进入视口也不自动下载，点击后才请求媒体
- 大型 Markdown 按块渐进渲染
- 切换结果时取消上一条预览和媒体请求
- 预取仅限当前结果前后各一条

### 10. 首页和结果列表虚拟化

结果固定上限不高时当前实现足够；若后续支持数百条结果或更长首页，可引入轻量虚拟列表。由于结果高度自适应，应使用支持动态测量的方案。

## P1：安全

### 11. 设置 Tauri CSP

当前 `tauri.conf.json` 的 CSP 为 `null`。建议根据实际资源来源建立白名单，至少限制：

- `default-src`
- `script-src`
- `style-src`
- `img-src`
- `media-src`
- `connect-src`

Craft 附件、OAuth 和本地自定义协议需要逐项加入，而不是保持完全开放。

### 12. 收紧外部链接和本地协议校验

继续保证：

- 只允许 HTTPS 远程资源
- Obsidian 路径必须位于已登记 Vault 内
- 本地文件和 Blob 请求必须验证资料库及资源归属
- Craft、滴答清单链接只允许官方域名或已知协议

## P2：测试和发布

### 13. 增加前端自动化测试

后端已有较多 Rust 测试，但前端缺少成体系的交互回归。建议至少覆盖：

- 键盘上下选择三种提供方
- Esc 清空/隐藏的两阶段行为
- 资料库多选
- 筛选下拉
- 标题单行与正文两行自适应
- 左右拖动和窗口状态恢复
- 设置弹窗滚动和固定关闭按钮

组件逻辑可用 Vitest，完整窗口交互可用 Playwright 或 WebDriver。

### 14. 建立发布检查清单

每次免安装版发布前自动执行：

1. TypeScript 构建
2. Rust 格式与检查
3. Rust 全量测试
4. 搜索质量评估
5. 便携版启动检查
6. 三种资料库的最小同步冒烟测试
7. 版本号和底栏内部版本一致性检查
8. 生成 SHA-256

### 15. 建立迁移测试

保存若干旧版本 SQLite 测试夹具，验证新版本启动后：

- 数据库迁移成功
- 索引可重建
- 设置默认值正确
- 凭证引用不丢失
- 自定义数据目录仍可定位

## P2：产品体验

### 16. 同步说明放进界面

在自动同步设置旁显示每类来源的实际行为：

- Craft：定时增量
- 滴答清单：定时拉取未完成任务
- Obsidian：文件监听 + 定时校准

并显示各库“上次成功”和“下次计划”时间。

### 17. 滴答清单范围提示

设置页明确写出“当前读取未完成任务”。如果用户需要完成历史，应提供独立的“保留已完成任务缓存”策略，而不是让已完成任务悄然消失。

### 18. 更细的失败处理

把失败分成：

- 可重试：网络、限流、文件占用
- 需要用户操作：授权失效、Vault 路径丢失
- 永久忽略：404、格式不支持、资源已删除

不同类型给出不同按钮，减少用户不知道该点“重试”还是“忽略”的情况。

## 建议实施顺序

1. 同步错误持久化和凭证健康检查
2. Craft/滴答清单导出与灾备
3. 前端交互测试和发布检查
4. 拆分 App.tsx 与 lib.rs
5. 预览按需加载和前端分包
6. 滴答清单同步并发与增量能力
7. CSP 和协议权限收紧
